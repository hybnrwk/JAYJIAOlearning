## 0. 这一部分真正要学会什么

现实数据最常见的形态是一张表，但“会看表”不等于“会处理表”。表格操作真正要求你持续回答四个问题：

1. **一行代表什么？** 是一个人、一部电影、一个姓名在某一年的统计，还是一次交易？
2. **哪些列唯一标识一行？** 一个姓名可能不够，`Name + Year + Sex` 才可能确定一条婴儿姓名记录。
3. **当前表的粒度是什么？** 原始表可能一行一个姓名和年份，聚合后则一行一个年份。
4. **一次操作改变了什么？** 是减少行、减少列、增加列、改变粒度，还是把两张表连接起来？

Ch06 和 Ch07 使用两套工具处理同一类问题：

- **pandas** 在 Python 内存中用 `DataFrame` 处理表，适合探索、清洗、可视化和建模前的数据准备。
- **SQL** 在数据库中用查询处理关系表，适合筛选大规模数据、组合多张表以及形成可复用的数据查询。

两章表面上是在学习两种语法，底层其实只有五类操作：

| 目的 | pandas | SQL | 对表的影响 |
| --- | --- | --- | --- |
| 选择列 | `df[[...]]`、`.loc` | `SELECT` | 列变少 |
| 筛选行 | 布尔索引、`.query()` | `WHERE` | 行变少 |
| 变换值 | 向量化、`.assign()` | 标量函数、`CASE` | 增加或修改列 |
| 分组聚合 | `.groupby().agg()` | `GROUP BY` | 多行压缩为少量组 |
| 连接表 | `.merge()` | `JOIN ... ON ...` | 按键组合两张表 |

本部分最重要的能力不是背 API，而是看到一个问题后，能先用自然语言说出操作计划：

> 从哪张表开始，先保留哪些行，再构造哪些列，按什么键分组，用什么统计量聚合，最后与哪张表按什么键连接。

## 1. 表格数据的统一心智模型

### 1.1 行、列、值和模式

一张表可以从四个层面理解：

- **行（record / observation）**：一个观测单位。
- **列（feature / variable / attribute）**：这个单位的一个属性。
- **值（value）**：某一行在某一列上的记录。
- **模式（schema）**：列名、数据类型、约束以及表之间的关系。

假设婴儿姓名表包含：

| Name | Sex | Year | Count |
| --- | --- | ---: | ---: |
| Luna | F | 2019 | 7781 |
| Luna | F | 2020 | 7774 |
| Liam | M | 2020 | 19659 |

这里一行不是“一个婴儿”，也不是“一个姓名”，而是：

> 某个性别下，某个姓名在某一年登记的人数统计。

`Count` 是这一组婴儿的数量。因此，若要求 2020 年登记婴儿总数，应该对 `Count` 求和，而不是数表中有多少行。把“一行的含义”判断错，后续代码即使运行成功，答案也会错。

### 1.2 行粒度决定可以回答什么

**粒度（granularity）**是每一行代表的最小分析单位。

- 原始婴儿姓名表：一行是 `Name + Sex + Year` 的组合。
- 按 `Year` 聚合后：一行是一个年份。
- 按 `Year + Sex` 聚合后：一行是一个年份与性别的组合。
- 姓名分类表：一行可能是一个姓名及其类别。

聚合会丢失细节。例如按年份求总人数后，已经不能再回答某个具体姓名当年有多少人，因为姓名维度被压缩掉了。连接则可能增加细节，也可能重复原行。因此每次操作后都应重新说出“一行现在代表什么”。

### 1.3 键与唯一性

**键（key）**是用于标识记录或匹配记录的一列或多列。

- **主键（primary key）**：在一张表中唯一标识一行。
- **复合键（composite key）**：需要多列共同唯一标识一行。
- **外键（foreign key）**：一张表中用于指向另一张表主键的列。

姓名分类表中 `nyt_name` 可能每个姓名只出现一次，因此它可以作为键。婴儿姓名表中的 `Name` 不是唯一键，因为同一姓名会跨年份、性别重复。连接前必须检查键的唯一性，否则很容易产生多对多匹配和行数膨胀。

### 1.4 长表与宽表

同一信息可以有不同形状。

长表：

| Year | Sex | Count |
| ---: | --- | ---: |
| 2020 | F | 1570000 |
| 2020 | M | 1680000 |

宽表：

| Year | F | M |
| ---: | ---: | ---: |
| 2020 | 1570000 | 1680000 |

长表适合筛选、分组和多数可视化系统；宽表适合横向比较和矩阵式展示。`pivot_table` 会把长表重排为宽表，但它不是创造新信息，只是在改变布局。

### 1.5 缺失值不是普通值

缺失值表示“未知、未记录、不适用或连接不到”，它不等于 0，也不等于空字符串。

- pandas 常见缺失标记是 `NaN` 或 `pd.NA`。
- SQL 使用 `NULL`。

必须先理解缺失的现实含义，再决定删除、填补还是保留。尤其要记住：多数计数和平均函数会忽略缺失值，因此“总行数”和“某列非缺失值数量”经常不同。

## 2. Ch06：pandas 的核心数据结构

### 2.1 `DataFrame`、`Series` 与 `Index`

`pandas` 中最重要的三个对象是：

- `DataFrame`：二维表格。
- `Series`：带索引的一维数据，通常可看作表的一列。
- `Index`：行标签集合，用于对齐和定位数据。

```python
import pandas as pd

baby = pd.DataFrame({
    "Name": ["Luna", "Luna", "Liam"],
    "Sex": ["F", "F", "M"],
    "Year": [2019, 2020, 2020],
    "Count": [7781, 7774, 19659],
})
```

`baby["Name"]` 返回 `Series`，而 `baby[["Name"]]` 返回只有一列的 `DataFrame`：

```python
type(baby["Name"])       # pandas.Series
type(baby[["Name"]])     # pandas.DataFrame
```

这不是外观差异，而是对象维度不同。许多方法只接受二维表，因此需要明确自己得到的是 `Series` 还是 `DataFrame`。

`Index` 是行标签，不是普通数据列。默认索引通常为 `0, 1, 2, ...`，但索引也可以是字符串、年份，甚至可以重复：

```python
baby.index
baby.columns
baby.shape       # (行数, 列数)
baby.dtypes
```

不要把索引当然地理解成“行号”。排序或筛选后，行的位置会变，但原索引标签通常保留。

### 2.2 读取数据后先检查结构

```python
baby = pd.read_csv("babynames.csv")

baby.head()
baby.tail()
baby.shape
baby.columns
baby.dtypes
baby.isna().sum()
baby.describe(include="all")
```

这些检查分别回答：

- 前后几行看起来是否合理；
- 表有多少行和列；
- 列名是否与预期一致；
- 数值是否被错误读成字符串；
- 每列有多少缺失值；
- 数值范围和类别频数是否异常。

`shape` 与 `size` 不同：`shape` 返回 `(行数, 列数)`，`size` 返回全部单元格数量，即行数乘列数。

### 2.3 数据类型与统计变量类型不是一回事

`int64`、`float64`、`object`、`string`、`boolean` 是计算机存储类型；名义变量、有序变量、定量变量是统计含义。

例如邮政编码可能以整数存储，但对邮政编码求平均通常没有意义。年份可以是整数，但有时只作为类别分组。分析中既要检查 `dtype`，也要判断变量在问题中的含义。

## 3. Ch06：选择与筛选

### 3.1 用 `[]` 选择列

```python
baby["Name"]                    # 一个 Series
baby[["Name", "Count"]]        # 一个 DataFrame
```

方括号最常用于选择列。单个列名返回一维 `Series`，列名列表返回二维 `DataFrame`。

### 3.2 `.loc` 按标签，`.iloc` 按位置

```python
baby.loc[0:2, ["Name", "Count"]]
baby.iloc[0:2, [0, 3]]
```

二者语法都是 `[行, 列]`，但含义不同：

- `.loc` 使用行标签和列标签，切片右端点**包含在内**。
- `.iloc` 使用整数位置，遵守 Python 半开区间，切片右端点**不包含**。

上例中 `.loc[0:2]` 会返回标签 0、1、2 三行；`.iloc[0:2]` 只返回位置 0、1 两行。

排序后尤其要分清标签与位置：

```python
sorted_baby = baby.sort_values("Count", ascending=False)
sorted_baby.loc[0]    # 原索引标签为 0 的行
sorted_baby.iloc[0]   # 当前排在第一位置的行
```

只要任务是按列名或索引含义取数据，优先使用 `.loc`；只有明确需要“第几行、第几列”时才使用 `.iloc`。

### 3.3 布尔筛选

比较一列会得到与原表等长的布尔 `Series`：

```python
is_2020 = baby["Year"] == 2020
baby.loc[is_2020]
```

多个条件要使用逐元素逻辑运算符：

```python
baby.loc[
    (baby["Year"] == 2020)
    & (baby["Count"] > 10000)
]
```

常用运算符是：

| 含义     | pandas 写法      |     |
| ------ | -------------- | --- |
| 与      | `&`            |     |
| 或      | `              | `   |
| 非      | `~`            |     |
| 是否属于集合 | `.isin([...])` |     |

每个比较条件都要加括号。不能用 Python 的 `and`、`or` 连接两个 `Series`，因为它们试图把整列压成一个真假值。

```python
baby.loc[
    baby["Year"].isin([2019, 2020])
    & baby["Name"].str.startswith("L")
]
```

### 3.4 字符串访问器 `.str`

字符串列上的常见向量化操作包括：

```python
baby["Name"].str.len()
baby["Name"].str.startswith("L")
baby["Name"].str.contains("an", case=False, na=False)
baby["Name"].str[0]
```

`.str` 会把字符串操作逐元素作用到整列，通常比 `.apply(lambda x: ...)` 更清楚、更快。`na=False` 表示缺失值不算匹配，能避免布尔筛选遇到未知值。

### 3.5 排序、去重与抽样

```python
baby.sort_values("Count", ascending=False).head(10)
baby.sort_values(["Year", "Count"], ascending=[True, False])
baby["Name"].value_counts()
baby["Name"].unique()
baby["Name"].nunique()
baby.drop_duplicates(subset=["Name", "Sex", "Year"])
baby.sample(n=5, random_state=42)
```

这里要区分：

- `value_counts()` 统计每个取值出现多少次。
- `unique()` 返回出现过的不同值。
- `nunique()` 返回不同值数量。
- `drop_duplicates()` 删除指定键完全重复的行。
- `sort_values()` 只改变行顺序，不改变索引标签。

需要可复现的随机抽样时设置 `random_state`。

### 3.6 方法链是一份可读的操作计划

“找出 2020 年最常见的 10 个姓名记录”可以写成：

```python
top_2020 = (
    baby.loc[baby["Year"] == 2020, ["Name", "Sex", "Count"]]
        .sort_values("Count", ascending=False)
        .head(10)
)
```

从上到下正好对应：先筛选年份，再保留相关列，再按人数降序，最后取前十。方法链不是为了炫技，而是让代码顺序接近问题的自然语言步骤。

## 4. Ch06：变换列与控制副作用

### 4.1 向量化运算优先

对整列直接运算称为向量化：

```python
baby["CountThousands"] = baby["Count"] / 1000
baby["FirstLetter"] = baby["Name"].str[0]
```

向量化代码通常比 Python 循环和逐元素 `.apply()` 更快，也更容易读懂。优先顺序通常是：

1. pandas 或 NumPy 的向量化方法；
2. `.str`、`.dt` 等专用访问器；
3. 实在没有现成操作时再用 `.apply()`。

### 4.2 `.apply()` 在做什么

```python
def first_letter(name):
    return name[0]

baby["Name"].apply(first_letter)
```

概念上，它依次取出 `Name` 中的每个值，调用函数，再把返回值组装成新的 `Series`。它灵活，但容易把本可向量化的任务写得更慢：

```python
# 更推荐
baby["Name"].str[0]
```

`.apply()` 适合复杂的自定义规则，不应该成为所有列变换的默认写法。

### 4.3 修改原表与返回新表

直接赋值会修改对象：

```python
baby["FirstLetter"] = baby["Name"].str[0]
```

`.assign()` 返回增加列后的新 `DataFrame`，适合方法链：

```python
baby_with_letter = baby.assign(
    FirstLetter=baby["Name"].str[0]
)
```

多数 pandas 方法默认返回新对象：

```python
baby.drop(columns="FirstLetter")   # 原 baby 通常不变
```

若要保留结果，需要赋值：

```python
baby = baby.drop(columns="FirstLetter")
```

分析代码中应尽量明确哪个对象被修改。随意使用 `inplace=True` 容易让数据在 notebook 前后状态不一致，也不利于方法链和复现。

### 4.4 重命名、删除与类型转换

```python
baby = baby.rename(columns={"Count": "BirthCount"})
baby = baby.drop(columns=["BirthCount"])
baby["Year"] = baby["Year"].astype("int64")
```

类型转换失败时，不要立即强行删除出错行。先找出不能转换的值，因为它们可能暴露数据单位、编码或缺失规则的问题。

### 4.5 条件构造新列

简单条件可用布尔表达式或 NumPy：

```python
import numpy as np

baby["Popularity"] = np.where(
    baby["Count"] >= 10000,
    "high",
    "ordinary",
)
```

多个区间可用 `pd.cut()`，映射固定类别可用 `.map()`：

```python
baby["SexLabel"] = baby["Sex"].map({"F": "female", "M": "male"})
```

如果映射字典没有覆盖某个值，结果会成为缺失值。变换后应检查新列的 `value_counts(dropna=False)`。

## 5. Ch06：分组、聚合与透视

### 5.1 聚合的本质是改变粒度

假设要计算每年登记的总婴儿数：

```python
year_counts = (
    baby.groupby("Year", as_index=False)["Count"]
        .sum()
)
```

操作可以拆成三步：

1. **Split**：按 `Year` 把行分组。
2. **Apply**：对每组的 `Count` 求和。
3. **Combine**：把每组结果组合成新表。

原表一行代表“姓名、性别、年份”，结果一行只代表“年份”。聚合不是给原表增加一列，而是生成粒度更粗的新表。

### 5.2 分组键必须出现在结果解释中

```python
year_sex_counts = (
    baby.groupby(["Year", "Sex"], as_index=False)
        .agg(TotalCount=("Count", "sum"))
)
```

现在一行是一个 `Year + Sex` 组合。`as_index=False` 让分组键保留为普通列；也可先分组再 `.reset_index()`。

命名聚合同时说明输入列、聚合函数和结果列名：

```python
summary = (
    baby.groupby("Year", as_index=False)
        .agg(
            TotalCount=("Count", "sum"),
            MaxNameCount=("Count", "max"),
            DistinctNames=("Name", "nunique"),
        )
)
```

这三个结果含义完全不同：总登记人数、最常见单条姓名记录的人数、不同姓名的数量。

### 5.3 `size`、`count` 和 `sum` 不可混用

| 操作 | 计算什么 | 是否忽略缺失 |
| --- | --- | --- |
| `.size()` | 每组行数 | 不看列值，因此不忽略行 |
| `.count()` | 每列非缺失值个数 | 是 |
| `.sum()` | 数值之和 | 通常忽略缺失 |

婴儿姓名表中：

- 行数是姓名记录数量；
- `Count` 之和才是登记婴儿数量。

```python
baby.groupby("Year").size()
baby.groupby("Year")["Name"].count()
baby.groupby("Year")["Count"].sum()
```

三行代码都能运行，但回答三个不同问题。

### 5.4 自定义聚合与组筛选

```python
def value_range(s):
    return s.max() - s.min()

baby.groupby("Year")["Count"].agg(value_range)
```

自定义聚合函数每次接收某一组的一列 `Series`，必须返回一个标量，才能把一组压成一行。

如果目标是“保留满足条件的整个组”，使用 `GroupBy.filter`：

```python
frequent_names = baby.groupby("Name").filter(
    lambda group: group["Year"].nunique() >= 100
)
```

这与普通布尔筛选不同。布尔筛选逐行判断，`groupby().filter()` 先观察整个组，再决定这个组的所有行是否保留。

### 5.5 聚合与变换的区别

- `agg` 把每组压缩成一个或少数几个结果，输出行数通常减少。
- `transform` 为每个原始行返回一个同长度结果，输出行数不变。

例如计算每条记录占当年总人数的比例：

```python
year_total = baby.groupby("Year")["Count"].transform("sum")
baby["YearShare"] = baby["Count"] / year_total
```

`year_total` 与原表等长，每一行都带着所属年份的总人数，因此可以直接相除。若这里用 `agg`，得到的短表无法直接逐行对齐。

### 5.6 `pivot_table` 是分组聚合后的重排

```python
year_sex_wide = baby.pivot_table(
    index="Year",
    columns="Sex",
    values="Count",
    aggfunc="sum",
)
```

它等价于先按 `Year + Sex` 分组求和，再把 `Sex` 的类别展开为列。四个参数要逐个解释：

- `index`：结果的行标签。
- `columns`：展开成新列的类别。
- `values`：要聚合的数值。
- `aggfunc`：同一格有多条记录时如何合并。

如果忘记 `aggfunc`，就没有说明重复组合如何处理。`pivot_table` 默认常用均值，这可能与“总数”问题不符，所以应明确写出聚合函数。

## 6. Ch06：连接多张表

### 6.1 为什么需要连接

数据库和实际项目常把不同实体分开存储：

- `baby` 保存姓名、年份和人数；
- `nyt` 保存姓名及其文化类别。

要研究各类姓名随时间的流行度，需要先按姓名连接，再按类别和年份聚合。

```python
merged = baby.merge(
    nyt,
    left_on="Name",
    right_on="nyt_name",
    how="inner",
)
```

### 6.2 四种常见连接

设左表为 `L`，右表为 `R`：

| `how` | 保留哪些键 |
| --- | --- |
| `inner` | 两边都能匹配的键 |
| `left` | 左表全部键，右表匹配不到处填缺失 |
| `right` | 右表全部键，左表匹配不到处填缺失 |
| `outer` | 两边所有键，任何一边匹配不到都填缺失 |

如果目标是“给左表每一行补充属性”，通常使用左连接；如果只分析有分类信息的姓名，使用内连接。

### 6.3 连接基数决定行数

连接前应判断键关系：

- 一对一：两边键都唯一。
- 多对一：左表键重复，右表键唯一。
- 一对多：左表键唯一，右表键重复。
- 多对多：两边键都重复。

若左表某键有 3 行，右表同一键有 2 行，连接后会得到 `3 × 2 = 6` 行。多对多连接可能是正确需求，也可能是严重错误。

pandas 可以显式验证预期：

```python
merged = baby.merge(
    nyt,
    left_on="Name",
    right_on="nyt_name",
    how="inner",
    validate="many_to_one",
)
```

若右表的 `nyt_name` 不唯一，这段代码会直接报错，而不是悄悄重复数据。

### 6.4 连接前后的检查

```python
baby["Name"].duplicated().any()
nyt["nyt_name"].duplicated().any()

merged.shape
merged["category"].isna().mean()
```

推荐检查：

1. 连接键的数据类型是否一致。
2. 键是否有前后空格、大小写差异或不同编码。
3. 哪一边的键应该唯一。
4. 连接后行数是否符合预期。
5. 左连接后新增列的缺失率是多少。

两个表都有同名非键列时，pandas 会添加后缀，可显式指定：

```python
left.merge(right, on="id", suffixes=("_left", "_right"))
```

### 6.5 先连接再聚合

```python
category_counts = (
    baby.merge(
        nyt,
        left_on="Name",
        right_on="nyt_name",
        how="inner",
        validate="many_to_one",
    )
    .groupby(["category", "Year"], as_index=False)
    .agg(Count=("Count", "sum"))
)
```

操作逻辑是：

1. 用姓名把类别补到婴儿姓名记录上；
2. 按类别和年份形成组；
3. 把组内不同姓名和性别记录的 `Count` 相加。

最终一行表示“某类姓名在某年的总登记人数”。只有把每一步的粒度说清楚，才能确认结果真的对应研究问题。

### 6.6 DataFrame、电子表格、矩阵和关系表

| 表示方式 | 优势 | 局限 | 典型用途 |
| --- | --- | --- | --- |
| 电子表格 | 直接查看、手工编辑、公式联动 | 操作历史难追踪，大数据和复杂复现较弱 | 小型人工维护表 |
| DataFrame | 代码可复现，混合类型，适合探索和建模 | 通常受单机内存限制 | 清洗、EDA、特征工程 |
| 矩阵 | 规则数值结构，适合线性代数 | 通常要求同一数值类型，标签语义较弱 | 模型计算、数值算法 |
| 关系表 | 数据库管理、约束、并发、磁盘查询 | 交互可视化和统计建模不如 Python 直接 | 业务数据、大规模筛选与连接 |

常见工作流是：数据库关系表经过 SQL 筛选后进入 pandas，再由 pandas 构造数值矩阵供模型使用。

## 7. Ch07：关系表与 SQL

### 7.1 SQL 的对象是关系，不是带索引的 DataFrame

关系表也有行和列，但有两个关键区别：

1. 关系表的行没有 pandas 那样的索引标签。
2. 除非显式使用 `ORDER BY`，SQL 查询结果没有可靠顺序。

因此不能把 `LIMIT 10` 理解为“固定的前十行”。如果题目要求最早、最大或评分最高的十条记录，必须先 `ORDER BY` 再 `LIMIT`。

SQL 是声明式语言。你描述“想得到什么结果”，数据库查询优化器决定具体怎样读取、过滤和连接数据。语句书写顺序不等于逻辑执行顺序。

### 7.2 数据库、模式、主键和外键

数据库可以包含多张关系表，模式规定每张表的列、类型和约束。规范化设计通常把不同实体放在不同表中，再用键连接。

例如 IMDb 数据库可拆成：

- `Title`：电影基本信息，`title_id` 为主键；
- `Rating`：电影评分，`title_id` 指向 `Title`；
- `Person`：人物信息，`person_id` 为主键；
- `Role`：人物与电影之间的出演关系，包含两个外键。

这样避免在每一条出演记录中重复保存完整电影和人物信息，也使更新更一致。

### 7.3 在 Jupyter 中运行 SQL

常见方式之一是用 SQLAlchemy 建立连接，再由 pandas 读取查询结果：

```python
import pandas as pd
import sqlalchemy

db = sqlalchemy.create_engine("sqlite:///babynames.db")

query = """
SELECT Name, Sex, Year, Count
FROM baby
LIMIT 5;
"""

result = pd.read_sql(query, db)
```

这体现了常见分工：SQL 在数据库侧减少数据量，`pd.read_sql` 把结果载入 DataFrame，之后再用 Python 可视化或建模。

课程 notebook 也会使用 `%%sql` 单元魔法。它适合交互式写查询；`pd.read_sql` 更方便把结果明确保存成 DataFrame。不同数据库系统在函数和语法细节上有差异，但核心查询结构相同。

### 7.4 `SELECT`、`FROM` 与列别名

```sql
SELECT Name, Count
FROM baby;
```

- `FROM` 指定数据来源。
- `SELECT` 指定输出列或表达式。
- `*` 表示所有列，但正式分析中明确列名通常更安全。

列别名使用 `AS`：

```sql
SELECT Name, Count AS birth_count
FROM baby;
```

`DISTINCT` 删除输出中的重复组合：

```sql
SELECT DISTINCT Year, Sex
FROM baby;
```

它作用于整个 `SELECT` 列表，而不是只作用于紧随其后的第一列。

### 7.5 `WHERE` 筛选行

```sql
SELECT Name, Sex, Count
FROM baby
WHERE Year = 2020
  AND Count > 10000;
```

SQL 中相等比较用单个 `=`，不等可写 `<>` 或部分系统支持的 `!=`。常见条件包括：

```sql
WHERE Year BETWEEN 2010 AND 2020
WHERE Sex IN ('F', 'M')
WHERE Name LIKE 'L%'
WHERE Count >= 10000
```

`AND` 优先于 `OR`，复杂条件应使用括号明确意图：

```sql
WHERE Count > 10000
  AND (Year = 2019 OR Year = 2020)
```

### 7.6 `NULL` 的三值逻辑

不能用 `= NULL` 判断缺失：

```sql
WHERE category IS NULL
WHERE category IS NOT NULL
```

原因是 SQL 比较可能得到 `TRUE`、`FALSE` 或 `UNKNOWN`。任何普通值与 `NULL` 的比较通常是未知，而 `WHERE` 只保留条件为真的行。

聚合时也要注意：

```sql
COUNT(*)          -- 所有行
COUNT(category)   -- category 非 NULL 的行
AVG(score)        -- 通常忽略 score 为 NULL 的行
```

因此报告平均数时，应同时知道有效样本数。

### 7.7 排序、限制与分页

```sql
SELECT Name, Count
FROM baby
WHERE Year = 2020
ORDER BY Count DESC, Name ASC
LIMIT 10 OFFSET 0;
```

- `ASC` 升序，通常是默认值。
- `DESC` 降序。
- 多列排序从左到右决定优先级。
- `LIMIT` 限制返回行数。
- `OFFSET` 跳过若干行，可用于简单分页。

没有 `ORDER BY` 的 `LIMIT` 只是在当前执行中取一部分行，不保证每次或换数据库后仍是同一批。

### 7.8 SQL 标量函数与表达式

标量函数对每一行的单个值进行变换：

```sql
SELECT
  Name,
  LENGTH(Name) AS name_length,
  SUBSTR(Name, 1, 1) AS first_letter,
  ROUND(Count / 1000.0, 2) AS count_thousands
FROM baby;
```

它们与聚合函数不同：

- `LENGTH(Name)` 对每行产生一个结果，粒度不变。
- `AVG(Count)` 把多行压成一个组结果，粒度改变。

不要在没有正确 `GROUP BY` 的情况下混合裸列和聚合表达式：

```sql
-- 含义不明确，不要这样写
SELECT Name, AVG(Count)
FROM baby;
```

严格的 SQL 系统会拒绝这种查询；SQLite 有时返回某个任意姓名，容易制造误解。

### 7.9 `LIKE`、`CAST` 与 `CASE`

字符串模式匹配：

```sql
WHERE title LIKE 'Star Wars%'
```

- `%` 匹配任意长度字符串。
- `_` 匹配任意单个字符。

类型转换：

```sql
SELECT CAST(release_year AS INTEGER) AS release_year_int
FROM Title;
```

条件构造列：

```sql
SELECT
  title,
  CASE
    WHEN release_year < 1980 THEN 'old'
    WHEN release_year < 2010 THEN 'middle'
    ELSE 'new'
  END AS movie_age
FROM Title;
```

`CASE` 从上到下判断，命中第一个条件后停止。因此区间条件的顺序会影响结果。若省略 `ELSE`，没有命中任何条件的行会得到 `NULL`。

### 7.10 `GROUP BY` 与聚合

```sql
SELECT
  Year,
  SUM(Count) AS total_count
FROM baby
GROUP BY Year;
```

结果中每行是一个年份。通用规则是：

> `SELECT` 中不属于聚合函数的列，原则上都必须出现在 `GROUP BY` 中。

多列分组：

```sql
SELECT
  Year,
  Sex,
  SUM(Count) AS total_count
FROM baby
GROUP BY Year, Sex;
```

常用聚合函数有 `COUNT`、`SUM`、`AVG`、`MIN` 和 `MAX`。一定要先判断要统计的是“行数”“非缺失值数”还是“某个数值列之和”。

### 7.11 `WHERE` 与 `HAVING`

`WHERE` 在分组前过滤行，`HAVING` 在分组后过滤组：

```sql
SELECT
  Year,
  SUM(Count) AS total_count
FROM baby
WHERE Count >= 5
GROUP BY Year
HAVING SUM(Count) > 3000000;
```

解释顺序是：

1. 删除 `Count < 5` 的原始记录；
2. 按年份分组；
3. 对每组求和；
4. 只保留总数超过 300 万的年份。

如果把 `HAVING` 条件错误放进 `WHERE`，就会试图在分组尚未形成时使用组统计量。

### 7.12 SQL 查询的书写顺序与逻辑顺序

常见书写顺序：

```sql
SELECT ...
FROM ...
JOIN ... ON ...
WHERE ...
GROUP BY ...
HAVING ...
ORDER BY ...
LIMIT ...;
```

便于理解的逻辑执行顺序：

1. `FROM` 和 `JOIN`：确定数据来源并连接。
2. `WHERE`：过滤原始行。
3. `GROUP BY`：形成组。
4. `HAVING`：过滤组。
5. `SELECT`：计算输出表达式。
6. `DISTINCT`：去除重复输出。
7. `ORDER BY`：排序。
8. `LIMIT`：截取最终行。

这解释了为什么聚合写在 `SELECT` 中，却是在分组形成后才有意义；也解释了为什么某些数据库不能在 `WHERE` 中直接引用刚在 `SELECT` 定义的别名。

### 7.13 SQL 连接

```sql
SELECT
  b.Name,
  b.Year,
  b.Count,
  n.category
FROM baby AS b
INNER JOIN nyt AS n
  ON b.Name = n.nyt_name;
```

表别名 `b` 和 `n` 能消除同名列歧义，也让长表名更易读。

常见连接：

- `INNER JOIN`：只保留匹配行。
- `LEFT JOIN`：保留左表所有行。
- `RIGHT JOIN`：保留右表所有行，部分 SQLite 版本不支持，可交换表后使用左连接。
- `FULL OUTER JOIN`：保留两边所有行，不同数据库支持情况不同。
- `CROSS JOIN`：返回所有行组合，若左表 `m` 行、右表 `n` 行，结果有 `m × n` 行。

SQL 的 `ON` 可以使用比相等更复杂的条件，但连接基数问题与 pandas 完全相同。若两边键都重复，结果仍会成倍扩张。

### 7.14 公用表表达式 `WITH`

复杂查询应拆成有名字的中间步骤：

```sql
WITH letters AS (
  SELECT
    Name,
    Year,
    Count,
    SUBSTR(Name, 1, 1) AS first_letter
  FROM baby
),
yearly_letter_counts AS (
  SELECT
    first_letter,
    Year,
    SUM(Count) AS total_count
  FROM letters
  GROUP BY first_letter, Year
)
SELECT Year, total_count
FROM yearly_letter_counts
WHERE first_letter = 'L'
ORDER BY Year;
```

`WITH` 定义的是当前查询期间可用的临时关系，也称 CTE。它的价值是把复杂逻辑分解为可独立检查的阶段，而不是让查询变得更“高级”。每个 CTE 都应有清楚的行粒度和职责。

### 7.15 子查询与 CTE 的关系

子查询把查询直接嵌套在另一条语句里；CTE 给中间查询命名。两者经常可以互相改写。短小的一次性条件可用子查询，包含多个步骤或需要重复引用时，CTE 通常更易读和调试。

## 8. pandas 与 SQL 如何对应

### 8.1 同一个问题的两种写法

问题：找出 2020 年人数超过 10000 的姓名记录，按人数降序取前十。

pandas：

```python
top_names = (
    baby.loc[
        (baby["Year"] == 2020) & (baby["Count"] > 10000),
        ["Name", "Sex", "Count"],
    ]
    .sort_values("Count", ascending=False)
    .head(10)
)
```

SQL：

```sql
SELECT Name, Sex, Count
FROM baby
WHERE Year = 2020
  AND Count > 10000
ORDER BY Count DESC
LIMIT 10;
```

两段代码都遵循：筛选行、选择列、排序、截取。pandas 的执行顺序接近代码书写顺序；SQL 则按声明式查询的逻辑顺序处理。

### 8.2 常见操作对照表

| 任务 | pandas | SQL |
| --- | --- | --- |
| 选择列 | `df[["a", "b"]]` | `SELECT a, b` |
| 筛选行 | `df.loc[df["a"] > 0]` | `WHERE a > 0` |
| 去重 | `drop_duplicates()` | `SELECT DISTINCT` |
| 排序 | `sort_values()` | `ORDER BY` |
| 前 n 行 | `head(n)` | `LIMIT n` |
| 新列 | `.assign()`、向量化 | `SELECT expression AS name` |
| 分组 | `.groupby()` | `GROUP BY` |
| 过滤组 | `.groupby().filter()` | `HAVING` |
| 内连接 | `merge(..., how="inner")` | `INNER JOIN` |
| 左连接 | `merge(..., how="left")` | `LEFT JOIN` |
| 缺失判断 | `.isna()` | `IS NULL` |
| 条件列 | `np.where`、`.map` | `CASE` |
| 中间步骤 | 变量、方法链 | CTE `WITH` |

### 8.3 什么时候用 pandas，什么时候用 SQL

优先在 SQL 中做：

- 从大型数据库只取需要的行和列；
- 在数据库侧完成连接和基础聚合；
- 需要依赖数据库约束、权限和统一数据源；
- 查询需要被其他系统复用。

优先在 pandas 中做：

- 数据量能放入内存；
- 需要快速探索、绘图和检查中间结果；
- 需要复杂的 Python 函数、统计模型或机器学习工具；
- 数据来自 CSV、API 等非数据库来源。

真实项目常把二者结合：

```text
数据库原表
  -> SQL 筛选、连接、聚合
  -> pd.read_sql 得到适量 DataFrame
  -> pandas 清洗、检查、可视化
  -> NumPy / sklearn / statsmodels 建模
```

原则是尽量让数据量大的简单操作靠近数据库执行，把需要灵活分析的适量结果带入 Python。

## 9. 综合案例：姓名类别流行度

### 9.1 先定义问题与数据粒度

问题：不同文化类别的姓名在各年登记人数如何变化？

- `baby` 一行：一个姓名、性别、年份的登记人数。
- `nyt` 一行：一个姓名对应的文化类别。
- 目标结果一行：一个类别在一个年份的总登记人数。

操作计划：

1. `baby` 与 `nyt` 按姓名内连接，只保留有分类的姓名。
2. 按 `category + Year` 分组。
3. 对 `Count` 求和。
4. 按年份排序，再进行绘图或比较。

### 9.2 pandas 实现

```python
category_counts = (
    baby.merge(
        nyt,
        left_on="Name",
        right_on="nyt_name",
        how="inner",
        validate="many_to_one",
    )
    .groupby(["category", "Year"], as_index=False)
    .agg(Count=("Count", "sum"))
    .sort_values(["category", "Year"])
)
```

### 9.3 SQL 实现

```sql
SELECT
  n.category,
  b.Year,
  SUM(b.Count) AS Count
FROM baby AS b
INNER JOIN nyt AS n
  ON b.Name = n.nyt_name
GROUP BY n.category, b.Year
ORDER BY n.category, b.Year;
```

### 9.4 结果不能自动代表所有姓名

内连接只保留 `nyt` 分类表收录的姓名，因此结果回答的是：

> 这份分类名单中各类别姓名在登记数据里的变化。

它不能自动推广成“所有美国姓名的文化类别分布”。此外，SSA 数据本身有时间覆盖、登记门槛和性别编码限制。表格操作解决的是计算问题，不能替代对数据范围的判断。

### 9.5 Luna 示例中的完整推理

要判断 Luna 何时开始流行：

```python
luna = (
    baby.loc[
        (baby["Name"] == "Luna") & (baby["Sex"] == "F"),
        ["Year", "Count"],
    ]
    .sort_values("Year")
)
```

SQL 等价写法：

```sql
SELECT Year, Count
FROM baby
WHERE Name = 'Luna'
  AND Sex = 'F'
ORDER BY Year;
```

这里不能只看最大值，还要查看时间序列形状。绝对人数还会受每年总出生人数影响；若研究“相对流行度”，应计算 Luna 人数占当年相应总体的比例。问题定义决定是否用原始 `Count` 还是标准化比例。

## 10. 最容易犯的错误

### 10.1 把记录数当人数总和

`len(baby)` 是记录行数，`baby["Count"].sum()` 才是这些记录代表的人数总和。

### 10.2 把索引标签当位置

排序后 `.loc[0]` 仍取标签 0，`.iloc[0]` 才取当前第一行。

### 10.3 单列与单列 DataFrame 混淆

`df["x"]` 是 `Series`，`df[["x"]]` 是 `DataFrame`。对象维度会影响后续方法和返回形状。

### 10.4 布尔条件忘记括号

```python
# 正确
(df["a"] > 0) & (df["b"] < 10)
```

不要使用 `and`、`or` 连接整列。

### 10.5 误以为 pandas 方法都修改原表

`drop`、`rename`、`sort_values` 等通常返回新对象。若不赋值，原表仍然不变。

### 10.6 分组后选择了无意义的裸列

一组内可能有多个姓名。若按年份分组，就不能随意要求每组同时返回一个未聚合的 `Name`。

### 10.7 把 `count` 与 `sum` 混用

`count` 是非缺失记录数量，`sum` 是数值合计。两者对应不同研究问题。

### 10.8 连接前不检查键

多对多连接会产生组合数量的行。先检查重复键，再用 `validate` 声明预期基数。

### 10.9 用 `= NULL`

SQL 缺失判断必须使用 `IS NULL` 或 `IS NOT NULL`。

### 10.10 没有排序就使用 `LIMIT`

没有 `ORDER BY` 时，SQL 行没有稳定顺序，所谓“前十”没有明确业务含义。

### 10.11 混淆 `WHERE` 与 `HAVING`

`WHERE` 筛原始行，`HAVING` 筛聚合后的组。

### 10.12 只检查代码是否运行，不检查表的含义

每个关键步骤后至少检查：

```python
result.shape
result.head()
result.dtypes
result.isna().sum()
```

同时用一句话说明结果中一行代表什么。形状和粒度检查比“没有报错”更能发现逻辑错误。

## 12. 把两章压缩成一个统一解题框架

面对任何表格问题，按下面顺序写分析草稿。

### 12.1 定义目标结果

- 最终一行应该代表什么？
- 最终需要哪些列？
- 需要明细、汇总还是排名？

### 12.2 确认输入表

- 每张表一行代表什么？
- 哪些列是键？键是否唯一？
- 类型、缺失和覆盖范围是否合理？

### 12.3 用动词拆解操作

```text
筛选行 -> 选择列 -> 构造列 -> 连接 -> 分组 -> 聚合 -> 排序 -> 截取
```

顺序不是永远固定。例如先聚合再连接有时能减少数据量，但必须确认不会改变答案。

### 12.4 每一步检查不变量

- 只选择列时，行数不应改变。
- 只筛选时，行数不应增加。
- 左连接时，若右键唯一，结果行数应等于左表行数。
- 分组聚合后，行数应等于不同分组键组合数。
- `transform` 后结果长度应与原表相同。

这些不变量能快速定位逻辑错误。

### 12.5 最后解释，不只输出

最终答案至少要说明：

1. 结果中一行的含义；
2. 使用了哪些筛选条件；
3. 分组和聚合计算了什么；
4. 连接遗漏了哪些未匹配记录；
5. 结果受哪些数据范围和缺失机制限制。

## 13. 掌握检查与参考答案

先独立回答，再展开核对。

### 13.1 概念题

1. `baby["Name"]` 与 `baby[["Name"]]` 有什么区别？
2. `.loc[0:3]` 和 `.iloc[0:3]` 通常各返回几行？为什么？
3. 为什么姓名表中的行数不等于婴儿总人数？
4. `groupby().size()`、`count()` 和 `sum()` 分别回答什么问题？
5. 为什么分组聚合后必须重新说明行粒度？
6. 左表某键有 3 行、右表同键有 2 行，内连接会产生多少行？
7. SQL 中为什么不能写 `column = NULL`？
8. `WHERE` 与 `HAVING` 的区别是什么？
9. 为什么 `LIMIT 10` 前通常需要 `ORDER BY`？
10. `LENGTH(Name)` 与 `AVG(Count)` 对粒度有什么不同？
11. CTE 的主要作用是什么？
12. SQL 与 pandas 各自更适合哪些阶段？

### 13.2 参考答案

1. 前者返回一维 `Series`，后者返回二维单列 `DataFrame`。
2. `.loc` 按标签且右端点包含，标签连续时返回 4 行；`.iloc` 按位置且右端点不包含，返回 3 行。
3. 一行是一个姓名、性别、年份组合的统计，真正人数存放在 `Count` 中，需要求和。
4. `size` 数所有行，`count` 数某列非缺失值，`sum` 对数值求和。
5. 聚合把多条明细压成组级记录，结果单位已经改变；不说明粒度就无法正确解释数值。
6. 产生 `3 × 2 = 6` 行，因为每个左匹配与每个右匹配都组合。
7. `NULL` 代表未知，普通相等比较得到未知；应使用 `IS NULL`。
8. `WHERE` 在分组前筛行，`HAVING` 在分组后筛组。
9. 关系表没有可靠默认顺序，不排序的“前十”没有稳定含义。
10. `LENGTH` 对每行产生一个值，粒度不变；`AVG` 把多行聚合成一个组结果，粒度变粗。
11. 给中间查询命名，把复杂查询拆成可理解、可检查的步骤。
12. SQL 擅长数据库侧的大规模筛选、连接和聚合；pandas 擅长内存中的探索、清洗、可视化和建模衔接。

### 13.3 最终掌握标准

学完第二部分后，你应该能做到：

- 不运行代码也能预测操作会改变行、列还是粒度；
- 在 pandas 中正确使用选择、筛选、变换、分组、透视和连接；
- 在 SQL 中正确组织查询子句并理解逻辑执行顺序；
- 区分记录数、非缺失数和数值总和；
- 在连接前判断键的唯一性和基数；
- 在 pandas 与 SQL 之间翻译同一个表格问题；
- 对结果给出数据含义和范围解释，而不只是展示一张输出表。

这才是第二部分的核心：不是记住两套语法，而是建立稳定的表格推理能力。
