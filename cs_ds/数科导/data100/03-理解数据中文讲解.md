## 0. 这一部分真正要学会什么

第二部分解决了“怎样操作一张表”，第三部分要解决更难的问题：

> 我怎样确认这张表被正确读入、结构适合分析、数值值得相信，并从中发现能够解释和交流的规律？

一份真实数据通常不会以理想的 `DataFrame` 出现在你面前。它可能是带有 72 行说明文字的空格分隔文件，可能使用 Latin-1 编码，可能用 `-99.99` 代表缺失，可能把月份放在列名里，可能混合不同粒度，还可能因为时区和重复时间戳而让每天的记录数翻倍。

因此，理解数据不是“画几张图看看”，而是一条连续的证据链：

```text
原始来源
  -> 文件格式、编码和大小
  -> 正确读入并确认粒度
  -> 质量检查与可复现清洗
  -> 探索分布、关系和子群差异
  -> 设计诚实而清楚的可视化
  -> 形成可建模、可解释的分析数据
```

这五章分别负责其中一段：

| 章节          | 核心任务       | 最重要的问题              |
| ----------- | ---------- | ------------------- |
| Ch08 文件处理   | 从磁盘文件得到表   | 文件到底怎样编码和组织？一行是什么？  |
| Ch09 数据整理   | 让表可信且适合分析  | 哪些值有问题？怎样修正而不掩盖问题？  |
| Ch10 EDA    | 用图形和统计形成认识 | 分布、关系、异常和子群差异是什么？   |
| Ch11 可视化    | 让比较准确且信息清楚 | 图是否揭示结构，还是制造错觉？     |
| Ch12 空气质量案例 | 把上述步骤完整串联  | 怎样把便宜但有偏的传感器校准得更可靠？ |

学完后，你应形成一个基本习惯：

> 在解释任何图或模型之前，先说明数据从哪里来、一行代表什么、做过哪些改变，以及这些改变会怎样影响结论。

## 1. 理解数据的三个支柱

### 1.1 结构（structure）

结构描述数据怎样组织：表格、层级 JSON、固定宽度文本、多维数组，还是混合格式日志。结构决定可使用的操作。

文件格式与数据结构不是同一件事。同一张表可以存成 CSV、TSV、数据库表或 Parquet；一个 JSON 文件则可能包含一张表，也可能包含嵌套对象和多张相关表。

### 1.2 粒度与时间性（granularity and temporality）

粒度说明一条记录代表什么。时间性进一步说明记录对应的是：

- 某个瞬间的测量；
- 一段时间内的平均或总和；
- 一次事件；
- 一个持续存在的实体。

例如：

- AQS 原始表一行可能是“某日按某种标准计算的 24 小时均值”；
- PurpleAir 原始表一行是“某个通道在某一时刻的两分钟读数”；
- 清洗后两者都变成“一台传感器某日的日均值”。

只有先统一粒度，两个来源才能正确比较或连接。

### 1.3 忠实性（faithfulness）

忠实性问的是：表中的记录是否忠实地表示它声称测量的现实对象。问题可能来自：

- 采样框遗漏目标人群；
- 单位或编码解释错误；
- 缺失并非随机；
- 设备误差或系统偏差；
- 重复记录；
- 时间、地点或实体错误匹配；
- 清洗步骤改变了原始含义。

数据可以在语法上完全合法，却在现实含义上错误。例如邮编 `"Ca"` 能被正常读成字符串，但不是合法邮编；CO₂ 的 `-99.99` 能参与均值计算，但其实表示缺失。

## 2. Ch08：从文件到可信的 DataFrame

### 2.1 不要先 `read_csv`，先认识文件

拿到文件后，建议按以下顺序检查：

1. 来源和说明文档；
2. 文件名、扩展名和大小；
3. 前几行和后几行；
4. 编码；
5. 分隔方式、表头和注释行；
6. 预计读入后的行粒度与列含义。

文件扩展名只是提示，不是保证。一个 `.csv` 文件仍可能包含错误逗号、额外说明行或非 UTF-8 编码；`.txt` 也可能是规则的固定宽度表。

在 Python 中可先做无副作用检查：

```python
from pathlib import Path

path = Path("data/co2_mm_mlo.txt")

path.exists()
path.stat().st_size

with path.open("r", encoding="ascii") as file:
    for _ in range(8):
        print(file.readline().rstrip())
```

不要对未知大文件直接使用 `read_text()` 或 `cat`，因为它们会一次读取或打印全部内容。

### 2.2 文件大小不等于内存占用

磁盘上的 300 MB CSV 读入内存后可能远大于 300 MB，因为：

- 文本数字要转换成数值对象；
- 字符串列可能保存大量 Python 对象和指针；
- 解析过程会产生临时对象；
- DataFrame 还要维护索引和列元数据。

```python
size_mib = path.stat().st_size / 1024**2
print(f"{size_mib:.1f} MiB")
```

读大文件时可降低风险：

```python
# 先试读
preview = pd.read_csv("large.csv", nrows=1000)

# 只读需要的列
df = pd.read_csv(
    "large.csv",
    usecols=["date", "site_id", "pm25"],
)

# 分块处理
for chunk in pd.read_csv("large.csv", chunksize=100_000):
    process(chunk)
```

试读只能确认解析方式，不能证明文件后部完全正常。正式处理仍要检查全表的形状、类型、范围和缺失。

### 2.3 命令行是快速检查工具

课程在 Linux/Jupyter 终端中常用：

```bash
ls -lh data/
wc -l data/file.csv
head -5 data/file.csv
tail -5 data/file.csv
du -sh data/
file -I data/file.csv
```

它们分别查看文件、行数、开头、结尾、目录大小和可能的编码。在 Jupyter 代码单元中可用 `!head -5 data/file.csv` 调用 shell。

Windows PowerShell 的对应写法包括：

```powershell
Get-Item data\file.csv
Get-Content data\file.csv -TotalCount 5
Get-Content data\file.csv | Select-Object -Last 5
```

命令行的价值不只是快，还在于操作可记录、可复现，并能批量处理文件。

### 2.4 分隔文件：CSV、TSV 与空白分隔

分隔文件以某个字符分开字段：CSV 用逗号，TSV 用制表符，其他文件也可能用空格、竖线或分号。

```python
csv_df = pd.read_csv("data.csv")
tsv_df = pd.read_csv("data.tsv", sep="\t")
space_df = pd.read_csv("data.txt", sep=r"\s+")
```

常见参数要能解释：

```python
co2 = pd.read_csv(
    "data/co2_mm_mlo.txt",
    header=None,            # 数据区没有可直接使用的单行表头
    skiprows=72,            # 跳过前 72 行说明文字
    sep=r"\s+",             # 一个或多个空白字符都是分隔符
    names=["Yr", "Mo", "DecDate", "Avg", "Int", "Trend", "days"],
)
```

这段代码不是“记住参数”，而是把观察到的文件结构正式编码进读取规则。读完后必须验证：

```python
co2.shape
co2.head()
co2.tail()
co2.dtypes
```

CSV 中被引号包围的逗号不是分隔符。不要自己用 `line.split(',')` 解析 CSV，标准解析器才能正确处理引号、转义和换行。

### 2.5 固定宽度格式必须依靠 codebook

固定宽度文件不用分隔符，而是规定每个字段占据固定字符位置。DAWN 文件的每行很长，肉眼看到的数字可能挤在一起；必须查 codebook 才知道第 34 至 35 位代表年龄类别。

```python
colspecs = [
    (0, 6),
    (14, 29),
    (33, 35),
    (35, 37),
    (37, 39),
    (1213, 1214),
]

names = ["id", "wt", "age", "sex", "race", "type"]

dawn = pd.read_fwf(
    "data/DAWN-Data.txt",
    colspecs=colspecs,
    header=None,
    index_col=0,
    names=names,
)
```

`colspecs` 使用左闭右开的字符位置。读取成功不代表位置选对了，必须使用 codebook 中的允许取值做验证：

```python
assert dawn["type"].between(1, 8).all()
assert dawn["age"].between(1, 11).all()
```

### 2.6 JSON 与层级数据

JSON 由对象、数组、键和值嵌套组成，适合 Web API 和层级信息。先用标准解析器恢复结构：

```python
import json
from pathlib import Path

with Path("sensors.json").open(encoding="utf-8") as file:
    obj = json.load(file)

obj.keys()
```

如果 JSON 用 `fields` 保存列名、`data` 保存行，可写：

```python
sensors = pd.DataFrame(obj["data"], columns=obj["fields"])
```

对于更深的嵌套对象，可用 `pd.json_normalize()`。关键仍是先检查嵌套层级和每个数组中一项代表什么，而不是急着“拍平”。拍平可能重复父级信息，也可能改变粒度。

### 2.7 松散文本与日志

日志通常有模式，但不是规整表格。例如一行可能同时包含方括号时间、引号内请求和键值对。处理步骤通常是：

1. 找到稳定的分隔或文本模式；
2. 用字符串方法或正则表达式提取字段；
3. 转换类型；
4. 检查未匹配行；
5. 形成结构化表。

永远记录“有多少行没有被解析成功”。只看成功提取的行，会把最异常、也可能最重要的数据静默丢掉。

### 2.8 编码决定字节怎样变成文字

常见编码包括 ASCII、Latin-1 和 UTF-8。UTF-8 兼容 ASCII，并能表示大量语言字符。编码错误可能直接报错，也可能产生乱码。

```python
businesses = pd.read_csv(
    "data/businesses.csv",
    encoding="ISO-8859-1",
)
```

如果文档没有说明，可用 `chardet` 猜测：

```python
import chardet

raw = Path("data/businesses.csv").read_bytes()
guess = chardet.detect(raw)
guess
```

猜测结果带有置信度，不是事实。`errors="ignore"` 会悄悄删除无法解码的字符，一般不应作为默认解决方案。

### 2.9 读入后立刻确认形状与粒度

```python
df.shape
df.columns.tolist()
df.dtypes
df.head()
```

然后写出一句完整定义：

> 这张表的一行代表 ______，候选主键是 ______，时间字段表示 ______ 时段或时刻。

再用代码验证候选键：

```python
key = ["business_id", "date"]
duplicate_count = df.duplicated(key, keep=False).sum()
```

重复不一定是错误。餐厅一年可以检查多次；AQS 同一天可能因多个计算标准出现多行。真正的问题是：重复行是否符合你对粒度的定义。

## 3. Ch09：数据清洗不是美化，而是恢复含义

### 3.1 四个质量检查视角

读入并理解粒度后，从四个方向检查质量：

| 视角 | 问题 | 示例 |
| --- | --- | --- |
| 范围 | 是否符合目标总体和时空范围 | 旧金山邮编通常应以 941 开头 |
| 测量和值 | 范围、单位、编码是否合理 | 检查分数应在 0 到 100 |
| 变量关系 | 相关字段是否内部一致 | 结束日期不能早于开始日期 |
| 分析用途 | 该列是否有足够信息 | 14000 条记录中只有一个特殊类别 |

代码层面的常用检查：

```python
df.info()
df.describe(include="all")
df.nunique(dropna=False)
df.isna().mean().sort_values(ascending=False)
df["category"].value_counts(dropna=False)
```

范围断言比只看表头更可靠：

```python
bad_score = ~df["score"].between(0, 100)
df.loc[bad_score]

bad_month = ~df["month"].between(1, 12)
assert not bad_month.any()
```

不要只报告“有异常”，还要查看异常记录的其他列，因为整行可能错位，也可能代表一个真实而特殊的对象。

### 3.2 修不修数据是分析决策

发现问题后有四类选择：

1. 保持原样，但记录限制；
2. 修正个别值，同时保留原始值；
3. 删除不可靠或无用的列；
4. 删除记录或缩小研究范围。

不应自动删除离群值。异常值可能是录入错误，也可能是野火、金融危机或真正罕见的高价房。先调查来源，再判断它对研究问题是否属于目标范围。

推荐保留原列：

```python
df = df.assign(
    postal_code_clean=df["postal_code"].str.extract(r"(\d{5})", expand=False)
)
```

这样既能分析清洗值，也能追溯原始记录。

### 3.3 缺失有两个层次

- **整条记录缺失**：某个人、事件或日期完全没有进入数据。
- **字段缺失**：记录存在，但某列未知或未填写。

`NaN` 只会显示已存在记录中的字段缺失，无法显示“根本没有被采集的整行”。因此 `isna()` 不能发现抽样框遗漏或不回应者。

### 3.4 缺失机制决定能否修复

常见概念是：

- **完全随机缺失（MCAR）**：缺失与该值、其他变量和抽样设计都无关，例如设备被意外损坏一天。
- **给定协变量后随机缺失（MAR）**：在已知其他变量后，缺失不再依赖未观测值，例如不回应只由已记录的年龄和地区决定。
- **非随机缺失（MNAR）**：缺失本身与未观测值有关，例如高收入者更不愿报告收入。

缺失机制不能仅凭数据表完全证明，需要收集流程和领域知识。样本量增大也不会自动消除系统性的缺失偏差。

### 3.5 特殊编码要先转成真正缺失

CO₂ 数据用 `-99.99` 表示 `Avg` 缺失，用 `-1` 表示设备运行天数缺失。如果保留这些数字，它们会污染均值和图形。

```python
co2 = co2.replace({
    "Avg": {-99.99: np.nan},
    "days": {-1: np.nan},
})
```

更稳妥的方式是在读取时声明：

```python
co2 = pd.read_csv(
    "data/co2_mm_mlo.txt",
    skiprows=72,
    sep=r"\s+",
    header=None,
    names=names,
    na_values={"Avg": [-99.99], "days": [-1]},
)
```

### 3.6 删除、保留和插补

```python
df.dropna(subset=["critical_feature"])
df["x"].fillna(df["x"].median())
df["x_was_missing"] = df["x"].isna()
```

常见插补方法：

- **演绎插补**：利用逻辑关系或外部来源确定值，证据最强。
- **均值/中位数插补**：简单，但会人为降低变异，影响相关性和区间估计。
- **热卡插补**：从相似已观测记录中随机借值，保留分布但会加入随机性。
- **邻近或回归插补**：用其他变量预测缺失值，依赖模型假设。
- **时间序列插值**：使用相邻时间与季节规律，只适合有充分时间结构的变量。

无论使用哪种方法，都应保留缺失指示列，记录规则，并比较处理前后的结论。预测缺失值不等于真正观测到它。

### 3.7 三类变量变换

1. **类型转换**：字符串价格转数值、字符串日期转时间戳。
2. **数学变换**：单位换算、对数、比例、价格每平方英尺。
3. **信息提取**：从文本、日期或编码中得到新特征。

```python
price = (
    df["price"]
      .str.replace("$", "", regex=False)
      .str.replace(",", "", regex=False)
      .pipe(pd.to_numeric, errors="coerce")
)

df = df.assign(log_price=np.log(df["price"]))
df = df.assign(is_vermin=df["description"].str.contains("vermin", na=False))
```

`errors="coerce"` 会把无法转换的值设为缺失，因此转换后必须检查新增缺失来自哪些原始字符串。

### 3.8 时间戳：格式、时区和日历语义

```python
dates = pd.to_datetime(
    inspections["date"],
    format="%Y%m%d",
    errors="raise",
)

inspections = inspections.assign(
    timestamp=dates,
    year=dates.dt.year,
    month=dates.dt.month,
    day_of_week=dates.dt.day_of_week,
)
```

显式 `format` 可以避免把日月顺序猜错。成功解析只说明字符串符合格式，不保证日期符合研究范围。

带时区数据要区分：

- `tz_localize`：给原本没有时区的时间指定时区；
- `tz_convert`：把已有时区的时间转换到另一时区。

夏令时会产生 23 小时或 25 小时的一天。按日聚合传感器读数时，如果忽略时区，原本属于本地日期的记录可能落入相邻日期。

### 3.9 `resample` 是时间索引上的分组

```python
sensor = sensor.set_index("timestamp")

records_per_day = sensor.resample("D").size()
daily_mean = sensor.resample("D")["pm25"].mean()
weekly_mean = sensor.resample("W")["pm25"].mean()
```

`resample("D")` 按日分组，`W` 按周，`M` 或新版中的相应月末频率按月。它要求 `DatetimeIndex`。聚合前必须决定时区和每个时间窗口是否有足够观测。

### 3.10 调整结构：简化、统一粒度和宽长转换

常见结构调整包括：

- 删除不需要的列；
- 限制时间、地点或目标子群；
- 将细粒度记录聚合到目标粒度；
- 将混合粒度拆成多张表；
- 将宽表转成长表。

```python
long_df = wide_df.melt(
    id_vars=["year"],
    var_name="month",
    value_name="average",
)
```

长表中一行只对应一个 `year + month` 值，更适合分组、绘图和建模。`melt` 会改变形状，但不应改变信息总量；转换后要核对行数和键组合。

### 3.11 用函数与 `.pipe()` 固化清洗流程

Notebook 可任意顺序运行，反复原地修改容易产生隐藏状态。把每个变换写成“输入 DataFrame，返回新 DataFrame”的函数：

```python
def parse_dates_and_years(df, column="date"):
    dates = pd.to_datetime(df[column], format="%Y%m%d")
    return df.assign(timestamp=dates, year=dates.dt.year)


def subset_2016(df):
    return df.query("year == 2016")


clean = (
    pd.read_csv("inspections.csv")
      .pipe(parse_dates_and_years)
      .pipe(subset_2016)
)
```

好处是步骤可读、可测试、可复用，也不依赖“之前刚好运行过某个单元”。函数内部需要修改时先 `.copy()`，避免意外改到调用者对象。

### 3.12 CO₂ 案例：一条完整清洗链

Mauna Loa 月均 CO₂ 数据展示了清洗的正确顺序：

1. 检查文件大小、编码和前几行；
2. 发现数据从第 73 行开始，以空白分隔；
3. 读入后确认一行是一个月，1958 年 3 月到 2019 年 8 月共 738 行；
4. 检查月份 1 到 12 的频数；
5. 发现 `-99.99` 与 `-1` 是缺失编码；
6. 检查缺失集中在哪些年份；
7. 比较删除、保留 `NaN` 和季节性插值三种处理；
8. 按年份聚合，得到长期趋势。

```python
annual = (
    co2.replace(-99.99, np.nan)
       .groupby("Yr", as_index=False)
       .agg(average_co2=("Int", "mean"))
)
```

月度数据揭示季节呼吸，年度数据揭示长期上升。不存在永远“最好”的粒度，只有与问题匹配的粒度。

### 3.13 餐厅案例：先统一粒度再连接

检查表一行是一场检查，违规表一行是一条违规。一场检查可能有多条违规，不能直接连接后分析分数，否则检查会按违规数被重复。

```python
num_vios = (
    violations
      .groupby(["business_id", "timestamp"])
      .size()
      .rename("num_vio")
      .reset_index()
)

inspection_level = inspections.merge(
    num_vios,
    on=["business_id", "timestamp"],
    how="left",
    validate="one_to_one",
)
```

左连接保留没有违规记录的检查。只有在领域规则支持时才能把缺失改为 0，例如分数 100 的检查可演绎推断为没有违规；其他未匹配记录可能来自日期错位，不能一概填 0。

违规描述可提取为布尔特征：

```python
def make_violation_features(vio):
    text = vio["description"]
    return vio.assign(
        vermin=text.str.contains(r"vermin", case=False, na=False),
        hygiene=text.str.contains(r"hand|glove|hair|nail", case=False, na=False),
        storage=text.str.contains(r"thaw|cool|therm|storage", case=False, na=False),
    )
```

这些规则是可解释的特征工程，但可能漏掉同义词或误匹配语境，必须抽样检查命中和未命中的文本。

## 4. Ch10：探索性数据分析是一套提问方法

### 4.1 EDA 不是无目的地画图

EDA 的目标是形成对数据的可检验认识，并让新发现指导下一步。四个基础问题是：

1. 特征 X 怎样分布？
2. X 与 Y 有什么关系？
3. X 的分布是否随 Z 定义的子群变化？
4. X、`(X, Y)` 或某个 Z 子群中是否有异常观测？

每得到一个图形结论，都继续追问：

- **So what?** 这个形状为什么重要？
- **What next?** 下一项最有价值的比较是什么？
- 这个结果是数据错误、抽样设计，还是现实机制？
- 哪个新变量或分组能区分这些解释？

EDA 会反复回到清洗阶段。它不是建模前一次性完成的清单。

### 4.2 特征类型不等于存储类型

| 特征类型 | 含义 | 合理运算 |
| --- | --- | --- |
| 名义型 | 类别无自然顺序 | 频数、比例、众数 |
| 有序型 | 类别有顺序，但间隔未必相等 | 顺序、分位位置、比例 |
| 定量型 | 数值差异有实际含义 | 均值、中位数、差、比例等 |
| 离散定量 | 只取有限或可数值 | 计数、分布，可视情况当类别 |
| 连续定量 | 理论上可任意精细测量 | 密度、位置、尺度、关系 |

`dtype=int64` 不代表变量一定是定量型。邮编、等级编码和类别 ID 都可能以整数存储。反过来，`"$2.17"` 是字符串存储，却表达定量价格。

判断标准是：对值做差或做比是否具有现实意义，而不是 Python 是否允许计算。

### 4.3 类型决定汇总和图形

| 变量组合 | 首选图形或汇总 |
| --- | --- |
| 单个名义/有序变量 | 频数、比例、条形图、点图 |
| 单个定量变量 | 直方图、KDE、箱线图、分位数 |
| 两个定量变量 | 散点图、平滑曲线、hexbin、等高线、q-q 图 |
| 一个类别 + 一个定量 | 分组箱线图、violin、叠加 KDE、分面图 |
| 两个类别变量 | 条件比例、并列条形图、马赛克图 |
| 时间 + 定量变量 | 折线图，必要时展示区间或多个分位数 |

图形选择还受样本量和唯一值数量影响。只有少数整数值的定量变量，条形图有时比直方图更清楚。

### 4.4 类别变换必须保留原始信息

有三种常见处理：

- 把 `1/2/3` 重标为 `high/medium/low`，恢复语义；
- 把多个类别合并成更高层概念；
- 把长尾数值截成 `0, 1, 2, 3, 4+` 等有序类别。

```python
df["suitability"] = df["children"].map({1: "high", 2: "medium", 3: "low"})
df["many_ailments"] = df["ailments"].ge(4)
df["ailments_group"] = df["ailments"].clip(upper=4).astype(str).replace("4", "4+")
```

合并类别和离散化会丢失信息，所以创建新列，不覆盖原列。类别边界必须由分析目的或领域依据决定，而不是为了让图“更好看”。

### 4.5 怎样读一个分布

不要只说“看起来像正态”。按以下维度描述：

- 中心在哪里；
- 离散程度多大；
- 单峰、多峰还是有肩部；
- 对称、左偏还是右偏；
- 尾部多长；
- 是否有空隙、边界或堆积点；
- 是否有异常值；
- 这些形状对应什么现实量。

直方图中，若 y 轴是 density，柱面积之和为 1：

```text
某区间所占比例 ≈ 柱宽 × 柱高
```

当柱宽不同时，不能只比较柱高。条形图则不同：类别频数由高度表达，柱宽没有数据含义；类别顺序也不像数轴那样连续。因此不能用“尾部、偏度、连续峰形”解释条形图。

### 4.6 箱线图、violin 和 KDE 各看到什么

- 直方图：较直观地显示峰、偏度和尾部，但受箱宽影响。
- KDE：给出平滑密度形状，但受带宽影响，并可能在不可能区域产生密度。
- 箱线图：压缩为 Q1、中位数、Q3、IQR 和须，适合跨组比较，但会隐藏多峰。
- violin：在每组展示平滑密度，信息较多，但样本少时容易显得过度精确。

箱线图中超出须的点只是按规则标出的潜在离群点，不等于错误值。

### 4.7 KDE 的逻辑与带宽

KDE 在每个观测值上放一个核函数，再把所有核相加并归一化：

$$
\hat f_h(x)=\frac{1}{nh}\sum_{i=1}^{n}K\left(\frac{x-x_i}{h}\right)
$$

- $K$ 是核，例如 Gaussian 或 boxcar；
- $h$ 是带宽；
- $h$ 小时曲线起伏多，可能追逐随机噪声；
- $h$ 大时曲线过平，可能抹掉真实多峰。

```python
sns.kdeplot(data=df, x="value", bw_adjust=0.5)
sns.kdeplot(data=df, x="value", bw_adjust=1.0)
sns.kdeplot(data=df, x="value", bw_adjust=2.0)
```

应尝试多个合理带宽，确认主要结论是否稳定。KDE 是估计，不是原始数据本身。

### 4.8 怎样读两个变量的关系

两个定量变量的散点图要观察：

- 方向：正、负或无明显方向；
- 形式：线性、弯曲、分段、周期；
- 强度：点围绕趋势的紧密程度；
- 条件变异：x 改变时 y 的散布是否改变；
- 子群：是否混合了多类对象；
- 异常点：高杠杆点、离群点或特殊事件。

两个单变量直方图无法恢复配对关系。即使 X、Y 各自分布相同，配对方式不同也能产生完全不同的相关关系。

```python
sns.scatterplot(data=df, x="height", y="weight")
sns.regplot(data=df, x="height", y="weight", lowess=True)
```

平滑线用于揭示形状，不应被自动解释成因果效应。

### 4.9 一个类别变量与一个定量变量

核心是比较各组的**完整分布**，而不只比较均值：

```python
sns.boxplot(data=df, x="city", y="log_price")
sns.violinplot(data=df, x="size", y="height", inner="quartile")
```

组样本量不同、分布偏斜或多峰时，同样的均值可能掩盖重要差异。图旁最好同时报告每组样本量。

### 4.10 两个类别变量要比较条件比例

如果各组总人数不同，只比较计数常常会误导。应在一个条件内归一化：

```python
counts = pd.crosstab(df["suitability"], df["size"])
proportions = counts.div(counts.sum(axis=1), axis=0)
```

这里每一行和为 1，含义是“给定 suitability 后，各 size 的比例”。若按列归一化，回答的是另一个条件问题。必须在文字中说明分母是谁。

### 4.11 多变量、分面与 Simpson 悖论

第三个变量可以通过颜色、符号、线型或分面加入图中。类别较多时，分面通常比十几种颜色更清楚：

```python
sns.lmplot(
    data=df,
    x="height",
    y="longevity",
    col="repetition_group",
    col_wrap=2,
    lowess=True,
)
```

分面是在控制一个变量后比较 X 与 Y 的关系。总体趋势可能在每个子组内减弱、消失甚至反向，这就是 Simpson 悖论。它提醒我们：总体关联可能来自组间构成差异。

随着维度增加，类别组合数迅速增长，子组样本变少，这就是维度灾难在探索中的表现。不要为了“控制更多变量”制造大量几乎没有数据的小图。

### 4.12 房价案例：让新发现决定下一步

房价 EDA 的逻辑值得完整掌握：

1. 明确一行是一笔房屋交易，不是一栋唯一房屋；
2. 发现售价右偏，最大值远高于中位数；
3. 查看高分位数，确认 99.9% 低于约 400 万美元；
4. 使用对数价格获得更对称的分布；
5. 固定到 2004 年并限制极端面积、价格，减少时间和极端对象混杂；
6. 检查建筑面积、地块面积和卧室数；
7. 发现地块面积 436 平方英尺堆积及 30 多卧室等疑点；
8. 构造每平方英尺价格；
9. 发现小房屋每平方英尺更贵，关系是非线性的；
10. 按城市分面，看到位置带来的价格提升。

这不是一开始就决定画十张图，而是每个结果触发下一项调查。EDA 的产物不只是图，还包括：需要修复的质量问题、值得建模的新特征、合理的变换和更精确的问题定义。

## 5. Ch11：可视化的目标是让比较变得准确

### 5.1 探索图与解释图

探索图主要服务分析者自己，可以快速、粗糙、数量多，目标是暴露问题。解释图面向读者，应围绕一个清晰结论，补充上下文并删除无关元素。

无论哪一种图，都要先回答：

1. 读者需要比较什么？
2. 哪个视觉通道最准确地表达这种比较？
3. 数据范围、采样设计或清洗步骤是否需要在图中说明？

同一份数据可以画出很多合法图形，但不一定都让关键差异容易看见。

### 5.2 人眼判断信息的准确度有顺序

通常从容易准确判断到较难判断：

1. 同一坐标轴上的位置；
2. 相同但未对齐坐标轴上的位置；
3. 长度；
4. 角度和斜率；
5. 面积；
6. 体积和密度；
7. 颜色饱和度与色相。

因此，重要比较尽量使用位置或长度。饼图要求比较角度，气泡图要求比较面积，三维柱状图要求比较体积，都比对齐的点或条形更难准确读取。

### 5.3 对齐比较对象

若要比较同一教育水平下男女收入差异，就应让两个点在同一水平或垂直基线上对齐，而不是把所有男性和所有女性分别堆在两个区域。

类别排序规则：

- 有序变量遵循自然顺序；
- 名义类别的条形通常按高度排序；
- 多组箱线图通常按中位数排序；
- 时间永远按时间先后排序。

```python
order = (
    df.groupby("city")["price"]
      .median()
      .sort_values()
      .index
)

sns.boxplot(data=df, x="city", y="price", order=order)
```

### 5.4 尽量避免堆叠

堆叠条形图只有最底层类别共享同一基线，其他部分的上下边界都在移动，难以比较。堆叠面积图更严重，因为读者需要判断两条起伏曲线之间的宽度。

如果目标是比较各类别随时间的变化，通常使用：

- 不堆叠的多条折线；
- 分面小图；
- 条件比例的并列点图；
- 热力图。

堆叠图适合强调“总量及构成”，不适合精确比较每个组成部分。

### 5.5 坐标轴是否从 0 开始

没有一条规则要求所有图都从 0 开始。

- **条形图通常必须从 0 开始**，因为条长直接编码数值；截断会夸大差异。
- **比例图通常包括 0**，因为 0 到 1 是完整有意义范围。
- **散点图和折线图不一定从 0 开始**，若从 0 开始产生大量空白并隐藏关系，可以缩小范围。

若裁掉极端值或缩放坐标，应在标题、图注或正文中明确说明。调整显示范围不等于删除数据，但读者需要知道哪些数据没有显示。

### 5.6 用变换揭示结构

右偏分布常被少数巨大值挤在图的一侧。对数尺度能把数量级很大的值拉近：

```python
ax = sns.histplot(data=houses, x="price", bins=40)
ax.set_xscale("log")
```

轴使用 log scale 时，标签仍可显示原始单位，比手动创建 `log_price` 更容易解释。但建模时往往仍需显式构造变换后的特征。

两变量经变换后呈线性时，可反推原关系：

| x 轴 | y 轴 | 直线对应的原关系 |
| --- | --- | --- |
| 原尺度 | 原尺度 | $y=ax+b$，线性 |
| log(x) | 原尺度 | $y=a\log x+b$，线性-对数 |
| 原尺度 | log(y) | $y=ba^x$，指数 |
| log(x) | log(y) | $y=bx^a$，幂律 |

计数数据有时适合平方根变换。任何变换都要有目的：改善可见性、稳定变异或把关系拉直，而不是试遍函数后只保留最好看的结果。

### 5.7 Banking：让趋势接近 45 度

散点图或折线图的纵横比会改变视觉斜率。将主要趋势调整到大约 45 度附近，通常更容易看出偏离、弯曲和局部变化。这称为 banking to 45 degrees。

它不是修改数据，而是选择更合适的画布比例。若同一图被拉得极宽或极高，读者对变化速度的感受会不同。

### 5.8 过度绘制需要聚合或平滑

七万个点画在散点图中会互相覆盖，肉眼看不到密度。常见解决方法：

```python
# 半透明，只适合中等规模
sns.scatterplot(data=df, x="age", y="time", alpha=0.15, s=10)

# 六边形分箱
plt.hexbin(df["age"], df["time"], gridsize=35, mincnt=1)
plt.colorbar(label="count")

# 二维 KDE 等高线
sns.kdeplot(data=df, x="age", y="time", levels=8, fill=True)
```

也可以将相近 x 分箱，再绘制每箱的均值或中位数：

```python
summary = (
    df.assign(age_bin=pd.cut(df["age"], bins=range(10, 91, 5)))
      .groupby("age_bin", observed=True)
      .agg(age=("age", "median"), time=("time", "median"))
)

sns.lineplot(data=summary, x="age", y="time", marker="o")
```

平滑会牺牲个体细节来显示总体结构。它不能替代原始数据检查，尤其在边界和稀疏区域。

### 5.9 平滑参数必须做敏感性检查

直方图的箱宽、KDE 的带宽、局部回归的平滑程度都会改变图形。

- 参数太小：保留太多采样噪声；
- 参数太大：真实峰和局部变化被抹掉。

不要只展示自动默认值。至少尝试偏小、默认和偏大的三个值，确认核心结论是否稳定。若结论只在一个精心挑选的参数下出现，它很可能不可靠。

### 5.10 q-q 图比较完整分布

q-q 图将两个分布的相同分位数配对：

```python
probs = np.linspace(0.01, 0.99, 99)
xq = np.quantile(group_a, probs)
yq = np.quantile(group_b, probs)

sns.scatterplot(x=xq, y=yq)
plt.axline((0, 0), slope=1, linestyle="--")
```

解释方式：

- 点接近 $y=x$：位置和尺度相近；
- 大致为直线但斜率大于 1：Y 的离散程度更大；
- 截距不为 0：中心有系统偏移；
- 尾部弯曲：两分布尾部形状不同。

q-q 图保留配对分位数信息，但不显示同一观测上的两个测量如何共同变化；后者需要散点图或差值图。

### 5.11 颜色必须编码信息

三类常见色板：

- **qualitative**：区分无顺序类别；
- **sequential**：从低到高的定量值；
- **diverging**：强调中点两侧的正负或两个极端。

颜色应尽量感知均匀、色盲友好，并在灰度打印时仍可辨认。类别颜色一般不要超过约 7 种；类别再多时改用分面、筛选或直接标注。

不要使用颜色仅作装饰。颜色、符号和线型适合作为位置之外的辅助通道，不应承担最需要精确读取的数值。

### 5.12 图形必须反映数据设计

一张图在数值上正确，也可能在推断上误导。

**时间数据**：使用时间轴，并考虑通胀、季节和事件节点。房价随时间比较时，可以展示多个分位数相对起始年的变化，而不是只画均值。

**横截面数据**：不同年龄的人不是同一个人随年龄变化。赛跑数据中 60 岁参赛者和 40 岁参赛者是不同群体，不能据此推断同一人 20 年后的成绩。

**不等概率抽样**：DAWN 复杂抽样中每条记录有权重。不加权频数描述的是样本，不是全国急诊就诊总体。

```python
weighted_count = (
    dawn.groupby("type")["wt"]
        .sum()
        .sort_values(ascending=False)
)
```

**地理数据**：传感器在地区上分布不均。将全部站点观测直接做全国直方图，会让传感器密集地区获得更大权重。地图、地区分面或空间加权可能更合适。

### 5.13 给图增加足够上下文

一张面向读者的图至少应考虑：

- 标题是否直接说明主要发现；
- 轴标签是否含变量名和单位；
- 图例是否必要且顺序合理；
- 数据时间、地点和筛选条件；
- 被排除的记录；
- 参考线、政策阈值或事件日期；
- 数据来源和样本量。

## 6. 补充专题：气候数据与 Xarray

### 6.1 为什么普通 DataFrame 不总是最自然

气候数据常同时有 `time × latitude × longitude × variable` 多个维度。把每个网格点和时间全部摊平成长表虽然可行，但会丢失清楚的坐标结构。

Xarray 提供两个核心对象：

- `DataArray`：一个带维度名和坐标的多维数组；
- `Dataset`：共享坐标系统的多个 `DataArray` 集合。

```python
import xarray as xr

ds = xr.open_dataset("era5.nc")
ds

temperature = ds["air_temperature_at_2_metres"]
temperature.dims
temperature.coords
```

维度是轴的名字，例如 `time`、`latitude`、`longitude`；坐标是轴上的具体标签。数据变量是在这些坐标上变化的测量值。

### 6.2 `isel` 按位置，`sel` 按坐标

```python
# 整数位置，右端点不包含
first = ds.isel(time=0, latitude=26, longitude=119)

# 坐标标签："1979-01" 会选中整个月
berkeley_jan = ds.sel(
    time="1979-01",
    latitude=37.125,
    longitude=238.875,
)

# 坐标不一定恰好存在时，可只对标量坐标寻找最近点
nearest_location = ds.sel(
    latitude=37.13,
    longitude=238.88,
    method="nearest",
)
```

这与 pandas 的 `.iloc` 和 `.loc` 类似。部分日期字符串可能选择一个时间区间，而 `method="nearest"` 适用于标量标签，二者不要放在同一次 `.sel()` 中。气候数据中应优先使用有语义的坐标选择，避免数据网格变化后位置索引指向不同地点。

### 6.3 全球平均不能直接平均网格点

经纬网格越靠近两极，格点代表的实际面积越小。直接对所有纬度、经度单元求均值会让高纬地区权重过大。常用近似权重是：

$$
w(\phi)=\cos(\phi)
$$

```python
weights = np.cos(np.deg2rad(ds.latitude))

global_mean = (
    ds["air_temperature_at_2_metres"]
      .weighted(weights)
      .mean(dim=["latitude", "longitude"])
)
```

这与调查加权是同一种思想：一条记录或一个网格单元对目标总体的代表量不同，汇总时必须体现设计。

### 6.4 时间分组与气候趋势

```python
monthly_cycle = temperature.groupby("time.month").mean("time")
annual_mean = temperature.resample(time="YS").mean()
```

季节循环和长期趋势回答不同问题。ERA5 是再分析数据：它把历史观测与物理模型、数据同化结合成完整的时空估计，不等同于每个网格点都有直接观测。

模型中的 parameterization 是对无法直接解析的物理过程的近似。它让模型可计算，也引入假设和误差；使用气候数据时要区分直接观测、再分析结果和模型预测。

## 7. Ch12：PurpleAir 案例完整走过理解数据流程

### 7.1 问题不是“哪个传感器更好”

AQS 传感器昂贵、稀疏、延迟约一到两小时，但经过严格校准，被视为较准确的基准。PurpleAir 约 250 美元、数量多、每两分钟报告一次，空间和时间覆盖更好，却常系统性高估 PM2.5。

真正的问题是：

> 能否用少量准确的 AQS 数据，校准大量及时但有偏的 PurpleAir 数据？

这是“大而噪的数据 + 小而准的数据”的典型问题。

### 7.2 为什么必须找共址传感器

若 AQS 在公园、PurpleAir 在高速公路旁，两者差异可能来自环境，不是设备。共址匹配尽量让两台设备测量同一团空气，从而控制地点这个混杂因素。

EPA 研究把 50 米内的设备作为候选，并进一步联系站点确认。课程案例用近似矩形匹配：

```python
meters_per_lat_degree = 111_111
meters_per_lon_degree = 111_111 * np.cos(np.radians(median_latitude))

lat_offset = 25 / meters_per_lat_degree
lon_offset = 25 / meters_per_lon_degree
```

然后按经纬度容差连接。这个近似适合候选筛选，不是精确测地距离；严谨空间匹配可使用 haversine 距离或 GeoPandas 空间连接。

### 7.3 匹配前先修复站点粒度

AQS 站点表的 `AQS_Site_ID` 有重复，因为一处站点可能有多个测量同一污染物的仪器，`POC` 区分这些仪器。因此原表粒度是“仪器”，不是“站点”。

```python
aqs_sites = (
    aqs_sites_full
      .groupby("AQS_Site_ID", as_index=False)
      .first()
      [["AQS_Site_ID", "Latitude", "Longitude"]]
      .rename(columns={
          "AQS_Site_ID": "site_id",
          "Latitude": "lat",
          "Longitude": "lon",
      })
)
```

只有确认同一站点的选择规则合理后，才能取第一条。不能把 `.first()` 当作通用去重方法。

PurpleAir 站点来自 JSON，先用 `fields` 和 `data` 还原 DataFrame，再确认传感器 ID 唯一。课程近似匹配得到 149 个候选 AQS-PurpleAir 站点对。

### 7.4 清洗 AQS：重复日期不一定是重复测量

目标粒度是一日一条 24 小时 PM2.5 均值，但原表每个日期有 12 行，原因是不同污染物标准和特殊事件选项。

先比较同日 12 个 `arithmetic_mean` 的极差：

```python
daily_ranges = (
    aqs_full.groupby("date_local")["arithmetic_mean"]
            .agg(np.ptp)
)
```

所有日期极差都是 0，说明 12 行的目标测量相同，因此可以按日取第一条：

```python
aqs = (
    aqs_full.groupby("date_local", as_index=False)
            .first()
            [["date_local", "arithmetic_mean"]]
            .rename(columns={"arithmetic_mean": "pm25"})
)
```

随后显式解析 `%Y-%m-%d`，检查缺失日期和 PM2.5 非负范围。2018 年 11 月的巨大峰值不是错误，它对应 Sacramento 附近 Camp Fire 的真实事件。

### 7.5 清洗 PurpleAir：先理解设备设计

每个 PurpleAir 站点有 A、B 两个通道，分别记录 Primary 与 Secondary 文件。目标变量来自 Primary 文件中的：

- `PM2.5_CF1_ug/m3`；
- 温度；
- 相对湿度。

CF1 与 ATM 是两种把激光读数转换成 PM2.5 的方法，原研究发现 CF1 更适合后续校准。

```python
def select_and_rename(df):
    return (
        df[[
            "created_at",
            "PM2.5_CF1_ug/m3",
            "Temperature_F",
            "Humidity_%",
        ]]
        .rename(columns={
            "created_at": "timestamp",
            "PM2.5_CF1_ug/m3": "pm25",
            "Temperature_F": "temp_f",
            "Humidity_%": "rh",
        })
    )
```

### 7.6 时区、采样频率和重复时间戳

PurpleAir 时间是 UTC，而 AQS 日均值按 California 本地日计算。必须先转换：

```python
def parse_and_convert_time(df):
    timestamp = pd.to_datetime(
        df["timestamp"],
        format="%Y-%m-%d %X %Z",
        utc=True,
    )
    return (
        df.assign(timestamp=timestamp)
          .set_index("timestamp")
          .tz_convert("US/Pacific")
    )
```

检查每天记录数后发现：

- 2019-05-30 前每 80 秒一次，理论每天 1080 条；
- 之后每 120 秒一次，理论每天 720 条；
- 某些日期每个时间戳重复两次；
- 夏令时结束日可能有 25 小时，因此记录数更高；
- 一些时间段完全缺失。

```python
sensor = sensor.loc[~sensor.index.duplicated(keep="first")]
per_day = sensor.resample("D").size()
```

看到“每天约 2000 条”不能直接认为传感器采样更频繁。必须检查时间戳是否重复以及重复行的测量值是否一致。

### 7.7 日均值必须满足完整度门槛

如果一天只有少量读数，简单平均并不能代表 24 小时。原分析要求至少达到理论记录数的 90%：

```python
change_date = pd.Timestamp("2019-05-30", tz="US/Pacific")

def expected_count(day):
    return 1080 if day < change_date else 720

counts = sensor.resample("D").size()
enough = pd.Series(
    [count >= 0.9 * expected_count(day) for day, count in counts.items()],
    index=counts.index,
)

daily = sensor.resample("D").mean().loc[enough]
```

代码实现可不同，但逻辑必须包含：理论采样数会随日期变化，实际数达到 90% 才保留。

### 7.8 双通道是内部质量控制

A、B 通道都清洗成日均值后，比较同日结果。Barkjohn 的规则会删除两通道相差超过 61% 或超过 5 µg/m³ 的日期。最终的每个 PurpleAir 日均值应同时满足：

- 当天记录足够完整；
- 时间戳去重；
- 两通道均可用；
- 两通道结果一致；
- 以两个通道的平均作为站点日值。

双通道不是两倍样本，而是设备内部的重复测量，用来发现传感器故障。

### 7.9 EDA 应围绕校准目标

清洗并合并共址日均值后，依次检查：

1. 单站点周均时间序列：两设备是否同步上下波动；
2. 两种测量的直方图或 q-q 图：中心、尺度和尾部怎样不同；
3. `PA - AQS` 差值分布：是否围绕 0；
4. `AQS` 对 `PA` 散点图：关系形式是否足够简单；
5. 相关系数与局部平滑：线性强度及低浓度区弯曲；
6. 湿度是否解释剩余偏差。

主要发现是：

- PurpleAir 与 AQS 同步变化，说明它捕捉到了真实空气质量趋势；
- PurpleAir 通常更高，约 90% 的日期高于 AQS；
- PurpleAir 分布约有 AQS 两倍的尺度；
- 两者高度相关且大致线性；
- 低污染区存在轻微弯曲；
- 相对湿度有助于解释误差。

相关高并不意味着两设备一致。一个设备恒等于另一个的两倍，相关可以是 1，但绝对误差很大。

### 7.10 校准模型为什么要反过来拟合

把 AQS 视为接近真实值，先拟合仪器读数：

$$
\text{PA} \approx b+m\text{AQS}
$$

```python
from sklearn.linear_model import LinearRegression

X = data[["pm25aqs"]]
y = data["pm25pa"]

calibration = LinearRegression().fit(X, y)
m = calibration.coef_[0]
b = calibration.intercept_
```

未来只有 PurpleAir 读数时，将校准线反解：

$$
\widehat{\text{True PM}_{2.5}}
=-\frac{b}{m}+\frac{1}{m}\text{PA}
$$

之所以把准确的 AQS 放在 x 轴，是因为普通最小二乘最小化 y 方向误差。校准场景把已知标准量当作输入，研究仪器会报告什么，再反解未知真值。只有两种测量高度相关时，这种逆回归才合理。

### 7.11 加入湿度的多变量校准

最终模型加入相对湿度：

$$
\text{PA}\approx b+m_1\text{AQS}+m_2\text{RH}
$$

反解得到：

$$
\widehat{\text{True PM}_{2.5}}
=-\frac{b}{m_1}
+\frac{1}{m_1}\text{PA}
-\frac{m_2}{m_1}\text{RH}
$$

```python
X = data[["pm25aqs", "rh"]]
y = data["pm25pa"]

model = LinearRegression().fit(X, y)
m1, m2 = model.coef_
b = model.intercept_

intercept = -b / m1
pa_coef = 1 / m1
rh_coef = -m2 / m1
```

湿度模型表现更好，因为光学粒子传感器的读数会受空气水分影响。模型系数不是纯粹数学结果，而应能与设备机理相互解释。

### 7.12 这个案例真正教会什么

模型代码只有几行，困难工作在模型之前：

- 正确理解两类设备；
- 找到真正可比较的共址站点；
- 统一站点、日期和测量粒度；
- 处理时区、夏令时、重复记录和采样率变化；
- 设置完整度和双通道一致性规则；
- 用 EDA 判断校准关系的形式；
- 最后才拟合模型。

如果前面的数据准备错了，线性回归仍会输出系数，但系数没有可信含义。

## 9. 最容易犯的错误

### 9.1 文件能读入就认为读对了

列数正确并不代表编码、分隔、表头和字段位置正确。必须用文档、允许范围和预期行数交叉验证。

### 9.2 把扩展名当成格式保证

`.csv` 可能含说明行或错误引号，`.txt` 可能是固定宽度表。先看内容。

### 9.3 把重复键一律删掉

重复可能说明粒度比预期更细，例如站点下有多个仪器。先找到重复原因，再决定怎样聚合。

### 9.4 把特殊负数当真实测量

`-99.99`、`-1` 等可能是缺失编码。一定查 codebook 和文件头说明。

### 9.5 清洗时覆盖原始列

覆盖后无法追溯或更换规则。保留原列，创建 `_clean`、`_parsed` 或缺失指示列。

### 9.6 对所有缺失都填均值

均值插补会压缩方差，也不能修复非随机缺失。先判断缺失机制和分析用途。

### 9.7 直接连接不同粒度的表

违规级表直接连接检查级表会重复检查记录。先聚合到共同粒度。

### 9.8 把异常值自动视为错误

空气质量峰值可能是野火，价格极值可能是真实豪宅。异常是调查入口，不是删除命令。

### 9.9 把存储类型当特征类型

整数编码的等级不是定量测量。能求均值不代表均值有含义。

### 9.10 用直方图解释类别变量

类别间没有连续距离，不能谈偏度和尾部。使用条形图并选择有意义的顺序。

### 9.11 只比较均值

组间可能有不同偏度、多峰、尾部和样本量。比较完整分布并报告组大小。

### 9.12 KDE 只看默认带宽

带宽可以制造或抹掉峰。核心形状必须对合理参数具有稳定性。

### 9.13 条形图截断 y 轴

条长编码数值，截断基线会夸大差异。散点图可缩放，条形图通常从 0 开始。

### 9.14 用颜色承担精确比较

颜色适合区分类别或辅助表达数值，不适合替代对齐位置。避免过多颜色和不均匀色板。

### 9.15 把横截面关系解释成个体变化

不同年龄组是不同的人，不能说某个人老去后一定沿曲线移动。

### 9.16 相关高就认为测量一致

两设备可以高度相关却有固定倍数偏差。还要看差值、q-q 图、尺度和绝对误差。

### 10.1 文件层

- 来源和文档是什么？
- 文件多大、什么编码、什么格式？
- 前后几行是否符合预期？
- 读取参数怎样对应观察到的结构？

### 10.2 表格层

- 一行代表什么？
- 候选主键是什么，是否唯一？
- 时间字段是时刻、区间还是聚合值？
- 多张表的粒度是否一致？

### 10.3 质量层

- 值的范围、单位和编码是否合理？
- 相关字段是否一致？
- 缺失在哪里，可能由什么机制产生？
- 重复、异常和未匹配记录意味着什么？
- 清洗前后行数、分布和结论怎样变化？

### 10.4 探索层

- 单变量分布的中心、尺度、峰、偏度和尾部怎样？
- 两变量关系的方向、形式、强度和条件变异怎样？
- 子群中关系是否变化？
- 新发现带来什么下一步问题？

### 10.5 表达层

- 读者需要比较什么？
- 是否使用最准确的视觉通道？
- 尺度、颜色、平滑和排序是否帮助比较？
- 图中是否说明单位、范围、筛选和数据设计？

### 10.6 建模前检查

建模数据应满足：

```text
一行的单位稳定
+ 特征含义明确
+ 缺失和异常处理有记录
+ 训练目标与问题一致
+ 数据来源和范围允许推广
```

模型不会自动修复错误的数据语义。

## 11. 掌握检查与参考答案

### 11.1 概念题

1. 文件格式、数据结构和字符编码分别描述什么？
2. 为什么文件大小不能直接等同于 DataFrame 内存占用？
3. 固定宽度文件为什么离不开 codebook？
4. `NaN` 为什么无法表示整条记录缺失？
5. MCAR、MAR 和 MNAR 的核心区别是什么？
6. 为什么均值插补会低估变异？
7. `.resample("D")` 前要满足什么条件？
8. 为什么违规表不能直接连接到检查表后计算平均分？
9. 特征类型与 `dtype` 有什么区别？
10. 描述定量分布时应检查哪些形状？
11. KDE 带宽过小和过大分别有什么后果？
12. 为什么两个单变量直方图不能说明 X 与 Y 的关系？
13. 两个类别变量为什么常比较条件比例而不是原始计数？
14. 什么是 Simpson 悖论？
15. 哪些图通常必须包含 0？
16. 为什么堆叠图难比较中间类别？
17. q-q 图和配对散点图分别回答什么？
18. 为什么全球经纬网格均值要按纬度加权？
19. 为什么 PurpleAir 必须先转本地时区再计算日均值？
20. 为什么高相关不能证明两种传感器一致？

### 11.2 参考答案

1. 格式说明磁盘字节怎样组织，结构说明数据在概念上怎样组织，编码说明字节怎样映射成字符。
2. 解析会创建数值、字符串对象、索引和临时数据，内存表示通常比压缩文本大。
3. 没有分隔符，只能靠文档确定每个字段的字符位置、编码和允许值。
4. `NaN` 只能存在于已进入表的行中，未被采集的对象根本没有对应行。
5. MCAR 与所有变量无关；MAR 在给定已观测协变量后不依赖缺失值；MNAR 仍与未观测值有关。
6. 所有缺失都被填成相同中心值，使数据人为集中，并扭曲相关和不确定性。
7. 索引必须是正确解析并处理好时区的 `DatetimeIndex`，还要定义窗口完整度要求。
8. 一场检查对应多条违规，直接连接会按违规数重复检查并改变权重；应先聚合到检查粒度。
9. `dtype` 是计算机存储方式，特征类型是变量在现实中的统计含义。
10. 中心、离散、峰、对称/偏斜、尾部、空隙、边界、堆积和异常。
11. 过小会追逐噪声，过大会抹去峰、尾部和局部结构。
12. 单变量图丢失了同一行中 X 与 Y 的配对信息。
13. 组总量不同时，计数混合了组大小与组成；条件比例固定分母后才便于比较。
14. 总体关系在控制某个分组变量后减弱、消失或反向。
15. 条形图和通常的比例图，因为长度或完整范围需要从 0 解释。
16. 中间部分没有共同基线，读者必须比较上下都在移动的长度。
17. q-q 图比较两个边际分布的中心、尺度和尾部；配对散点图显示同一观测上的共同变化。
18. 高纬网格代表的实际面积更小，直接平均会让极区权重过大。
19. UTC 日期边界与 California 本地日期边界不同，直接聚合会把读数分到错误日期。
20. 一个设备若始终读成另一个的两倍，相关仍可接近 1，但偏差和绝对误差很大。

### 11.3 最终掌握标准

学完第三部分后，你应该能做到：

- 面对陌生文件，先检查格式、编码、大小和文档，再选择读取方式；
- 用粒度、主键、时间性和范围解释一张表；
- 设计范围、数值、跨字段和分析用途四类质量检查；
- 根据缺失机制谨慎选择删除、保留或插补；
- 使用时间戳、时区、`resample`、`melt` 和 `.pipe()` 构建可复现清洗流程；
- 根据特征类型选择统计量和图形；
- 系统解释分布、关系和子群差异；
- 调整尺度、平滑、颜色和布局，使比较准确而不误导；
- 识别采样权重、横截面、空间不均和 Simpson 悖论；
- 完整解释 PurpleAir 校准案例中每一步为什么必要。

第三部分的核心不是“把脏数据洗干净”，而是建立一套证据充分、过程透明的理解方法：你知道数据怎样变成现在的样子，也知道结论凭什么值得相信。
