> 这篇文章是 `04-其他数据源-Ch13-14` 的主教材。正文综合了本文件夹中的课本、笔记和讲义，目标是让你不必再逐篇阅读这些理论材料。关键代码会在正文中解释；需要亲手完成的实验和作业集中放在第 15 节。

## 0. 这一部分真正要学会什么

到第三部分为止，我们主要处理已经进入表格的数据。第四部分把视野扩展到两类更常见、也更复杂的数据源：

1. **文本数据**：县名、日志、违规描述、新闻文章和演讲全文；
2. **网络与层级数据**：JSON、HTTP 响应、REST API、HTML、XML 和 NetCDF。

这两章表面上在讲许多工具，底层任务其实只有两个：

> 怎样把不适合直接分析的数据，转换成保留其含义的结构化表示？

以及：

> 怎样以可复现、可检查的方式取得外部数据，并确认自己解析的是正确内容？

完整流程可以压缩为：

```text
确定分析单位
  -> 识别数据的原始结构
  -> 使用与结构匹配的解析器
  -> 规范化或抽取所需信息
  -> 转成表格、特征矩阵或多维数组
  -> 检查数量、类型、范围和语义
  -> 保存来源与转换记录
  -> 再进行探索、可视化或建模
```

本部分最重要的不是记住每一个正则符号或网络函数，而是建立三种判断能力：

- **结构判断**：这是普通字符串、规则日志、树状文档，还是多维数组？
- **工具判断**：应使用字符串方法、正则、JSON/XML 解析器，还是 Xarray？
- **证据判断**：怎样证明下载成功、抽取完整、匹配正确，而且下次还能复现？

## 1. 一张总图：不同数据源需要不同心智模型

### 1.1 文本不是“没有结构”，而是结构强弱不同

可以把文本分成三个层次：

| 文本类型 | 例子 | 合适工具 |
| --- | --- | --- |
| 短字段 | 县名、地址、类别标签 | Python 字符串方法、`Series.str` |
| 半结构化文本 | 日志、日期字符串、产品编号 | 正则表达式 |
| 完整文档 | 新闻、演讲、评论 | 分词、词频、TF-IDF、文本模型 |

县名 `"De Witt County"` 的重点是统一写法；日志的重点是从固定模式中抽取日期和状态码；一篇演讲的重点则是把整个文档转换成可比较的数值向量。

不要因为它们都使用字符串存储，就对它们使用同一种方法。

### 1.2 层级数据应按树理解

JSON、XML 和 HTML 都可以嵌套。它们不是天然的二维表：

```text
根
├── 元数据
└── 数据
    ├── 记录 1
    │   ├── 标量字段
    │   └── 嵌套对象
    └── 记录 2
```

在将它们转成 DataFrame 前，必须先回答：

- 哪个节点对应一行？
- 哪些键对应列？
- 嵌套列表是一对多关系，还是单元格中的一个整体？
- 元数据是否应该单独保存？

### 1.3 多维科学数据应按坐标数组理解

NetCDF 中的温度可能按：

```text
time × latitude × longitude
```

排列。它的自然表示不是把每个经纬度和时间重复写成几亿行，而是：

- 维度定义轴；
- 坐标给出轴上的标签；
- 数据变量保存网格值；
- 属性保存单位、来源和说明。

这就是为什么 NetCDF 通常配合 Xarray，而不是一开始就强行转成 DataFrame。

### 1.4 格式与协议不是一回事

这几个概念很容易混淆：

- **JSON、HTML、XML、NetCDF**：数据怎样组织和存储；
- **HTTP**：客户端与服务器怎样发送请求和响应；
- **REST**：怎样围绕“资源”设计一组 Web 接口；
- **API**：程序可以调用的一组接口约定。

一次 REST API 请求可能使用 HTTP 传输，并在响应体中返回 JSON。四者各自回答不同问题。

## 2. Ch13：文本处理的四类任务

文本分析通常从下面四类任务开始。

### 2.1 规范化：让同一对象拥有同一种写法

两个表中的同一个县可能分别写成：

```text
De Witt County
DeWitt
```

或：

```text
Lewis and Clark County
Lewis & Clark
```

如果直接连接，字符串不同就无法匹配。规范化（canonicalization）要把等价写法映射到共同表示。

```python
def canonicalize_county(name):
    return (
        name.lower()
            .replace("county", "")
            .replace("parish", "")
            .replace("&", "and")
            .replace(".", "")
            .replace(" ", "")
            .strip()
    )
```

这段代码的逻辑顺序是：

1. 统一大小写；
2. 删除不稳定但不影响实体身份的后缀；
3. 统一缩写；
4. 删除标点和空格。

规范化后的字符串适合做连接键，但不应覆盖原始列：

```python
counties = counties.assign(
    county_key=counties["County"].map(canonicalize_county)
)
```

保留原始列有两个原因：

- 发现误匹配时可以追溯；
- 规范化可能损失真实差异。

例如，把所有空格删除通常适合县名匹配，却不适合清洗文章正文。

### 2.2 抽取：从一段文本中拿出结构化字段

Web 日志可能长成这样：

```text
169.237.46.168 - - [26/Jan/2004:10:47:58 -0800]
"GET /stat141/Winter04 HTTP/1.1" 301 328
```

这里至少包含：

- IP 地址；
- 日、月、年；
- 时、分、秒；
- 时区；
- HTTP 方法和路径；
- 状态码；
- 响应大小。

抽取不是删除无用字符，而是将一条字符串转换成多列。

### 2.3 特征化：把文本含义变成变量

餐厅违规描述可以转换成布尔或计数特征：

```python
features = violations.assign(
    is_unclean=violations["clean_desc"].str.contains(
        r"clean|sanit", na=False
    ),
    is_vermin=violations["clean_desc"].str.contains(
        r"\bvermin\b", na=False
    ),
    is_surface=violations["clean_desc"].str.contains(
        r"wall|ceiling|floor|surface", na=False
    ),
    is_human=violations["clean_desc"].str.contains(
        r"hand|glove|hair|nail", na=False
    ),
)
```

每个新变量都对应一个分析定义。“出现 `hand` 等词”不等于“违规一定由员工造成”，它只是一个可计算代理变量。变量名和解释都不应超出规则本身。

### 2.4 文档分析：把整篇文章变成向量

对新闻和演讲，逐个关键词有时不够。我们会把每篇文档转换成一个高维向量，再比较：

- 哪些词更能区分文档；
- 文档之间是否相似；
- 语言是否随时间变化；
- 是否形成主题或时期聚类。

这条链路是：

```text
原文
  -> 清洗
  -> 分词
  -> 词形处理
  -> 文档-词项矩阵
  -> TF-IDF
  -> 相似度、降维或模型
```

## 3. 字符串方法：先用最简单、最明确的工具

### 3.1 Python 字符串与 pandas 字符串列

单个字符串使用 Python 方法：

```python
name = "  De Witt County "

name.lower()
name.strip()
name.replace("County", "")
name.split()
name[2:8]
```

整列字符串使用 pandas 的 `.str` 访问器：

```python
df["county_key"] = (
    df["County"]
      .str.lower()
      .str.replace("county", "", regex=False)
      .str.replace("parish", "", regex=False)
      .str.replace("&", "and", regex=False)
      .str.replace(".", "", regex=False)
      .str.replace(" ", "", regex=False)
      .str.strip()
)
```

`Series.str.lower()` 的含义是：对 Series 中每个非缺失字符串调用 `lower()`，并返回一个新的 Series。

### 3.2 `regex=False` 为什么值得显式写

在 `str.replace()` 中，模式有时按普通文本处理，有时按正则处理。若只是替换字面量，显式写：

```python
s.str.replace(".", "", regex=False)
```

表达了“删除真正的句点”。如果 `.` 被当作正则，它表示几乎任意单个字符，结果会完全不同。

原则是：

> 字面替换使用 `regex=False`；需要描述模式时才使用 `regex=True`。

### 3.3 缺失值要单独考虑

字符串列中可能存在 `NaN`：

```python
df["text"].str.lower()
df["text"].str.contains("error", na=False)
```

多数 `.str` 方法会传播缺失值；`str.contains()` 若用于布尔筛选，最好明确 `na=False`：

```python
errors = df.loc[df["message"].str.contains("error", case=False, na=False)]
```

否则结果中可能含 `NaN`，无法直接作为完整布尔掩码。

### 3.4 连接时不要只依赖规范化结果

县名案例必须同时按规范化县名和州连接：

```python
merged = election.merge(
    census,
    on=["county_key", "State"],
    how="left",
    validate="one_to_one",
    indicator=True,
)
```

原因是不同州可能存在同名县。这里的几个参数都很重要：

- `how="left"`：保留选举表全部记录；
- `validate="one_to_one"`：若键不是一对一，立刻报错；
- `indicator=True`：用 `_merge` 检查哪些行未匹配。

```python
merged["_merge"].value_counts()
merged.loc[merged["_merge"] != "both"]
```

规范化只是提高可连接性，不能替代连接后的质量检查。

### 3.5 什么时候 `split()` 足够

如果分隔符固定且结构简单，优先使用 `split()`：

```python
date = "26/Jan/2004"
day, month, year = date.split("/")
```

pandas 中可以直接展开：

```python
parts = (
    df["date_text"]
      .str.split("/", expand=True)
      .set_axis(["day", "month", "year"], axis="columns")
)
```

当分隔符不统一、字段可选或需要验证整体格式时，正则更合适。

## 4. 正则表达式：描述字符模式的语言

### 4.1 正则的核心心智模型

正则引擎通常从字符串左侧开始，在每个可能位置尝试匹配完整模式：

```text
模式：cat
文本：cards scatter
```

它先尝试第一个 `c`，后续不匹配便继续向右移动，最终在 `scatter` 中找到 `cat`。

这解释了一个关键事实：

> 正则搜索默认可以匹配字符串中的一部分，不代表整个字符串都符合格式。

若要验证整个字段，应使用锚点或 `fullmatch()`。

### 4.2 原始字符串 `r"..."` 

反斜杠在 Python 字符串和正则中都有特殊含义。正则模式通常写成原始字符串：

```python
pattern = r"\d{3}-\d{2}-\d{4}"
```

这样 `\d` 会原样交给正则引擎，不必写成 `"\\d"`。

原始字符串不等于“忽略一切转义”，但对绝大多数正则模式更清楚。

### 4.3 字面量、字符类与通配符

最基础的元素如下：

| 模式 | 含义 | 示例匹配 |
| --- | --- | --- |
| `cat` | 连续字面量 | `cat` |
| `[abc]` | `a`、`b`、`c` 中任意一个 | `a` |
| `[a-z]` | 一个小写字母 | `m` |
| `[0-9]` 或 `\d` | 一个数字 | `7` |
| `[^0-9]` | 一个非数字字符 | `A` |
| `.` | 除换行外任意字符 | `?` |
| `\s` | 空白字符 | 空格、制表符 |
| `\w` | 字母、数字或下划线 | `a`、`8`、`_` |

例如：

```python
r"c[oa][td]"
```

可以匹配 `cat`、`cot`、`cad` 和 `cod`。

`.` 很强，但也很危险：

```python
r"[0-9].+[0-9]"
```

会从第一个数字一直贪婪地匹配到最后一个数字，常常比预期长。能写具体字符类时，不要滥用 `.`。

### 4.4 数量词只修饰左边紧邻的元素

| 数量词 | 含义 |
| --- | --- |
| `{m}` | 恰好 m 次 |
| `{m,n}` | m 到 n 次 |
| `{m,}` | 至少 m 次 |
| `*` | 0 次或更多 |
| `+` | 1 次或更多 |
| `?` | 0 次或 1 次 |

社会保障号可写成：

```python
ssn_pattern = r"\d{3}-\d{2}-\d{4}"
```

注意：

```text
ab+   表示 a 后面有一个或多个 b
(ab)+ 表示 ab 这个整体重复一次或多次
```

括号改变数量词作用范围。

### 4.5 锚点与边界

| 模式 | 含义 |
| --- | --- |
| `^` | 字符串或行开头 |
| `$` | 字符串或行结尾 |
| `\b` | 单词边界 |

搜索文本中的完整 SSN：

```python
r"\b\d{3}-\d{2}-\d{4}\b"
```

验证整个字段：

```python
valid = df["ssn"].str.fullmatch(r"\d{3}-\d{2}-\d{4}", na=False)
```

区别是：

- `contains` / `search`：某处出现即可；
- `match`：从开头匹配，但不要求到结尾；
- `fullmatch`：整个字符串必须符合模式。

不要用 `contains()` 完成严格格式验证。

### 4.6 转义元字符

若要匹配元字符本身，需要反斜杠：

```python
r"\["   # 字面量 [
r"\."   # 字面量 .
r"\$"   # 字面量 $
```

例如匹配方括号中的内容：

```python
r"\[[^\]]+\]"
```

逐段解释：

1. `\[`：左方括号；
2. `[^\]]+`：一个或多个“不是右方括号”的字符；
3. `\]`：右方括号。

这个写法比 `r"\[.*\]"` 更稳，因为它会在遇到第一个右括号时停止。

### 4.7 贪婪与懒惰

数量词默认贪婪，会尽量匹配更长内容：

```python
text = '"first" and "second"'
re.findall(r'".*"', text)
# ['"first" and "second"']
```

加 `?` 变成懒惰匹配：

```python
re.findall(r'".*?"', text)
# ['"first"', '"second"']
```

更好的做法通常是限制允许字符：

```python
re.findall(r'"[^"]*"', text)
```

它明确表示引号内部不能再出现引号，比依赖贪婪模式更容易推理。

### 4.8 选择与分组

竖线表示“或”：

```python
r"hand|nail|hair|glove"
```

括号有两种常见用途：

1. 把元素组合成整体：`r"(cat|dog)s?"`；
2. 抽取捕获组：`r"(\d{2})/([A-Za-z]{3})/(\d{4})"`。

若只想分组、不想捕获，使用非捕获组：

```python
r"(?:cat|dog)s?"
```

这可以避免 `findall()` 因捕获组而改变返回结构。

### 4.9 操作优先级

从高到低可以记成：

```text
分组 () > 数量词 * + ? {} > 拼接 > 选择 |
```

例如：

```python
r"cat|dogs"
```

表示 `cat` 或 `dogs`；若要表示 `cat` 或 `dog` 后面都可有 `s`，应写：

```python
r"(?:cat|dog)s?"
```

## 5. Python 与 pandas 中的正则操作

### 5.1 `re` 模块的核心函数

```python
import re

re.search(pattern, text)       # 任意位置第一个匹配
re.fullmatch(pattern, text)    # 整个字符串匹配
re.findall(pattern, text)      # 所有匹配
re.finditer(pattern, text)     # 逐个返回 Match 对象
re.sub(pattern, repl, text)    # 替换
re.split(pattern, text)        # 按模式切分
```

开发复杂模式时，先编译并写测试样本：

```python
log_pattern = re.compile(
    r"\[(?P<day>\d{2})/"
    r"(?P<month>[A-Za-z]{3})/"
    r"(?P<year>\d{4}):"
    r"(?P<hour>\d{2}):"
    r"(?P<minute>\d{2}):"
    r"(?P<second>\d{2}) "
    r"(?P<timezone>[+-]\d{4})\]"
)

match = log_pattern.search(log_entry)
match.groupdict()
```

命名捕获组 `(?P<name>...)` 比依赖“第 5 个括号是什么”更易维护。

### 5.2 pandas 的五个高频方法

#### 判断是否包含：`str.contains`

```python
mask = df["description"].str.contains(
    r"\b(error|failed|timeout)\b",
    case=False,
    na=False,
)
```

捕获组在这里只用于逻辑分组时，最好写成非捕获组，避免警告：

```python
r"\b(?:error|failed|timeout)\b"
```

#### 判断整体格式：`str.fullmatch`

```python
valid_code = df["code"].str.fullmatch(r"[A-Z]{2}-\d{4}", na=False)
```

#### 抽取第一个匹配：`str.extract`

```python
parts = df["log"].str.extract(
    r"\[(?P<day>\d{2})/"
    r"(?P<month>[A-Za-z]{3})/"
    r"(?P<year>\d{4}):"
    r"(?P<time>\d{2}:\d{2}:\d{2}) "
    r"(?P<timezone>[+-]\d{4})\]"
)
```

结果是一张与原索引对齐的 DataFrame；未匹配行填 `NaN`。

#### 抽取全部匹配：`str.extractall`

```python
all_ssns = df["text"].str.extractall(
    r"(?P<area>\d{3})-(?P<group>\d{2})-(?P<serial>\d{4})"
)
```

一个原始字符串可产生多行，因此返回 MultiIndex，其中额外的 `match` 层表示第几个匹配。

#### 替换与清洗：`str.replace`

```python
clean = (
    df["description"]
      .str.replace(r"\s*\[.*?\]\s*$", "", regex=True)
      .str.strip()
      .str.lower()
)
```

### 5.3 `findall`、`extract` 和 `extractall` 的区别

| 方法 | 每个字符串可返回几个匹配 | 典型结果 |
| --- | --- | --- |
| `str.findall` | 全部 | 每格一个列表 |
| `str.extract` | 第一个 | 每个捕获组一列 |
| `str.extractall` | 全部 | 每个匹配一行 |

选择方法前，先决定目标粒度：

- 一行仍代表原文档：`findall` 或 `extract`；
- 一行要代表一次匹配：`extractall`。

### 5.4 日志抽取的完整实现

```python
pattern = (
    r"\[(?P<day>\d{2})/"
    r"(?P<month>[A-Za-z]{3})/"
    r"(?P<year>\d{4}):"
    r"(?P<hour>\d{2}):"
    r"(?P<minute>\d{2}):"
    r"(?P<second>\d{2}) "
    r"(?P<timezone>[+-]\d{4})\]"
)

parts = logs["raw"].str.extract(pattern)

parts["timestamp_text"] = (
    parts["day"] + "/" + parts["month"] + "/" + parts["year"]
    + " " + parts["hour"] + ":" + parts["minute"] + ":" + parts["second"]
    + " " + parts["timezone"]
)

parts["timestamp"] = pd.to_datetime(
    parts["timestamp_text"],
    format="%d/%b/%Y %H:%M:%S %z",
    errors="coerce",
    utc=True,
)
```

代码没有在抽取后直接相信结果，而是将字段重组并交给日期解析器验证。

```python
match_rate = parts["timestamp"].notna().mean()
bad_rows = logs.loc[parts["timestamp"].isna(), "raw"]
```

应同时报告匹配率并查看未匹配样本。正则只会忠实执行模式，不会提醒你漏掉了新格式。

### 5.5 正则测试不能只放一个成功案例

至少准备四类测试：

```python
tests = pd.Series({
    "normal": "[26/Jan/2004:10:47:58 -0800]",
    "boundary": "[01/May/2024:00:00:00 +0000]",
    "malformed": "[1/May/2024 00:00]",
    "extra_text": "prefix [26/Jan/2004:10:47:58 -0800] suffix",
})
```

然后明确预期：

- 哪些应该匹配？
- 哪些不应该匹配？
- 是允许子串匹配，还是要求完整字段匹配？

### 5.6 正则不适合做什么

不要使用正则：

- 解析任意嵌套的 JSON、HTML 或 XML；
- 判断平衡括号等递归结构；
- 完整验证电子邮箱、URL 等复杂标准；
- 替代现成日期、URL、HTML 解析器。

正则擅长局部、相对稳定的字符模式。层级结构应交给结构化解析器。

## 6. 从文本字段到可分析特征

### 6.1 清洗描述时要区分“格式噪声”和“内容”

餐厅违规描述可能在结尾附带方括号备注：

```python
violations["clean_desc"] = (
    violations["desc"]
      .str.replace(r"\s*\[.*?\]\s*$", "", regex=True)
      .str.strip()
      .str.lower()
)
```

这里使用 `$` 限制只删除结尾备注，避免把正文中间的方括号内容一并删掉。

清洗前后应比较：

```python
before = violations["desc"].nunique(dropna=False)
after = violations["clean_desc"].nunique(dropna=False)

print(before, after)
violations[["desc", "clean_desc"]].sample(10, random_state=42)
```

唯一值减少是预期现象，但仍要抽样确认不同含义没有被错误合并。

### 6.2 布尔特征与计数特征回答不同问题

每条违规记录上的布尔变量：

```python
violations["is_vermin"] = violations["clean_desc"].str.contains(
    r"\bvermin\b", na=False
)
```

聚合到检查粒度后变成计数：

```python
inspection_features = (
    violations
      .groupby(["business_id", "date"], as_index=False)
      [["is_vermin", "is_unclean", "is_surface", "is_human"]]
      .sum()
)
```

此时：

- 原始一行：一项违规；
- 聚合后一行：一次检查；
- 特征值：该次检查中某类违规出现次数。

如果目标是“是否至少出现过”，应转回布尔：

```python
inspection_features["has_vermin"] = (
    inspection_features["is_vermin"] > 0
)
```

### 6.3 关键词规则存在假阳性和假阴性

规则：

```python
r"clean|sanit"
```

可能匹配 `unclean`、`cleaned`、`sanitary`，也可能漏掉同义表达。评估规则不能只看命中数量，要人工标注一小批样本：

```python
sample = violations.sample(100, random_state=42)
sample[["clean_desc", "is_unclean"]]
```

然后计算或至少观察：

- **精确率**：命中的记录中有多少真的属于该类；
- **召回率**：真正属于该类的记录中有多少被规则找到。

规则特征不是客观真相，而是可审查、可改进的测量工具。

## 7. 文档分析：从词语到数值向量

### 7.1 三个基本单位

- **语料库（corpus）**：全部文档；
- **文档（document）**：分析的一条文本单位；
- **词项（term/token）**：切分后的基本文本单位。

在国情咨文案例中：

- 语料库是 1790-2022 年全部演讲；
- 一篇演讲是一份文档；
- 处理后的单词是词项。

粒度仍然是第一问题。若一行从“文章”改成“段落”，TF-IDF 和相似度的含义都会改变。

### 7.2 文档清洗

```python
def clean_text(df):
    bracket_re = r"\[[^\]]+\]"
    not_word_re = r"[^a-z\s]"

    cleaned = (
        df["text"]
          .str.lower()
          .str.replace(bracket_re, "", regex=True)
          .str.replace(not_word_re, " ", regex=True)
          .str.replace(r"\s+", " ", regex=True)
          .str.strip()
    )
    return df.assign(clean_text=cleaned)
```

每一步都有具体语义：

1. 大小写统一；
2. 删除 `[laughter]` 等非演讲内容；
3. 只保留字母与空白；
4. 合并连续空白。

这些选择依赖问题。若研究演讲中的数字使用，就不能删除数字；若研究现场反应，`[laughter]` 反而是重要信息。

### 7.3 停用词、词干与词形还原

**停用词（stop words）** 是出现频繁但区分作用较弱的词，如英文中的 `the`、`and`。

**词干提取（stemming）** 用规则截断词形：

```text
argue, arguing -> argu
```

它速度快，但结果未必是合法单词。

**词形还原（lemmatization）** 尝试还原词典基本形式，通常更自然，但需要更多语言信息和计算。

这些处理都不是必需步骤。现代预训练语言模型通常有自己的 tokenizer，不应先按传统规则过度清洗。

### 7.4 Bag-of-Words 的表示

假设有三个文档：

```text
D1: data science
D2: data analysis
D3: science analysis
```

词表为：

```text
[data, science, analysis]
```

词频矩阵为：

| 文档 | data | science | analysis |
| --- | ---: | ---: | ---: |
| D1 | 1 | 1 | 0 |
| D2 | 1 | 0 | 1 |
| D3 | 0 | 1 | 1 |

Bag-of-Words 忽略词序，只保留出现次数。它简单、可解释，但无法区分：

```text
dog bites man
man bites dog
```

### 7.5 为什么文本矩阵是稀疏的

真实语料可能有数万词项，但一篇文档只使用其中很少一部分，所以矩阵绝大多数元素为 0。

```python
X.shape
X.nnz
density = X.nnz / (X.shape[0] * X.shape[1])
```

`scikit-learn` 默认使用稀疏矩阵。不要轻易调用：

```python
X.toarray()
```

在大语料上，这可能瞬间耗尽内存。

### 7.6 TF-IDF 的逻辑

单纯词频会让到处出现的常用词占据很大权重。TF-IDF 同时考虑：

1. 某词在当前文档中出现多少；
2. 该词在整个语料中有多罕见。

常见形式为：

$$
\operatorname{tfidf}(t,d)
=\operatorname{tf}(t,d)
\times
\log\left(\frac{N}{\operatorname{df}(t)}\right)
$$

其中：

- $t$ 是词项；
- $d$ 是文档；
- $N$ 是文档数；
- $\operatorname{df}(t)$ 是包含该词的文档数。

若一个词出现在几乎所有文档中，IDF 很小；若只在少数文档出现，它更有区分力。

实际库会使用平滑、归一化等变体，因此手算值可能和软件略有不同，但逻辑一致。

### 7.7 用 `TfidfVectorizer` 建立特征矩阵

```python
from sklearn.feature_extraction.text import TfidfVectorizer

vectorizer = TfidfVectorizer(
    lowercase=True,
    stop_words="english",
    min_df=2,
    max_df=0.95,
    ngram_range=(1, 2),
)

X = vectorizer.fit_transform(documents)
terms = vectorizer.get_feature_names_out()
```

参数含义：

- `min_df=2`：忽略只在一篇文档出现的极罕见词；
- `max_df=0.95`：忽略出现在 95% 以上文档中的词；
- `ngram_range=(1, 2)`：同时使用单词和相邻双词组。

不要在划分训练集前对全部数据 `fit_transform()`。建模时应：

```python
X_train = vectorizer.fit_transform(train_text)
X_test = vectorizer.transform(test_text)
```

否则测试集词频信息会泄漏到特征构造中。

### 7.8 文档相似度

TF-IDF 向量常用余弦相似度：

$$
\cos(\theta)
=\frac{\mathbf{x}\cdot\mathbf{y}}
{\|\mathbf{x}\|\|\mathbf{y}\|}
$$

```python
from sklearn.metrics.pairwise import cosine_similarity

similarity = cosine_similarity(X)
```

它关注向量方向，而不是文档总长度。值越接近 1，词项权重模式越相似。

但“词相似”不等于“立场相同”或“事实相同”。否定、讽刺和词序都可能被简单 Bag-of-Words 忽略。

### 7.9 PCA/SVD 用于观察文档结构

国情咨文案例将 232 篇演讲转换成约 1.3 万维 TF-IDF 向量，再降到二维观察。

稀疏文本矩阵通常使用 `TruncatedSVD`：

```python
from sklearn.decomposition import TruncatedSVD

svd = TruncatedSVD(n_components=2, random_state=42)
pcs = svd.fit_transform(X)

plot_df = speeches.assign(
    pc1=pcs[:, 0],
    pc2=pcs[:, 1],
)
```

二维图中距离近表示在当前文本表示和降维下较相似。必须加限定：

- 二维只保留部分信息；
- 主成分正负方向可以整体翻转；
- 聚类可能由年代、长度、格式差异或特定词汇驱动；
- 图形是探索证据，不是因果结论。

### 7.10 国情咨文案例的完整逻辑

```text
用 *** 分隔演讲
  -> 提取总统、日期、正文
  -> 删除舞台说明和非字母符号
  -> 去停用词并做词干处理
  -> 构建 TF-IDF 稀疏矩阵
  -> 用低维表示观察文档差异
  -> 按年份着色解释时期变化
```

主要发现是较早与较晚时期的演讲用词存在明显差异，同一时期演讲也更容易聚在一起。

正确解释应是：

> 在当前清洗、TF-IDF 和降维方法下，演讲的词汇使用呈现明显时间结构。

不能直接说：

> 年代导致演讲内容变化，或相邻点表达了相同政治立场。

### 7.11 情感模型输出不是情绪真值

作业中使用预训练模型：

```python
from transformers import pipeline

sentiment_model = pipeline(
    "sentiment-analysis",
    model="distilbert/distilbert-base-uncased-finetuned-sst-2-english",
)

sentiment_model([
    "I have two dogs.",
    "Fortunately, I do not have dogs to worry about.",
])
```

输出中的 `label` 和 `score` 表示模型在自身标签体系下的预测及置信程度，不是客观情绪量。

将模型返回的字典列表先转成表，再构造带符号分数：

```python
sentiment = pd.DataFrame(results)
sentiment["signed_score"] = np.where(
    sentiment["label"].eq("POSITIVE"),
    sentiment["score"],
    -sentiment["score"],
)
```

仍需注意：

- 模型训练域与新闻文本可能不同；
- 高置信度不保证正确；
- 否定、讽刺、引用和复杂立场很难处理；
- 主题词筛选会改变进入分析的文章集合；
- 媒体“偏见”不能由平均情感分数单独证明。

文本模型的输出应视为新的测量变量，也要做误差和偏差检查。

## 8. Ch14：数据交换先判断结构，再选择解析器

### 8.1 为什么不能把所有数据都当 CSV

CSV 适合规则二维表，但其他数据结构有不同需求：

| 格式 | 主要结构 | 优点 | 常用工具 |
| --- | --- | --- | --- |
| JSON | 对象与数组嵌套 | 灵活、Web 常用 | `json`、`pd.json_normalize` |
| XML | 带标签和属性的树 | 严格、可扩展、支持命名空间 | `lxml.etree` |
| HTML | 描述网页内容的树 | 页面中可能包含表格和文本 | `lxml.html`、`pd.read_html` |
| NetCDF | 带坐标的多维数组 | 紧凑、自描述、适合科学数据 | `xarray` |
| CSV | 二维表 | 简单、通用、人可读 | `pd.read_csv` |

选择格式时问：

- 数据是否天然二维？
- 是否需要嵌套关系？
- 是否需要保存坐标、单位和来源元数据？
- 数据规模有多大？
- 是供人阅读，还是供程序高效访问？

“能否读进 DataFrame”不是唯一标准。过早展平可能丢失层级或多维语义。

### 8.2 一条可靠的数据取得链

无论数据来自网页还是 API，都应分成四层：

```text
传输层：请求是否到达、响应状态是什么
格式层：响应体到底是 JSON、HTML、XML 还是二进制
结构层：记录、字段、嵌套和坐标怎样组织
语义层：单位、粒度、时间范围和来源是否符合问题
```

典型错误是跳过前三层，直接写：

```python
pd.DataFrame(requests.get(url).json())
```

代码可能运行，但你尚未确认：

- 请求是否超时或被重定向；
- 返回的是成功数据还是 JSON 格式的错误消息；
- 真正记录是否藏在 `data` / `results` / `items` 中；
- 是否只拿到了第一页；
- 字段含义和单位是否正确。

## 9. JSON：对象和数组组成的层级数据

### 9.1 JSON 与 Python 对象的对应

JSON 有两个复合结构：

- **object**：名称和值组成的集合，对应 Python `dict`；
- **array**：有顺序的值序列，对应 Python `list`。

基本类型对应如下：

| JSON | Python |
| --- | --- |
| object | `dict` |
| array | `list` |
| string | `str` |
| number | `int` / `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

JSON 要求键和字符串使用双引号；它不是 Python 字典的文本写法。

```json
{
  "lender_id": "matt",
  "loan_count": 23,
  "status": [2, 1, 3],
  "sponsored": false,
  "sponsor_name": null,
  "lender_dem": {
    "sex": "m",
    "age": 77
  }
}
```

### 9.2 `load`、`loads` 与响应的 `.json()`

读取文件对象：

```python
import json

with open("data.json", encoding="utf-8") as f:
    payload = json.load(f)
```

解析已经在内存中的 JSON 字符串：

```python
payload = json.loads(json_text)
```

解析 HTTP 响应体：

```python
response = requests.get(url, timeout=30)
response.raise_for_status()
payload = response.json()
```

记忆方法：

- `load`：从文件流加载；
- `loads`：从 string 加载；
- `response.json()`：由 `requests` 解码响应。

### 9.3 先查看顶层结构

```python
type(payload)
```

若是字典：

```python
payload.keys()
```

若是列表：

```python
len(payload)
payload[0]
```

若响应很大，不要在 notebook 中打印全部内容。只看：

```python
print(type(payload))
print(list(payload)[:10] if isinstance(payload, dict) else len(payload))
```

### 9.4 三种常见表格组织方式

#### 按行组织：records

```json
{
  "Data": [
    {"site": "0014", "date": "02-27", "aqi": 30},
    {"site": "0014", "date": "02-24", "aqi": 17}
  ]
}
```

转换：

```python
df = pd.DataFrame(payload["Data"])
```

#### 按列组织：columns

```json
{
  "site": ["0014", "0014"],
  "date": ["02-27", "02-24"],
  "aqi": [30, 17]
}
```

转换：

```python
df = pd.DataFrame(payload)
```

某些这类文件可以直接：

```python
df = pd.read_json("data.json")
```

#### 矩阵加列名

```json
{
  "vars": ["site", "date", "aqi"],
  "data": [
    ["0014", "02-27", 30],
    ["0014", "02-24", 17]
  ]
}
```

转换：

```python
df = pd.DataFrame(payload["data"], columns=payload["vars"])
```

同样是 JSON，读取代码不同。必须先理解结构。

### 9.5 展平嵌套对象

```python
flat = pd.json_normalize(payload)
```

例如嵌套对象：

```json
{"lender_dem": {"sex": "m", "age": 77}}
```

会展开为：

```text
lender_dem.sex
lender_dem.age
```

若记录藏在嵌套列表中：

```python
df = pd.json_normalize(
    payload,
    record_path=["response", "items"],
    meta=[["response", "request_id"]],
    errors="ignore",
)
```

`record_path` 指明“哪个数组的每个元素是一行”，`meta` 把上层信息复制到每条记录。

### 9.6 展平不是越彻底越好

若一篇文章有多个作者，把作者列表保存在一个单元格中，粒度仍是文章；如果展开作者列表，一篇文章会变成多行，粒度改成“文章-作者”。

因此在 `explode()` 前必须说明目标粒度：

```python
article_author = articles.explode("authors", ignore_index=True)
```

检查：

```python
len(article_author)
article_author["article_id"].value_counts().head()
```

JSON 转表的难点不是语法，而是决定怎样把层级映射到行和列。

### 9.7 JSON 读取后的最低检查

```python
assert payload["Header"][0]["status"] == "Success"
assert payload["Header"][0]["rows"] == len(df)

df.info()
df.head()
df.isna().mean()
```

尤其要保存：

- 请求时间；
- 请求 URL 和参数；
- API 返回的行数；
- 页码或游标；
- 数据版本。

## 10. HTTP：理解请求与响应

### 10.1 HTTP 的心智模型

HTTP 是请求-响应协议：

```text
客户端 -- request --> 服务器
客户端 <-- response -- 服务器
```

客户端可以是浏览器，也可以是 Python 程序。

请求包含：

- 方法：GET、POST 等；
- URL；
- headers；
- 可选的查询参数或 body。

响应包含：

- 状态码；
- headers；
- body。

### 10.2 GET 和 POST 的区别

**GET** 主要用于取得资源：

```python
response = requests.get(
    "https://api.example.com/measurements",
    params={"station": "0014", "year": 2024},
    timeout=30,
)
```

`params` 会编码进 URL 查询字符串。

**POST** 常用于提交数据、创建资源或交换认证信息：

```python
response = requests.post(
    "https://api.example.com/token",
    data={
        "grant_type": "client_credentials",
        "client_id": client_id,
        "client_secret": client_secret,
    },
    timeout=30,
)
```

若接口要求 JSON body：

```python
response = requests.post(
    url,
    json={"name": "sample", "value": 42},
    timeout=30,
)
```

`data=` 和 `json=` 不是一回事，要服从 API 文档。

### 10.3 状态码先按类别理解

| 范围 | 含义 | 例子 |
| --- | --- | --- |
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | 200 OK、201 Created |
| 3xx | 重定向 | 301 Moved Permanently |
| 4xx | 客户端错误 | 400、401、403、404、429 |
| 5xx | 服务端错误 | 500、503 |

几个高频状态码：

- `200`：请求成功；
- `201`：资源创建成功；
- `204`：成功但没有响应体；
- `400`：请求格式或参数有误；
- `401`：未认证或令牌过期；
- `403`：已识别但无权限；
- `404`：资源不存在；
- `429`：请求过于频繁；
- `500/503`：服务端故障或暂不可用。

不要只写：

```python
response = requests.get(url)
data = response.json()
```

应先：

```python
response.raise_for_status()
```

### 10.4 一个稳健的 GET 模板

```python
import requests

def get_json(url, *, params=None, headers=None, timeout=30):
    response = requests.get(
        url,
        params=params,
        headers=headers,
        timeout=timeout,
    )
    response.raise_for_status()

    content_type = response.headers.get("content-type", "").lower()
    if "json" not in content_type:
        preview = response.text[:200]
        raise ValueError(
            f"Expected JSON, got {content_type!r}: {preview!r}"
        )

    return response.json()
```

这段代码同时检查：

- 请求有超时，不会无限等待；
- 非成功状态码会报错；
- 响应格式符合预期；
- 格式错误时保留一小段内容帮助调试。

`200` 只表示 HTTP 层成功，不保证业务层成功。有些 API 会返回：

```json
{"status": "error", "message": "invalid station"}
```

所以还要检查响应内部状态字段。

### 10.5 请求头和响应头

请求头可携带认证、内容协商和客户端信息：

```python
headers = {
    "Authorization": f"Bearer {access_token}",
    "Accept": "application/json",
    "User-Agent": "data100-learning/1.0",
}
```

响应头可以告诉你：

```python
response.headers.get("content-type")
response.headers.get("content-length")
response.headers.get("last-modified")
response.headers.get("retry-after")
```

解析 body 前，先确认 `content-type`。请求 JSON 接口却收到 HTML，常见原因是登录页、错误页或反爬页面。

### 10.6 超时、重试与可恢复错误

网络请求可能因临时故障失败。适合重试的通常是：

- 连接超时；
- `429 Too Many Requests`；
- 部分 `5xx` 服务端错误。

不应盲目重试：

- `400` 参数错误；
- `401` 认证失败；
- `403` 权限不足；
- `404` 资源不存在。

可使用 `Session` 和重试策略：

```python
from requests import Session
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(
    total=3,
    backoff_factor=1,
    status_forcelist=[429, 500, 502, 503, 504],
    allowed_methods=["GET"],
)

session = Session()
session.mount("https://", HTTPAdapter(max_retries=retry))

response = session.get(url, params=params, timeout=30)
response.raise_for_status()
```

对会产生副作用的 POST 请求，不要在不了解接口幂等性时自动重试。

### 10.7 分页：成功响应可能只有第一部分

API 常用：

- `page` / `per_page`；
- `offset` / `limit`；
- `next` URL；
- cursor 游标。

页码示例：

```python
records = []
page = 1

while True:
    payload = get_json(
        url,
        params={"page": page, "per_page": 100},
    )
    batch = payload["items"]
    records.extend(batch)

    if not payload.get("next"):
        break
    page += 1

df = pd.DataFrame(records)
```

最后验证：

```python
assert len(df) == payload["total"]
```

若 API 没提供总数，至少记录页数、每页数量和结束条件。

### 10.8 保存原始响应与数据来源

可复现取得数据不等于每次运行都重新打 API。更稳妥的是：

```python
from pathlib import Path
import json

raw_path = Path("data/raw/response.json")
raw_path.parent.mkdir(parents=True, exist_ok=True)
raw_path.write_text(
    json.dumps(payload, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
```

同时记录：

```python
metadata = {
    "source_url": response.url,
    "retrieved_at_utc": pd.Timestamp.now(tz="UTC").isoformat(),
    "status_code": response.status_code,
    "content_type": response.headers.get("content-type"),
}
```

这样可以把“获取原始数据”和“解析分析数据”分开，调试时不必反复请求。

## 11. REST API：把网络资源当作可寻址对象

### 11.1 REST 的核心思想

REST 风格接口通常让 URL 对应资源：

```text
/artists/{artist_id}
/artists/{artist_id}/albums
/albums/{album_id}/tracks
```

它是无状态的：服务器不依赖上一次请求来理解本次请求。每次请求都应携带必要信息，例如访问令牌和参数。

REST 不是“返回 JSON”的同义词。REST 描述接口组织方式，响应格式可以是 JSON、XML 或其他格式。

### 11.2 认证与取资源是两个阶段

Spotify 案例的流程是：

```text
client_id + client_secret
  -> POST 认证端点
  -> access token
  -> GET artist albums
  -> GET each album's tracks
  -> 解析 JSON
  -> 合并成 DataFrame
```

认证示例：

```python
import os
import requests

client_id = os.environ["SPOTIFY_CLIENT_ID"]
client_secret = os.environ["SPOTIFY_CLIENT_SECRET"]

auth = requests.post(
    "https://accounts.spotify.com/api/token",
    data={"grant_type": "client_credentials"},
    auth=(client_id, client_secret),
    timeout=30,
)
auth.raise_for_status()

token = auth.json()["access_token"]
```

不要把密钥直接写进 notebook、截图或 Git 仓库。使用环境变量或专用密钥管理工具。

### 11.3 携带令牌请求资源

```python
headers = {"Authorization": f"Bearer {token}"}

response = requests.get(
    f"https://api.spotify.com/v1/artists/{artist_id}/albums",
    headers=headers,
    params={"include_groups": "album", "limit": 50},
    timeout=30,
)
response.raise_for_status()

albums_payload = response.json()
albums = albums_payload["items"]
```

解析前检查：

```python
albums_payload.keys()
len(albums)
albums[0].keys()
```

### 11.4 嵌套请求会产生性能问题

下面的模式很直观：

```python
for album in albums:
    tracks = get_tracks(album["id"])
    for track in tracks:
        features = get_features(track["id"])
```

但它会产生：

```text
1 次专辑请求
+ A 次曲目请求
+ T 次特征请求
```

这叫 N+1 风格请求问题。应优先检查 API 是否提供：

- 批量端点；
- 一次请求多个 ID；
- 分页中直接包含所需字段；
- 官方 Python 客户端。

请求次数越多，越容易遇到速率限制、令牌过期和部分失败。

### 11.5 将响应变成分析表

先收集结构一致的记录：

```python
rows = []

for album in albums:
    for track in get_tracks(album["id"]):
        rows.append({
            "track_id": track["id"],
            "track_name": track["name"],
            "album_id": album["id"],
            "album_name": album["name"],
            "release_date": album["release_date"],
        })

tracks = pd.DataFrame(rows)
```

然后验证：

```python
assert tracks["track_id"].notna().all()
tracks["track_id"].duplicated().mean()
tracks["release_date"].str.len().value_counts()
```

日期字段可能只精确到年、月或日，不能不加检查就统一解析成完整日期。

### 11.6 Web 礼仪与合规

使用 API 或抓取网站时：

- 阅读服务条款和 API 文档；
- 查看是否允许自动访问；
- 遵守速率限制；
- 优先使用官方 API、数据下载或客户端库；
- 从小请求开始；
- 缓存结果，避免重复下载；
- 不绕过认证、访问控制或反爬限制；
- 不收集不必要的个人敏感信息。

能抓到数据不代表有权使用或发布数据。

## 12. XML、HTML 与 XPath：在树中定位节点

### 12.1 XML 的基本结构

```xml
<catalog>
  <plant>
    <common>Bloodroot</common>
    <price curr="USD">$2.44</price>
    <availability date="0399"/>
  </plant>
</catalog>
```

基本术语：

- `catalog`：根节点；
- `plant`：根节点的子节点；
- `common`：元素；
- `Bloodroot`：文本内容；
- `curr="USD"`：属性；
- `<availability .../>`：空元素的缩写形式。

一个良构 XML 文档至少满足：

- 只有一个根节点；
- 开始标签与结束标签匹配；
- 节点正确嵌套；
- 标签大小写敏感；
- 属性值被引号包围。

### 12.2 为什么 XML/HTML 不能用正则解析

树结构允许任意嵌套：

```html
<div>
  <span>outer <b>inner</b></span>
</div>
```

正则很难稳定处理：

- 嵌套深度；
- 可选属性；
- 标签顺序；
- 实体编码；
- 不规则 HTML；
- 命名空间。

因此：

```python
from lxml import html

tree = html.fromstring(response.content)
```

先用解析器建立树，再按树结构查找。

### 12.3 HTML 表格的结构

```html
<table>
  <tbody>
    <tr>
      <th>A</th><th>B</th><th>C</th>
    </tr>
    <tr>
      <td>1</td><td>2</td><td>3</td>
    </tr>
  </tbody>
</table>
```

- `<table>`：表；
- `<tr>`：一行；
- `<th>`：表头单元格；
- `<td>`：普通单元格。

简单页面可以先尝试：

```python
tables = pd.read_html(url)
```

但若需要精确选择节点或处理不规则结构，就使用 `lxml` 和 XPath。

### 12.4 XPath 的三个组成部分

XPath 的一个位置步骤包含：

1. **axis**：沿哪个方向寻找；
2. **node test**：寻找哪种节点；
3. **predicate**：用什么条件筛选。

常见表达式：

| XPath | 含义 |
| --- | --- |
| `//table` | 文档任意位置的所有 `table` |
| `/catalog/plant/common` | 从根开始沿明确路径寻找 |
| `//common/text()` | 所有 `common` 节点的文本 |
| `//plant[2]` | 第二个 `plant` |
| `//@date` | 任意节点的 `date` 属性 |
| `//price[@curr="CAD"]/text()` | `curr` 为 CAD 的价格文本 |
| `..` | 当前节点的父节点 |

`//` 表示向任意深度后代搜索；单个 `/` 表示下一层。

### 12.5 Wikipedia 1500 米纪录案例

```python
import requests
from lxml import html

url = "https://en.wikipedia.org/wiki/1500_metres_world_record_progression"
response = requests.get(url, timeout=30)
response.raise_for_status()

tree = html.fromstring(response.content)
tables = tree.xpath("//table")
```

课程材料通过列位置抽取：

```python
times = tree.xpath("//table[3]/tbody/tr/td[1]/b/text()")
names = tree.xpath("//table[3]/tbody/tr/td[3]/a/text()")
dates = tree.xpath("//table[3]/tbody/tr/td[4]/text()")
```

然后转换比赛时间：

```python
def time_to_seconds(value):
    minute, second = value.replace("+", "").split(":")
    return 60 * float(minute) + float(second)
```

最后建表：

```python
records = pd.DataFrame({
    "race_time_sec": [time_to_seconds(x) for x in times],
    "athlete": [str(x) for x in names],
    "date": pd.to_datetime([str(x).strip() for x in dates]),
})
```

### 12.6 网页抓取最脆弱的是定位规则

`//table[3]` 依赖“目标表恰好是第三张表”。网页加入一张导航表后，代码仍可能运行，却抽取错误内容。

更稳的策略：

- 根据表头文本定位；
- 根据稳定 `id` 或 `class` 定位；
- 检查抽取列长度是否相等；
- 检查首尾记录和数据范围；
- 保存原始 HTML 或内容哈希；
- 当页面结构变化时明确失败。

```python
assert len(times) == len(names) == len(dates)
assert len(times) > 0
```

抓取成功的标准不是 XPath 返回了列表，而是列表与预期语义一致。

### 12.7 XML 文件解析

```python
from lxml import etree

catalog = etree.parse("data/catalog.xml")

lights = catalog.xpath("//light/text()")
cad_plants = catalog.xpath(
    '//price[@curr="CAD"]/../common/text()'
)
```

第二个表达式：

1. 找到 `curr="CAD"` 的 `price`；
2. 用 `..` 回到父 `plant`；
3. 找到其 `common` 子节点；
4. 取得文本。

### 12.8 XML 命名空间

欧洲央行 XML 中可能出现：

```xml
<gesmes:Envelope
  xmlns="http://www.ecb.int/vocabulary/2002-08-01/eurofxref">
```

默认命名空间中的标签在 XPath 中也需要显式前缀：

```python
namespace = {
    "x": "http://www.ecb.int/vocabulary/2002-08-01/eurofxref"
}

dates = tree.xpath(
    "./x:Cube/x:Cube/@time",
    namespaces=namespace,
)

usd_rates = tree.xpath(
    './/x:Cube[@currency="USD"]/@rate',
    namespaces=namespace,
)
```

这里的 `x` 是我们自己选择的临时别名，关键是它映射到正确 URI。

若 XPath 看似正确却返回空列表，命名空间是首要排查对象之一。

## 13. NetCDF 与 Xarray：保留多维数据的原生结构

### 13.1 为什么 NetCDF 不应先展平成表

假设每小时记录全球网格温度：

```text
time × latitude × longitude
```

若转成长表，经纬度和时间会被大量重复。NetCDF 只需分别保存坐标轴，再保存网格值，更紧凑也更符合数据语义。

NetCDF 的优点包括：

- 可高效读取子集；
- 可追加；
- 跨语言和操作系统；
- 自描述；
- 适合大型科学数组。

它是二进制格式，不能依赖文本编辑器查看，需要专用工具。

### 13.2 四个核心组成

打开文件：

```python
import xarray as xr

ds = xr.open_dataset("data/CDS_ERA5_22-12.nc")
```

检查：

```python
ds.sizes       # 各维度长度
ds.coords      # 坐标
ds.data_vars   # 数据变量
ds.attrs       # 全局属性
```

变量属性：

```python
ds["tp"].dims
ds["tp"].shape
ds["tp"].attrs
```

概念区别：

- **dimension**：数组轴的名字；
- **coordinate**：轴上的具体标签；
- **data variable**：在坐标网格上变化的测量值；
- **attribute**：单位、长名称、来源、许可等元数据。

### 13.3 `DataArray` 与 `Dataset`

- `DataArray`：一个带维度、坐标和属性的数组；
- `Dataset`：共享坐标的一组 `DataArray`。

```python
temperature = ds["t2m"]
type(temperature)
```

这类似：

```text
Dataset ≈ 多个有关联的变量
DataArray ≈ 单个带标签的多维变量
```

但不要机械地把它们等同于 DataFrame 和 Series，因为维度可以超过二维。

### 13.4 `isel` 与 `sel`

按位置：

```python
first_point = ds.isel(time=0, latitude=26, longitude=119)
```

按坐标标签：

```python
berkeley = ds.sel(
    latitude=37.75,
    longitude=237.5,
)
```

如果坐标不完全存在：

```python
berkeley = ds.sel(
    latitude=37.75,
    longitude=237.5,
    method="nearest",
)
```

选择后应查看真正匹配的坐标：

```python
float(berkeley.latitude)
float(berkeley.longitude)
```

`method="nearest"` 不代表距离一定足够近，必要时要检查误差容限。

### 13.5 时间和空间子集

```python
subset = ds.sel(
    time=slice("2022-12-20", "2022-12-31"),
    latitude=slice(50, 21),
    longitude=slice(232, 300),
)
```

注意某些气候数据的纬度按从北到南递减，因此切片可能写成 `slice(50, 21)`。先检查：

```python
ds.latitude.values[:5]
ds.latitude.values[-5:]
```

不能假定坐标总是升序。

课程案例也使用布尔掩码：

```python
mask_lon = (ds.longitude > 232) & (ds.longitude < 300)
mask_lat = (ds.latitude > 21) & (ds.latitude < 50)

us_temperature = (
    ds.sel(time="2022-12-31T13:00:00")["t2m"]
      .where(mask_lon & mask_lat, drop=True)
)
```

### 13.6 单位必须从属性确认

```python
ds["tp"].attrs
ds["t2m"].attrs
```

若温度单位是 Kelvin：

```python
temp_c = ds["t2m"] - 273.15
temp_c.attrs = {
    **ds["t2m"].attrs,
    "units": "degC",
}
```

若总降水量原单位是米，转换厘米：

```python
precip_cm = ds["tp"] * 100
precip_cm.attrs["units"] = "cm"
```

不要只看变量名猜单位。图轴和最终表中必须保留单位。

### 13.7 大文件要先切片再计算

`xr.open_dataset()` 往往不会立即把全部数据加载进内存，但某些计算会触发实际读取。

正确顺序通常是：

```text
打开
  -> 查看元数据
  -> 按变量、时间和空间切小
  -> 再聚合、加载或绘图
```

而不是：

```text
打开
  -> 全部转 DataFrame
  -> 再筛选
```

对大型数据可在环境支持时使用分块：

```python
ds = xr.open_dataset(
    path,
    chunks={"time": 24},
)
```

这通常依赖 Dask。若项目没有安装或数据不大，不必为了分块额外增加复杂度。

### 13.8 关闭文件

```python
ds.close()
```

或使用上下文管理器：

```python
with xr.open_dataset(path) as ds:
    subset = ds[["t2m", "tp"]].sel(
        time=slice("2022-12-20", "2022-12-31")
    ).load()
```

`.load()` 在文件关闭前把所选子集读入内存。对小子集这是清晰、安全的做法。

### 13.9 NetCDF 的最低质量检查

```python
assert {"time", "latitude", "longitude"} <= set(ds.sizes)
assert ds.time.size > 0
assert ds.latitude.size > 0
assert ds.longitude.size > 0

print(pd.Timestamp(ds.time.min().values))
print(pd.Timestamp(ds.time.max().values))
print(ds["t2m"].attrs.get("units"))

# 只检查一个时间切片，避免为初步检查读取整个时空数组
sample_t2m = ds["t2m"].isel(time=0)
print(float(sample_t2m.isnull().mean().compute()))
```

还要确认：

- 经度使用 `0~360` 还是 `-180~180`；
- 纬度升序还是降序；
- 时间时区与日历；
- 缺失值编码；
- 每个变量的单位；
- 数据是观测、再分析还是模型输出。

## 14. 把两章串起来：从外部资源到分析结论

Ch13 和 Ch14 不是互不相关的工具箱。真实任务常把它们连在一起。

### 14.1 示例：从新闻 API 分析主题变化

#### 第一步：定义分析单位

假设一行代表一篇文章，主键是 `web_url` 或文章 ID。

先明确：

- 时间范围；
- 文章类型；
- 是否包含重复转载；
- 正文、摘要还是导语作为文本；
- 要研究主题出现次数，还是包含主题的文章数。

#### 第二步：通过 API 取得 JSON

```python
payload = get_json(
    api_url,
    params={
        "begin_date": "20190101",
        "end_date": "20241231",
        "page": 0,
    },
    headers={"Authorization": f"Bearer {token}"},
)
```

验证业务状态、分页和总数。

#### 第三步：从层级结构中提取记录

```python
articles = pd.json_normalize(
    payload,
    record_path=["response", "docs"],
)
```

选择需要字段：

```python
articles = articles[[
    "_id",
    "web_url",
    "pub_date",
    "headline.main",
    "lead_paragraph",
]]
```

#### 第四步：解析日期

若不能使用日期访问器，也可以用捕获组练习：

```python
date_parts = articles["pub_date"].str.extract(
    r"^(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})"
)
```

实际项目中优先使用日期解析器：

```python
articles["pub_date"] = pd.to_datetime(
    articles["pub_date"],
    errors="coerce",
    utc=True,
)
```

#### 第五步：构造主题特征

```python
text = (
    articles["headline.main"].fillna("")
    + " "
    + articles["lead_paragraph"].fillna("")
)

topic_patterns = {
    "new_year": r"\bnew year(?:'s)?\b",
    "zoom": r"\bzoom\b",
    "gpt": r"\b(?:chatgpt|gpt(?:-\d+)?)\b",
}

for name, pattern in topic_patterns.items():
    articles[name] = text.str.count(
        pattern,
        flags=re.IGNORECASE,
    )
```

使用单词边界可以避免 `zoom` 匹配到更长单词中的片段。模式仍要通过人工样本评估。

#### 第六步：聚合到季度

```python
articles["quarter"] = (
    articles["pub_date"]
      .dt.tz_localize(None)
      .dt.to_period("Q")
)

quarterly = (
    articles
      .groupby("quarter")[list(topic_patterns)]
      .agg(lambda column: column.gt(0).sum())
      .reset_index()
)
```

这里统计“提到主题的文章数”，不是“主题总出现次数”。两种定义可能得到不同趋势。

#### 第七步：解释前检查分母

每季度文章总数可能不同。除计数外还应计算比例：

```python
total = articles.groupby("quarter").size().rename("n_articles")
mentions = articles.groupby("quarter")[list(topic_patterns)].agg(
    lambda column: column.gt(0).sum()
)

proportions = mentions.div(total, axis="index")
```

若不控制分母，某季度主题文章更多，可能只是该季度收录的全部文章更多。

### 14.3 示例：API 返回的数据为什么要保留原始层

推荐目录结构：

```text
data/
├── raw/
│   ├── response-page-001.json
│   └── response-page-002.json
├── interim/
│   └── parsed-articles.parquet
└── processed/
    └── quarterly-topic-counts.csv
```

三层含义：

- `raw`：原始响应，原则上不手工修改；
- `interim`：结构化但未完成全部分析处理；
- `processed`：面向具体分析的最终数据。

这样当正则或字段映射发生变化时，可以从原始响应重新生成，而不必再次依赖外部服务。

## 16. 最容易犯的错误

### 16.1 规范化后覆盖原始文本

问题：失去追溯能力，也无法检查不同实体是否被错误合并。

正确做法：保留原始列，新增规范化键。

### 16.2 规范化键一相同就认为是同一实体

问题：不同州可有同名县，不同人也可能同名。

正确做法：使用足够的复合键，并用 `validate` 和 `_merge` 检查连接。

### 16.3 使用 `contains()` 验证整个字段

问题：只要子串符合就返回真。

正确做法：严格格式使用 `fullmatch()`。

### 16.4 忘记原始字符串

问题：Python 会先解释反斜杠，模式变得难写、难读。

正确做法：正则通常写成 `r"..."`。

### 16.5 大量使用 `.*`

问题：贪婪匹配容易跨过多个目标。

正确做法：使用更具体的否定字符类，如 `[^"]*`。

### 16.6 正则只测成功样本

问题：无法发现误匹配和边界错误。

正确做法：同时测试正常、边界、畸形和额外文本样本。

### 16.7 用正则解析 HTML 或 JSON

问题：正则不理解任意嵌套和语法结构。

正确做法：使用 `json`、`lxml` 或其他专用解析器。

### 16.8 把关键词命中当作真实标签

问题：规则存在假阳性、假阴性和语境问题。

正确做法：抽样人工验证，并说明变量是代理测量。

### 16.9 将稀疏文本矩阵全部转成密集数组

问题：高维文本数据会消耗巨大内存。

正确做法：保留稀疏表示，使用支持稀疏矩阵的算法。

### 16.10 在全部文档上拟合 TF-IDF 后再划分数据

问题：测试集信息进入词表和 IDF，造成数据泄漏。

正确做法：训练集 `fit_transform`，测试集只 `transform`。

### 16.11 把情感模型分数当作客观情绪

问题：它只是特定模型在特定标签体系下的预测。

正确做法：检查领域适配、错误样本和群体偏差。

### 16.12 只看 HTTP `200`

问题：业务错误也可能用 200 返回，内容还可能是 HTML 登录页。

正确做法：检查状态码、`content-type` 和响应内部状态字段。

### 16.13 网络请求不设超时

问题：程序可能无限等待。

正确做法：所有外部请求显式设置 `timeout`。

### 16.14 把密钥写在 notebook 中

问题：密钥容易进入 Git 历史或提交文件。

正确做法：使用环境变量，并定期轮换泄露密钥。

### 16.15 忽略分页

问题：程序正常结束，但只拿到第一页。

正确做法：检查 `next`、cursor 或总记录数。

### 16.16 在循环中发出过多请求

问题：速度慢、易触发限流，也容易部分失败。

正确做法：优先批量端点、官方客户端和本地缓存。

### 16.17 XPath 只依赖表格序号

问题：页面增加元素后会抽到错误表。

正确做法：根据稳定属性或表头定位，并设置结构断言。

### 16.18 XPath 返回空就随意改表达式

问题：真正原因可能是 XML 命名空间。

正确做法：先检查标签的 namespace URI。

### 16.19 NetCDF 一打开就转 DataFrame

问题：失去多维结构并可能造成巨大内存开销。

正确做法：先按变量、时间和空间切片，再考虑转换。

### 16.20 猜测 NetCDF 单位和坐标方向

问题：Kelvin 可能被当成摄氏度，经度体系和纬度顺序也可能不同。

正确做法：检查 `attrs` 和坐标值。

## 17. 一套可复用的外部数据工作流

### 17.1 获取前

- 定义分析单位和时间范围；
- 找官方数据下载、API 或库；
- 阅读格式、字段和认证文档；
- 确认许可、服务条款和访问限制；
- 设计原始数据保存位置。

### 17.2 获取时

- 使用参数化 URL 或 API 请求；
- 设置超时；
- 检查状态码和内容类型；
- 处理分页；
- 遵守速率限制；
- 记录请求时间、URL、参数和数据版本。

### 17.3 解析时

- JSON：先检查对象、数组和记录路径；
- HTML/XML：先建立树，再使用 XPath；
- 文本：先判断简单拆分还是正则；
- NetCDF：先检查维度、坐标、变量和属性。

### 17.4 转换时

- 保留原始字段；
- 说明规范化规则；
- 明确展开后粒度；
- 把日期和数值交给专用解析器；
- 保留单位和来源元数据；
- 不在大数据上做不必要的密集化。

### 17.5 验证时

```text
数量：行数、页数、匹配率、未匹配数
结构：主键、粒度、嵌套关系、维度
类型：日期、数值、布尔、类别
范围：时间、坐标、单位、合法值
语义：字段是否真代表分析概念
稳定性：页面或接口变化时能否明确失败
```

### 17.6 分析时

- 关键词特征要评估误差；
- 文本向量要说明预处理；
- 降维图不能过度解释；
- 模型输出要视为带误差的测量；
- 外部数据的选择机制限制结论推广。

### 18.2 参考答案

1. 规范化统一等价写法；抽取将文本片段变成字段；特征化把文本内容映射成变量；文档分析把整篇文本转成可比较表示。
2. 规范化可能损失信息，保留原始列才能追溯错误和重新制定规则。
3. 它把字符串方法向量化地应用于 Series 中每个非缺失值。
4. `contains` 搜索任意位置；`match` 从开头匹配；`fullmatch` 要求整个字符串符合模式。
5. 它减少 Python 对反斜杠的预处理，使 `\d`、`\b` 等正则符号保持清晰。
6. `*` 是零次或更多，`+` 是一次或更多，`?` 是零次或一次。
7. 数量词默认尽可能延长匹配，`.*` 可能一直吃到最后一个可行终点。
8. 捕获组会返回组内内容；非捕获组 `(?:...)` 只控制结构，不生成抽取结果。
9. `extract` 每个原字符串最多保留第一个匹配；`extractall` 把每次匹配展开成一行。
10. 只有反例、边界和畸形样本才能揭示误匹配、过度匹配和格式遗漏。
11. 它通常丢失词序、句法和大部分上下文。
12. 出现在很多文档中的词区分力较弱，IDF 会降低其权重。
13. 词表很大而单篇文档只含少量词项，密集化会浪费大量内存。
14. 可解释为当前表示和投影下的近似相似；不能直接解释成政治立场、因果关系或完整语义距离。
15. 它是特定模型、训练数据和标签定义下的预测，也会有领域偏移和系统误差。
16. object 对应 `dict`，array 对应 `list`。
17. 记录可能按行、按列、按矩阵或藏在嵌套列表中，行列映射不同。
18. 2xx 成功，4xx 客户端请求或权限问题，5xx 服务端问题。
19. 响应体仍可能是业务错误、空结果、错误页面或不完整第一页。
20. 数据会被系统性截断，而程序可能仍正常结束。
21. 每个请求都应包含服务器理解它所需的信息，不依赖上一次请求状态。
22. 它可能进入 Git、共享文件和输出，导致凭据泄露和未经授权访问。
23. 文本是节点中的字符内容；属性位于开始标签中；子节点是嵌套的其他元素。
24. `/` 向下一层，`//` 搜索任意深度后代，`..` 回到父节点，`@` 选择属性。
25. 命名空间属于标签完整身份；XPath 必须把前缀映射到相同 URI 才能匹配。
26. HTML 是展示结构而非稳定数据接口，表格序号、标签和 class 都可能改变。
27. dimension 是轴，coordinate 是轴标签，data variable 是网格测量，attribute 是单位、来源等元数据。
28. 展平或加载全部数据会造成重复和巨大内存开销；先切片可减少读取与计算量。
29. `.sel()` 按坐标标签，`.isel()` 按整数位置。
30. 保存原始响应、来源 URL、参数、请求时间、版本、解析代码和质量检查结果。
