第五部分研究的是数值预测：

$$
X\longrightarrow \hat y\in\mathbb R
$$

第六部分首先研究类别预测。以二分类为例：

$$
X
\longrightarrow \hat p=P(Y=1\mid X)

这里有两个不能混为一谈的步骤：

逻辑回归负责第一步，阈值和业务规则负责第二步。`predict_proba` 与 `predict` 的差别就来自这里。

## 1. Ch19：先把分类问题定义正确

### 1.1 监督学习、标签与正类

分类属于监督学习。训练数据由特征与已知标签组成：

$$
\{(\mathbf x_i,y_i)\}_{i=1}^{n}
$$

二分类通常把标签编码为：

$$
y_i\in\{0,1\}
$$

但 1 不表示“好”，0 也不表示“坏”。1 只是被定义为**正类**：

- 疾病筛查：1 可以是患病；
- 垃圾邮件：1 可以是 spam；
- 假新闻案例：1 可以是 fake；
- 欺诈识别：1 可以是欺诈。

在计算任何指标前，先写一句：

```text
本任务中 Y=1 表示什么？
```

否则“提高召回率”“减少假阳性”都没有明确含义。

### 1.2 数据粒度和标签质量先于模型

分类器学习的是“特征与现有标签之间的关系”，所以必须先确认：

- 一行代表一封邮件、一篇文章，还是一个用户？
- 标签由谁、按什么规则产生？
- 同一实体是否重复出现在多行？
- 部署时是否能获得这些特征？
- 训练标签是否等同于真正想预测的概念？

例如 Ch21 中的模型学习的是：

> Politifact 选中并标记的文章，在已有文本特征下被标为 fake 的概率。

它并不自动等于“任意时代、任意来源文章客观为假的概率”。覆盖、选择和测量过程共同决定了模型实际学到的目标。

### 1.3 常数分类器是必须建立的基准

最简单的分类器始终预测同一类别。若正类比例为：

$$
\hat\pi=\frac1n\sum_i y_i
$$

在 0-1 损失下，最佳常数类别是样本中的多数类：

$$
\ell(\hat y,y)=I(\hat y\neq y)
$$

若 99% 是负类，始终预测 0 就有 99% accuracy，但它一个正类也找不到。因此任何模型至少要与以下基准比较：

- 多数类分类器；
- 始终输出训练集正类比例的常数概率模型；
- 与业务现行规则相同的基准。

```python
from sklearn.dummy import DummyClassifier

baseline = DummyClassifier(strategy="prior")
baseline.fit(X_train, y_train)

baseline_prob = baseline.predict_proba(X_test)[:, 1]
baseline_pred = baseline.predict(X_test)
```

没有超过合理基准的复杂模型，没有部署价值。

### 1.4 分类器的三种输出

同一个分类模型可以给出：

1. **原始分数** $z$：通常可正可负；
2. **概率** $\hat p$：位于 0 和 1 之间；
3. **类别** $\hat y$：由阈值把概率离散化。

```python
score = model.decision_function(X_test)
prob = model.predict_proba(X_test)
pred = model.predict(X_test)
```

对 sklearn 二分类器：

```python
model.classes_
```

决定 `predict_proba` 各列对应哪个类别。不要在字符串标签下无条件假设 `[:, 1]` 就是业务正类：

```python
positive_label = 1
positive_col = list(model.classes_).index(positive_label)
p_positive = model.predict_proba(X_test)[:, positive_col]
```

## 2. 逻辑回归：先预测概率，再决定类别

### 2.1 为什么不能直接用普通直线预测概率

若直接对 0/1 标签做线性回归：

$$
\hat p=\theta_0+\theta_1x
$$

会遇到三个问题：

- 预测可能小于 0 或大于 1；
- 概率与特征的关系经常在两端趋于饱和；
- 相同的线性变化不应在任意位置产生相同概率变化。

逻辑回归先计算线性分数：

$$
z=\theta_0+\theta_1x_1+\cdots+\theta_px_p
$$

再用 sigmoid 函数压缩到 $(0,1)$：

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

因此：

$$
\hat p_i
=P_{\hat\theta}(Y_i=1\mid \mathbf x_i)
=\sigma(\mathbf x_i^\top\hat\theta)
$$

![逻辑回归把特征的线性组合转换成概率，再通过决策规则输出类别](./笔记/logistic_regression_1/images/log_reg_summary.png)

sigmoid 的关键性质：

- $\sigma(0)=0.5$；
- $z$ 越大，概率越接近 1；
- $z$ 越小，概率越接近 0；
- 中间变化快，两端逐渐饱和。

数值实现优先使用稳定版本：

```python
from scipy.special import expit

z = X_design @ theta
p = expit(z)
```

不要在很大的正负 $z$ 上手写 `1 / (1 + np.exp(-z))`，否则 `exp` 可能溢出。

### 2.2 odds、logit 与系数解释

概率 $p$ 对应的 odds（胜算）是：

$$
\operatorname{odds}=\frac{p}{1-p}
$$

例子：

| 概率 $p$ | odds $p/(1-p)$ | 直观含义 |
| ---: | ---: | --- |
| 0.2 | 0.25 | 正类与负类约为 1:4 |
| 0.5 | 1 | 正类与负类约为 1:1 |
| 0.8 | 4 | 正类与负类约为 4:1 |

对 odds 取自然对数得到 logit：

$$
\operatorname{logit}(p)
=\log\frac{p}{1-p}
$$

逻辑回归真正的“线性”发生在 log odds 上：

$$
\log\frac{p}{1-p}
=\theta_0+\theta_1x_1+\cdots+\theta_px_p
$$

在其他特征不变时，$x_j$ 增加 1：

$$
\text{odds 新值}
=e^{\theta_j}\times \text{odds 旧值}
$$

所以 $e^{\theta_j}$ 是 odds ratio：

- $\theta_j=0$：odds 不变；
- $\theta_j>0$：正类 odds 增加；
- $\theta_j<0$：正类 odds 减少。

注意，$\theta_j$ 不是“概率增加 $\theta_j$”。概率变化取决于当前位置：

$$
\frac{\partial p}{\partial x_j}
=\theta_j p(1-p)
$$

当 $p$ 接近 0.5 时概率最敏感；接近 0 或 1 时，同样的分数变化只造成很小的概率变化。

### 2.3 类别、对数和交互特征仍然适用

逻辑回归仍使用设计矩阵，所以第五部分的特征工程继续适用：

- 数值标准化；
- 对数和多项式变换；
- 独热编码；
- 交互项；
- 文本词频和 TF-IDF。

“逻辑回归的决策边界是线性的”指它在**当前设计矩阵特征空间**中是超平面。若加入 $x^2$、样条或交互，映射回原始空间后可以得到曲线边界。

### 2.4 决策边界

给定阈值 $T$：

$$
\hat y=
\begin{cases}
1,&\hat p\ge T\\
0,&\hat p<T
\end{cases}
$$

因为 sigmoid 单调递增：

$$
\hat p=T
\quad\Longleftrightarrow\quad
\mathbf x^\top\theta
=\log\frac{T}{1-T}
$$

当 $T=0.5$：

$$
\mathbf x^\top\theta=0
$$

在二维特征空间中这是直线，在三维中是平面，更高维中是超平面。改变阈值通常会平移边界，但不会改变模型已经学到的概率排序。

### 2.5 sklearn 的可靠实现

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

model = Pipeline([
    ("scale", StandardScaler()),
    ("logistic", LogisticRegression(
        C=1.0,
        penalty="l2",
        max_iter=10_000,
    )),
])

model.fit(X_train, y_train)

p_test = model.predict_proba(X_test)[:, 1]
y_test_pred = (p_test >= 0.5).astype(int)
```

这里：

- `C` 是正则强度的倒数，`C` 越小，正则越强；
- `max_iter` 是优化器最多迭代次数，不是模型复杂度；
- 标准化与模型放在同一 Pipeline，交叉验证时每折单独拟合；
- `predict()` 通常按 0.5 阈值分类，手工阈值应从 `predict_proba()` 开始。

若有类别特征，使用 `ColumnTransformer`：

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder

numeric = ["age", "amount"]
categorical = ["channel", "region"]

preprocess = ColumnTransformer([
    ("num", StandardScaler(), numeric),
    ("cat", OneHotEncoder(
        handle_unknown="ignore",
        drop="first",
    ), categorical),
])

model = Pipeline([
    ("preprocess", preprocess),
    ("logistic", LogisticRegression(max_iter=10_000)),
])
```

## 3. 交叉熵：逻辑回归为什么这样拟合

### 3.1 单个观测的交叉熵

模型对正类给出概率 $p$，真实标签为 $y\in\{0,1\}$。交叉熵损失是：

$$
\ell(p,y)
=-y\log p-(1-y)\log(1-p)
$$

分情况看：

$$
\ell(p,y)=
\begin{cases}
-\log p,&y=1\\
-\log(1-p),&y=0
\end{cases}
$$

它奖励正确且自信的概率，严厉惩罚错误且自信的概率：

| 真实标签 | 预测概率 $p=P(Y=1)$ | 损失 |
| ---: | ---: | ---: |
| 1 | 0.9 | $-\log0.9\approx0.105$ |
| 1 | 0.1 | $-\log0.1\approx2.303$ |
| 0 | 0.1 | $-\log0.9\approx0.105$ |
| 0 | 0.9 | $-\log0.1\approx2.303$ |

若对错误类别给出接近 1 的概率，损失趋于无穷。这迫使模型不仅分类正确，还要避免没有依据的过度自信。

### 3.2 经验风险与最佳常数概率

平均交叉熵：

$$
R(\theta)
=-\frac1n\sum_{i=1}^{n}
\left[
y_i\log p_i+(1-y_i)\log(1-p_i)
\right]
$$

若所有样本都输出同一个常数概率 $p$，使交叉熵最小的解是：

$$
\hat p=\bar y=\frac{n_1}{n}
$$

即训练集正类比例。这说明逻辑回归是在常数概率基准之上，利用特征让不同样本得到不同概率。

### 3.3 交叉熵与最大似然是同一件事

若：

$$
Y_i\mid X_i\sim\operatorname{Bernoulli}(p_i)
$$

一个标签出现的概率可写成：

$$
P(Y_i=y_i)
=p_i^{y_i}(1-p_i)^{1-y_i}
$$

独立样本的似然是这些概率的乘积。取对数后，乘积变成求和：

$$
\log L(\theta)
=\sum_i
\left[
y_i\log p_i+(1-y_i)\log(1-p_i)
\right]
$$

因此：

$$
\arg\max_\theta\log L(\theta)
=
\arg\min_\theta R(\theta)
$$

最小化交叉熵，就是选择让已观察标签最可能出现的参数。

### 3.4 为什么不用 MSE 拟合 sigmoid

对 sigmoid 输出使用 MSE 并非数学上完全不可能，但不适合作为标准逻辑回归目标：

- 损失对参数可能非凸，优化更困难；
- 错误且自信的预测，单点平方误差最多接近 1，惩罚不够强；
- 它没有直接对应 Bernoulli 最大似然；
- 交叉熵的梯度形式更自然。

另一方面，Brier score：

$$
\frac1n\sum_i(y_i-p_i)^2
$$

仍可作为**概率预测的评价指标**。训练损失与评价指标可以不同，但必须知道二者回答的问题不同。

### 3.5 稳定地实现交叉熵和梯度

直接计算 `log(p)` 可能遇到 `log(0)`。对分数 $z=X\theta$，单点损失可以稳定地写成：

$$
\log(1+e^z)-yz
$$

NumPy 中使用 `logaddexp`：

```python
import numpy as np
from scipy.special import expit

def logistic_risk_and_grad(theta, X, y, l2=0.0):
    z = X @ theta

    data_loss = np.mean(np.logaddexp(0, z) - y * z)
    penalty = 0.5 * l2 * np.sum(theta[1:] ** 2)
    loss = data_loss + penalty

    p = expit(z)
    reg_grad = np.r_[0.0, theta[1:]]
    grad = X.T @ (p - y) / len(y) + l2 * reg_grad

    return loss, grad
```

梯度：

$$
\nabla_\theta R(\theta)
=\frac1nX^\top(\mathbf p-\mathbf y)
$$

与线性回归的 $X^\top(\hat y-y)$ 结构很相似：预测概率与标签的偏差，经每个特征加权汇总后，决定系数应向哪里移动。

截距 `theta[0]` 没有加入惩罚。实际实现中也通常不正则化截距。

### 3.6 用 scipy 手动拟合

```python
from scipy.optimize import minimize

X_design = np.column_stack([
    np.ones(len(X_train)),
    X_train.to_numpy(),
])
y_array = np.asarray(y_train)

result = minimize(
    fun=lambda theta: logistic_risk_and_grad(
        theta, X_design, y_array, l2=0.01
    )[0],
    jac=lambda theta: logistic_risk_and_grad(
        theta, X_design, y_array, l2=0.01
    )[1],
    x0=np.zeros(X_design.shape[1]),
)

if not result.success:
    raise RuntimeError(result.message)

theta_hat = result.x
p_train = expit(X_design @ theta_hat)
```

这段代码用于理解 `lab10.ipynb` 的底层逻辑。实际项目优先使用 sklearn，因为它对求解器、稀疏矩阵、正则化和数值稳定性处理得更完善。

### 3.7 线性可分为什么会让参数发散

若存在一个超平面能把训练集两类完全分开，那么沿相同方向不断放大系数，可以让：

- 正类概率越来越接近 1；
- 负类概率越来越接近 0；
- 训练交叉熵不断接近 0。

此时未正则化逻辑回归的有限最优参数可能不存在。分类边界看似已经稳定，系数绝对值却继续增大，优化器可能报告不收敛。

$L_2$ 正则化加入：

$$
R_\lambda(\theta)
=R(\theta)+\lambda\sum_{j=1}^{p}\theta_j^2
$$

大系数必须付出代价，因此得到有限、稳定的解。正则化还能缓解高维文本中的共线性和过拟合。

在 sklearn 中：

```text
C 小  -> 正则更强 -> 系数更小
C 大  -> 正则更弱 -> 更接近未正则化模型
```

`C` 必须在训练集内部通过交叉验证选择。

## 4. 从概率到决策：阈值与分类评价

### 4.1 混淆矩阵先确定方向

sklearn 的二分类混淆矩阵默认是：

$$
\begin{bmatrix}
TN & FP\\
FN & TP
\end{bmatrix}
$$

其中行是真实类别，列是预测类别：

| 真实 / 预测 | 预测 0 | 预测 1 |
| --- | ---: | ---: |
| 真实 0 | TN | FP |
| 真实 1 | FN | TP |

```python
from sklearn.metrics import confusion_matrix

cm = confusion_matrix(y_test, y_test_pred, labels=[0, 1])
tn, fp, fn, tp = cm.ravel()
```

![混淆矩阵把正确和错误进一步拆成四种情况](./笔记/logistic_regression_2/images/confusion_matrix.png)

“假阳性”和“假阴性”是否严重，完全取决于正类定义与应用：

- 垃圾邮件：FP 是把正常邮件扔进垃圾箱；
- 癌症筛查：FN 是漏掉真实患者；
- 欺诈拦截：FP 是误拦正常交易。

### 4.2 六个必须会算的指标

准确率：

$$
\operatorname{Accuracy}
=\frac{TP+TN}{TP+TN+FP+FN}
$$

精确率：

$$
\operatorname{Precision}
=\frac{TP}{TP+FP}
$$

它问：“模型判为正类的样本中，有多少真的为正？”

召回率，也叫 TPR、sensitivity：

$$
\operatorname{Recall}
=\operatorname{TPR}
=\frac{TP}{TP+FN}
$$

它问：“真实正类中，有多少被找出来？”

特异度，也叫 TNR：

$$
\operatorname{Specificity}
=\operatorname{TNR}
=\frac{TN}{TN+FP}
$$

假阳性率：

$$
\operatorname{FPR}
=\frac{FP}{FP+TN}
=1-\operatorname{Specificity}
$$

F1：

$$
F_1
=2\frac{\operatorname{Precision}\cdot\operatorname{Recall}}
{\operatorname{Precision}+\operatorname{Recall}}
$$

F1 是 precision 与 recall 的调和平均，只有二者都高时才高；但它忽略 TN，也不表达真实金钱或安全成本。

```python
from sklearn.metrics import (
    accuracy_score,
    balanced_accuracy_score,
    f1_score,
    precision_score,
    recall_score,
)

metrics = {
    "accuracy": accuracy_score(y_test, y_test_pred),
    "balanced_accuracy": balanced_accuracy_score(
        y_test, y_test_pred
    ),
    "precision": precision_score(
        y_test, y_test_pred, zero_division=0
    ),
    "recall": recall_score(
        y_test, y_test_pred, zero_division=0
    ),
    "f1": f1_score(
        y_test, y_test_pred, zero_division=0
    ),
}
```

balanced accuracy 是正类召回率与负类召回率的平均，在类别不平衡时比普通 accuracy 更有信息。

### 4.3 阈值改变错误构成

设正类概率阈值为 $T$：

```python
def classify(prob, threshold):
    return (np.asarray(prob) >= threshold).astype(int)
```

通常：

| 阈值变化 | 预测为正的数量 | Recall | Precision |
| --- | --- | --- | --- |
| 降低阈值 | 增加 | 通常上升 | 常可能下降 |
| 提高阈值 | 减少 | 通常下降 | 常可能上升 |

这是同一个概率模型上的决策权衡，不必每改变一次阈值就重新拟合模型。

0.5 没有天然业务正确性。只有在概率可靠、两类先验与训练相符、FP/FN 代价近似对称时，它才是自然起点。

### 4.4 用真实成本选择阈值

若假阳性成本为 $c_{FP}$，假阴性成本为 $c_{FN}$：

$$
\operatorname{Cost}(T)
=c_{FP}FP(T)+c_{FN}FN(T)
$$

```python
def classification_cost(
    y_true,
    prob,
    threshold,
    *,
    fp_cost=1.0,
    fn_cost=1.0,
):
    pred = classify(prob, threshold)
    tn, fp, fn, tp = confusion_matrix(
        y_true, pred, labels=[0, 1]
    ).ravel()
    return fp_cost * fp + fn_cost * fn
```

若漏诊成本远大于误报成本，应降低阈值以提高 recall。若误删正常邮件代价更大，应提高垃圾邮件阈值以提高 precision。

### 4.5 阈值也不能用测试集选择

正确做法是用训练集的 out-of-fold 概率选择阈值：

```python
from sklearn.model_selection import (
    StratifiedKFold,
    cross_val_predict,
)

cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42,
)

oof_prob = cross_val_predict(
    model,
    X_train,
    y_train,
    cv=cv,
    method="predict_proba",
)[:, 1]

thresholds = np.linspace(0.05, 0.95, 181)
costs = [
    classification_cost(
        y_train,
        oof_prob,
        threshold=t,
        fp_cost=1,
        fn_cost=5,
    )
    for t in thresholds
]
best_threshold = thresholds[np.argmin(costs)]

model.fit(X_train, y_train)
test_prob = model.predict_proba(X_test)[:, 1]
test_pred = classify(test_prob, best_threshold)
```

`cross_val_predict` 让每个训练样本的概率来自“没有见过该样本”的折内模型，比直接用训练拟合概率选阈值可靠。测试集仍只在最终方案确定后使用一次。

上面假设模型结构和超参数已经固定。若还要选择 `C`、词表参数等，应使用第 13.1 节的嵌套交叉验证，避免先看全部训练标签调好模型，再用看似 OOF 的概率重复优化。

### 4.6 类别不平衡怎样处理

类别不平衡不等于数据错误，也不意味着必须把两类强行采成 1:1。处理顺序通常是：

1. 建立多数类和常数概率基准；
2. 使用分层划分；
3. 改用 PR、recall、precision、balanced accuracy 等合适指标；
4. 根据错误代价选择阈值；
5. 仍无法满足目标时，再考虑类权重或重采样。

```python
weighted_model = LogisticRegression(
    class_weight="balanced",
    max_iter=10_000,
)
```

`class_weight="balanced"` 会让少数类单点损失权重更大。它改变了拟合目标，常能提高少数类 recall，但可能降低 precision，也可能让原始 `predict_proba` 不再对应部署总体中的真实发生率。

若使用过采样或欠采样，只能在每个训练折内部进行。先对完整数据重采样再做 CV，会让重复或合成样本跨折泄漏。重采样、类权重和改阈值不是同一操作，应根据验证结果和实际成本选择。

### 4.7 Precision-Recall 曲线

PR 曲线把不同阈值下的 recall 放在横轴、precision 放在纵轴：

```python
from sklearn.metrics import (
    average_precision_score,
    precision_recall_curve,
)

precision, recall, pr_thresholds = (
    precision_recall_curve(y_test, test_prob)
)
ap = average_precision_score(y_test, test_prob)
```

当正类稀少且关心“找出的正类有多少是真的”时，PR 曲线通常比 ROC 更直接。无技巧排序器的 precision 基准大致等于正类比例；类别越稀少，这条基准越低。

![改变分类阈值会同时改变 precision 和 recall](./笔记/logistic_regression_2/images/precision-recall-thresh.png)

### 4.8 ROC、AUC 与它们没有回答的问题

ROC 曲线绘制：

$$
\operatorname{TPR}
\quad\text{对}\quad
\operatorname{FPR}
$$

```python
from sklearn.metrics import roc_auc_score, roc_curve

fpr, tpr, roc_thresholds = roc_curve(y_test, test_prob)
roc_auc = roc_auc_score(y_test, test_prob)
```

ROC-AUC 可解释为：随机抽一个正类和一个负类，模型把正类分数排得更高的概率。

- AUC 约 0.5：接近随机排序；
- AUC 越接近 1：排序能力越强；
- AUC 与单一阈值无关。

但 AUC 不告诉你：

- 实际部署阈值是多少；
- 概率是否校准；
- 某个具体 FP/FN 成本下是否好用；
- 不同子群是否公平；
- 极端不平衡下 precision 是否可接受。

### 4.9 分类正确不等于概率可靠

两个模型可能给出相同类别，却分别预测 0.51 和 0.99。若事件发生，两者 accuracy 都算正确，但第二个模型明显更自信。

概率模型还应检查：

- log loss；
- Brier score；
- calibration curve；
- 不同概率区间中的实际正类比例。

```python
from sklearn.metrics import brier_score_loss, log_loss

test_log_loss = log_loss(y_test, test_prob)
test_brier = brier_score_loss(y_test, test_prob)
```

阈值负责行动，校准负责解释概率。排序好、分类准的模型，概率不一定可以直接解释为真实频率。

### 4.10 多分类怎样推广

当 $Y$ 有 $K>2$ 个类别时，可以为每类计算一个分数 $z_k$，再用 softmax 转成和为 1 的概率：

$$
P(Y=k\mid x)
=\frac{e^{z_k}}
{\sum_{r=1}^{K}e^{z_r}}
$$

为避免指数溢出，实际计算会先从全部 $z_k$ 中减去最大值。

```python
multi_model = LogisticRegression(
    max_iter=10_000,
)
multi_model.fit(X_train, y_train)

class_prob = multi_model.predict_proba(X_test)
class_pred = multi_model.predict(X_test)
```

多分类混淆矩阵扩展为 $K\times K$。precision、recall 和 F1 需要说明平均方式：

- `macro`：各类别等权，重视少数类；
- `weighted`：按类别样本数加权；
- `micro`：先汇总全部决策，再计算总体指标。

报告一个“总体 F1”而不说明平均方式是不完整的。

## 5. Ch20：数值优化把“最小化损失”真正算出来

### 5.1 为什么需要数值优化

普通最小二乘有解析解，但很多目标没有方便的闭式解：

- 逻辑回归的交叉熵；
- Lasso 的 $L_1$ 惩罚；
- Huber 损失；
- Ch18 的非对称相对损失；
- 更复杂的机器学习模型。

最直接的网格搜索在参数维度增加后会迅速失效。若每个参数只尝试 100 个值：

$$
p\text{ 个参数需要 }100^p\text{ 个网格点}
$$

四个参数就需要一亿次损失计算，而且仍只能得到网格精度的近似解。

数值优化利用损失曲面的局部方向和曲率，逐步寻找更低的位置。

### 5.2 梯度是多维“上坡最快方向”

对参数向量：

$$
\theta=
\begin{bmatrix}
\theta_1&\cdots&\theta_p
\end{bmatrix}^{\top}
$$

梯度是各偏导数组成的向量：

$$
\nabla_\theta L(\theta)
=
\begin{bmatrix}
\frac{\partial L}{\partial\theta_1}\\
\vdots\\
\frac{\partial L}{\partial\theta_p}
\end{bmatrix}
$$

梯度指向局部上升最快方向，因此负梯度是下降最快方向：

$$
\theta^{(t+1)}
=\theta^{(t)}
-\alpha\nabla_\theta L(\theta^{(t)})
$$

$\alpha>0$ 是学习率。

对一个小步长 $\mathbf s$，一阶近似为：

$$
L(\theta+\mathbf s)
\approx L(\theta)+
\nabla L(\theta)^\top\mathbf s
$$

取 $\mathbf s=-\alpha\nabla L(\theta)$：

$$
L(\theta+\mathbf s)
\approx L(\theta)
-\alpha\|\nabla L(\theta)\|_2^2
$$

只要局部近似有效、步长不过大，损失就会下降。

![梯度下降利用当前位置的切线方向逐步靠近最小值](./课本/ch20/figures/gd-diagram.png)

### 5.3 一套可检查的梯度下降实现

```python
def gradient_descent(
    loss_fn,
    grad_fn,
    theta0,
    *,
    step_size=0.01,
    max_iter=10_000,
    grad_tol=1e-6,
):
    theta = np.asarray(theta0, dtype=float).copy()
    history = []

    for iteration in range(max_iter):
        loss = float(loss_fn(theta))
        grad = np.asarray(grad_fn(theta), dtype=float)
        grad_norm = np.linalg.norm(grad)

        history.append((iteration, loss, grad_norm))

        if not np.isfinite(loss) or not np.all(np.isfinite(grad)):
            raise FloatingPointError("loss/gradient is not finite")

        if grad_norm < grad_tol:
            return theta, history

        theta = theta - step_size * grad

    raise RuntimeError("gradient descent did not converge")
```

这段实现至少记录：

- 当前损失；
- 梯度范数；
- 迭代次数；
- 非有限数值；
- 最大迭代保护。

只看“参数变化很小”可能误判：学习率极小时，参数几乎不动，却未必接近最低点。梯度范数和损失曲线应一起检查。

### 5.4 学习率决定速度和稳定性

| 学习率 | 现象 |
| --- | --- |
| 太小 | 损失下降但非常慢 |
| 合适 | 稳定快速下降 |
| 太大 | 跨过最低点、振荡甚至发散 |

![学习率过小、合适和过大时的不同轨迹](./课本/ch20/figures/learning_rate.png)

诊断时可画：

```python
history_array = np.asarray(history)

plt.plot(
    history_array[:, 0],
    history_array[:, 1],
)
plt.xlabel("Iteration")
plt.ylabel("Loss")
```

若损失持续增加或出现 `nan`：

1. 检查学习率；
2. 检查特征尺度；
3. 检查损失和梯度符号；
4. 检查 `log(0)`、除零和指数溢出；
5. 用有限差分核验梯度。

```python
from scipy.optimize import check_grad

error = check_grad(loss_fn, grad_fn, theta0)
print(error)
```

误差应足够小，但具体容许值取决于参数尺度和数值精度。

### 5.5 为什么标准化能显著加速

若一个特征取值约为 $10^{-2}$，另一个约为 $10^5$，损失曲面可能像狭长山谷。单一学习率在陡峭方向容易越界，在平缓方向又前进太慢。

训练集标准化：

$$
z_j=\frac{x_j-\bar x_{j,\text{train}}}
{s_{j,\text{train}}}
$$

能让各方向尺度更接近，改善优化条件数。标准化必须放进 Pipeline；测试集和验证折只能使用对应训练部分学到的均值与标准差。

### 5.6 可微与凸分别保证什么

**可微**意味着局部有梯度可用；**凸**意味着不会被更差的局部最低点困住。

凸函数满足：对任意 $0\le q\le1$，

$$
f(q\theta_a+(1-q)\theta_b)
\le qf(\theta_a)+(1-q)f(\theta_b)
$$

几何上，任意两点之间的弦都在函数图像上方。

![凸损失没有差于全局最低点的局部最低点](./课本/ch20/figures/convex-diagram.png)

需要精确理解：

- 凸且可微：合适条件下，梯度下降可找到全局最优；
- 严格凸：通常还能保证参数解唯一；
- 凸但不光滑：仍可用次梯度、坐标下降等方法；
- 非凸：梯度下降可能到局部最低点、鞍点或不同解。

逻辑回归交叉熵对参数是凸的；加入 $L_2$ 后通常更稳定。但若设计矩阵秩不足，未正则化参数仍可能不唯一。

### 5.7 Batch、SGD 与 Mini-batch

经验风险：

$$
L(\theta)
=\frac1n\sum_{i=1}^{n}\ell_i(\theta)
$$

其梯度是单点梯度的平均：

$$
\nabla L(\theta)
=\frac1n\sum_i\nabla\ell_i(\theta)
$$

三种方法的区别是每一步使用多少数据：

| 方法 | 每步使用的数据 | 优点 | 缺点 |
| --- | --- | --- | --- |
| Batch GD | 全部 $n$ 行 | 梯度稳定 | 大数据每步昂贵 |
| SGD | 1 行 | 更新快、可在线学习 | 轨迹噪声大 |
| Mini-batch | 一小批 | 易并行、稳定性折中 | 需选择 batch size |

mini-batch 更新：

$$
\theta^{(t+1)}
=\theta^{(t)}
-\alpha
\frac1{|\mathcal B|}
\sum_{i\in\mathcal B}
\nabla\ell_i(\theta^{(t)})
$$

训练时通常：

```text
随机打乱数据
  -> 分成 mini-batches
  -> 每个 batch 更新一次
  -> 完整看过一次数据称为一个 epoch
  -> 下一 epoch 重新打乱
```

随机化很重要。若数据按类别或时间排序后直接逐行更新，连续梯度可能长期偏向同一方向。

SGD 接近最优点时仍会抖动，所以常配合逐渐减小的学习率。mini-batch 不保证每一步都降低完整训练损失，但长期平均方向应合理。

### 5.8 Huber 损失：平滑与稳健的折中

Huber 损失在小误差区域使用平方损失，在大误差区域转为线性：

$$
\ell_\gamma(r)=
\begin{cases}
\frac12r^2,&|r|\le\gamma\\
\gamma(|r|-\frac12\gamma),&|r|>\gamma
\end{cases}
$$

它：

- 在中心可微且像 MSE 一样平滑；
- 尾部不像平方损失那样被异常值无限放大；
- $\gamma$ 控制从平方到线性的转折。

```python
def huber_loss(theta, y, gamma=1.0):
    residual = y - theta
    abs_residual = np.abs(residual)

    point_loss = np.where(
        abs_residual <= gamma,
        0.5 * residual**2,
        gamma * (
            abs_residual - 0.5 * gamma
        ),
    )
    return point_loss.mean()

def huber_grad(theta, y, gamma=1.0):
    residual = y - theta
    point_grad = np.where(
        np.abs(residual) <= gamma,
        -residual,
        -gamma * np.sign(residual),
    )
    return point_grad.mean()
```

Ch20 用它说明：模型、损失与优化算法是三个独立选择。更换损失后，“最佳参数”随之改变，梯度也必须重新推导。

### 5.9 Newton 方法利用二阶曲率

梯度下降用局部直线近似；Newton 方法用局部二次近似：

$$
L(\theta+\mathbf s)
\approx L(\theta)
+g(\theta)^\top\mathbf s
+\frac12\mathbf s^\top H(\theta)\mathbf s
$$

其中：

- $g(\theta)=\nabla L(\theta)$；
- $H(\theta)=\nabla^2L(\theta)$ 是 Hessian。

令二次近似最小，得到：

$$
\theta^{(t+1)}
=\theta^{(t)}
-H(\theta^{(t)})^{-1}g(\theta^{(t)})
$$

编程时不直接求逆，而是解线性方程：

```python
step = np.linalg.solve(hessian, gradient)
theta = theta - step
```

Newton 法接近最优点时可能非常快，但每步要构造并求解 $p\times p$ Hessian，参数很多时昂贵；Hessian 病态或局部二次近似不准时也可能迈出危险大步。实际库常使用阻尼、线搜索、拟牛顿或坐标下降。

### 5.10 不要把求解器当成模型

同一逻辑回归目标可由不同求解器优化：

- `lbfgs`：通用中小规模光滑问题；
- `liblinear`：较小数据的二分类；
- `saga`：大规模稀疏数据，并支持 $L_1$；
- SGD：超大规模或流式数据。

求解器决定“怎样找参数”，模型和损失决定“找什么参数”。切换求解器后，若都充分收敛并优化同一目标，结果应接近。

看到 `ConvergenceWarning` 不应直接忽略。依次检查：

1. 特征是否需要缩放；
2. `max_iter` 是否太小；
3. 正则是否太弱；
4. 数据是否线性可分；
5. 求解器与惩罚是否匹配；
6. 稀疏高维特征是否适合当前算法。

## 6. Ch21：假新闻案例中的完整分类生命周期

### 6.1 先把问题缩小到数据真正支持的范围

原始问题“能否自动检测假新闻”过于宽泛。课程数据来自 FakeNewsNet 中被 Politifact 核查的政治文章，大多发布于 2007-2020 年。

更准确的问题是：

> 能否根据文章内容，预测 Politifact 选中核查的政治文章被标记为 fake 还是 real？

主要限制：

- **覆盖偏差**：只包含 Politifact 监测到的来源；
- **选择偏差**：被挑去核查的通常更受关注或更具争议；
- **测量偏差**：标签依赖一个组织的核查规则；
- **时间漂移**：主题、人物、写作方式和媒体来源都会变化；
- **网页缺失**：已经下线的文章更难被成功抓取。

测试准确率高不等于模型能判断任何网页的真伪。

### 6.2 数据粒度、清洗与可复现性

案例中一行代表一篇文章，保留：

- URL 与发布站点；
- 发布时间；
- 标题和正文；
- fake/real 标签。

关键清洗包括：

```python
def combine_content(df):
    return df.assign(
        content=df["title"] + " " + df["text"]
    )

def drop_missing_content(df):
    valid = (
        df["url"].notna()
        & df["title"].str.strip().ne("")
        & df["text"].str.strip().ne("")
    )
    return df.loc[valid].copy()
```

网络数据会变化，所以应记录：

- 抓取日期；
- 原始 URL；
- 失败和缺失记录数量；
- 清洗代码版本；
- 标签来源和时间范围。

“在线仓库里有抓取脚本”不等于任何时候都能还原同一数据集。

### 6.3 在 EDA 前隔离测试集

```python
from sklearn.model_selection import train_test_split

df["label"] = (df["label"] == "fake").astype(int)

train_df, test_df = train_test_split(
    df,
    test_size=0.25,
    stratify=df["label"],
    random_state=42,
)
```

`stratify` 让训练和测试的类别比例更接近。之后只在训练集上：

- 查看高频词；
- 选择候选词；
- 决定停用词和 n-gram；
- 调整正则强度；
- 选择阈值。

如果部署目标是预测未来文章，随机拆分仍可能过于乐观。更贴近部署的方案是按时间切分，用较早文章训练、较晚文章测试。

### 6.4 手工单词特征帮助建立直觉

最简单的文本特征是“某词是否出现”：

$$
x_{ij}=I(\text{文档 }i\text{ 包含词 }j)
$$

```python
def word_presence(texts, words):
    text = texts.fillna("").str.lower()
    columns = {
        word: text.str.contains(
            word,
            regex=False,
        ).astype(int)
        for word in words
    }
    return pd.DataFrame(columns, index=texts.index)
```

这些特征容易解释，但要注意：

- 子串匹配会把 `vote` 匹配进其他长词，严格词边界需 tokenizer 或正则；
- 大小写和词形变化会造成漏匹配；
- EDA 中手工挑词也属于模型选择；
- “某词和标签相关”可能只是时间、来源或主题代理。

一个词的正系数表示它出现时 fake 的 odds 更高，不表示这个词造成文章虚假。

### 6.5 TF-IDF 把整篇文章变成稀疏向量

词袋模型为每个 token 建一列。TF-IDF 综合：

- TF：词在当前文档中出现多少；
- IDF：词在全部训练文档中有多稀有。

常见词权重被压低，较有区分度的词得到更高权重。结果通常是“文档数 $\times$ 词表大小”的高维稀疏矩阵。

```python
from sklearn.feature_extraction.text import TfidfVectorizer

tfidf = TfidfVectorizer(
    lowercase=True,
    ngram_range=(1, 2),
    min_df=3,
    max_df=0.95,
    sublinear_tf=True,
)
```

参数含义：

- `ngram_range=(1, 2)`：同时使用单词和相邻双词；
- `min_df=3`：忽略只在极少文档出现的 token；
- `max_df=0.95`：忽略几乎每篇都有的 token；
- `sublinear_tf=True`：用对数压缩文档内的高词频。

TF-IDF 必须只在训练折拟合词表和 IDF。先在完整数据上 `fit_transform` 再划分，会泄漏测试文档的词汇分布。

### 6.6 文本 Pipeline 与交叉验证

```python
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
from sklearn.pipeline import Pipeline

text_model = Pipeline([
    ("tfidf", TfidfVectorizer(
        lowercase=True,
        min_df=3,
        sublinear_tf=True,
    )),
    ("logistic", LogisticRegression(
        max_iter=10_000,
        solver="liblinear",
    )),
])

search = GridSearchCV(
    text_model,
    param_grid={
        "tfidf__ngram_range": [(1, 1), (1, 2)],
        "tfidf__max_df": [0.9, 1.0],
        "logistic__C": [0.1, 1.0, 10.0],
    },
    scoring="f1",
    cv=5,
    n_jobs=-1,
)

search.fit(train_df["content"], train_df["label"])
best_text_model = search.best_estimator_
```

选择 `scoring="f1"` 只是示例。若误判真实新闻为假更严重，可能优先 precision；若漏掉假新闻更严重，可能优先 recall；若需要可靠概率，则还要看 log loss 和校准。

整个 Pipeline 放进 `GridSearchCV` 后，每一折都只根据该折训练文本学习词表、IDF 和分类系数。

### 6.7 训练 100% 准确率不是成功证据

课程中的 TF-IDF 模型有两万多个特征，而训练文章只有数百篇。高维模型很容易把训练文本分开，因此训练 accuracy 达到 100% 并不意外。

需要比较：

```text
常数基准
  -> 单词模型
  -> 少量手工词模型
  -> 正则化 TF-IDF 模型
```

并同时查看：

- 交叉验证均值和波动；
- 最终测试指标；
- 训练与验证差距；
- 推理时间和模型大小；
- 错误样本和子群；
- 时间外数据的性能。

复杂模型提高预测能力，也会降低解释性并增加漂移风险。

### 6.8 怎样查看文本模型学到了什么

```python
tfidf_step = best_text_model.named_steps["tfidf"]
logistic_step = best_text_model.named_steps["logistic"]

terms = tfidf_step.get_feature_names_out()
coef = logistic_step.coef_[0]

top_fake = terms[np.argsort(coef)[-15:][::-1]]
top_real = terms[np.argsort(coef)[:15]]
```

正系数 token 把模型推向 fake，负系数 token 把模型推向 real。但解释时必须记住：

- 系数受正则化和共现词影响；
- 同义词和相关词会分摊权重；
- 人名可能只代理某个选举周期；
- 标点、网站模板和抓取痕迹可能成为捷径；
- 预测关联不是判断真伪的语言规则。

### 6.9 错误分析比只看总分更有用

```python
test_prob = best_text_model.predict_proba(
    test_df["content"]
)[:, 1]
test_pred = (test_prob >= 0.5).astype(int)

error_mask = (
    test_pred != test_df["label"].to_numpy()
)
errors = test_df.loc[error_mask].assign(
    predicted=test_pred[error_mask],
    fake_probability=test_prob[error_mask],
)
```

逐类检查：

- 高置信度假阳性；
- 高置信度假阴性；
- 极短文本；
- 特定站点；
- 不同年份；
- 含大量引用或讽刺的文章。

错误分析的目的不是看完测试错误继续调模型。正式测试集只用于最终审计；开发阶段的错误分析应基于训练集 OOF 预测或单独验证集。

### 6.10 漂移和捷径决定真实寿命

文本分类尤其容易受到：

- **词汇漂移**：新人物、新事件和新表达；
- **标签漂移**：正类比例变化；
- **来源漂移**：媒体站点增加、消失或改版；
- **概念漂移**：同一词与标签的关系改变。

若训练数据集中在 2016-2018 年，随机测试集也大多来自同一时期。它能估计同分布泛化，却不能证明 2026 年仍有效。

实际部署应：

- 使用时间外验证；
- 监控词表外 token、概率分布和错误率；
- 定期重新标注与训练；
- 保留人工复核；
- 避免把模型输出当作事实裁决。

## 7. 垃圾邮件项目：把分类知识变成完整模型

### 7.1 任务、正类和错误代价

`projB1` 与 `projB2` 的目标是：

$$
\text{邮件文本与主题}
\longrightarrow
P(\text{spam}=1)
$$

在这个任务中：

- TP：垃圾邮件被正确拦截；
- FP：正常邮件被误删或移入垃圾箱；
- FN：垃圾邮件进入收件箱；
- TN：正常邮件正常到达。

通常 FP 比 FN 更令人难以接受，因此只追求 accuracy 可能不够，应重点查看 spam precision，并根据产品容忍度选择阈值。

### 7.2 B1 的重点：亲手理解词特征

`words_in_texts(words, texts)` 要输出形状为 $(n,d)$ 的 0/1 数组：

```python
import re

def words_in_texts(words, texts):
    clean = texts.fillna("").str.lower()
    columns = []

    for word in words:
        pattern = rf"\b{re.escape(word.lower())}\b"
        present = clean.str.contains(
            pattern,
            regex=True,
        )
        columns.append(present.astype(int).to_numpy())

    return np.column_stack(columns)
```

关键细节：

- 返回二维数组，即使只有一个词；
- 行顺序必须和标签一致；
- `re.escape` 防止词中符号被当作正则；
- `\b` 是简单英文词边界，对中文或复杂 token 不够；
- 词表只能根据训练数据选择。

这个练习帮助理解设计矩阵，但真实项目通常优先使用 `CountVectorizer(binary=True)` 或 `TfidfVectorizer`。

### 7.3 不要只找“看起来像 spam 的词”

有用特征可以分为：

| 类型 | 例子 | 风险 |
| --- | --- | --- |
| 内容词 | free、bank、meeting | 随主题和时代漂移 |
| 格式 | 感叹号、全大写、HTML | 正常营销邮件也常出现 |
| 长度 | 字符数、词数 | 易受签名和引用影响 |
| 主题 | reply、forward、促销短语 | 可能代理邮件客户端 |
| 链接 | URL 数、域名 | 攻击者会主动规避 |

EDA 应比较特征在 spam/ham 中的**分布和覆盖率**。只在 3 封邮件出现且恰好全是 spam 的词，可能比一个在数百封邮件中有稳定差异的词更不可靠。

### 7.4 用 ColumnTransformer 合并文本与数值特征

```python
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import (
    FunctionTransformer,
    StandardScaler,
)

def numeric_email_features(frame):
    subject = frame["subject"].fillna("")
    email = frame["email"].fillna("")

    return np.column_stack([
        email.str.len(),
        email.str.count(r"!"),
        email.str.count(r"https?://"),
        subject.str.len(),
        subject.str.contains(
            r"(?i)\b(re|fwd):",
            regex=True,
        ).astype(int),
    ])

numeric_pipe = Pipeline([
    ("extract", FunctionTransformer(
        numeric_email_features,
        validate=False,
    )),
    ("scale", StandardScaler()),
])

email_preprocess = ColumnTransformer([
    ("body", TfidfVectorizer(
        min_df=3,
        ngram_range=(1, 2),
        sublinear_tf=True,
    ), "email"),
    ("subject", TfidfVectorizer(
        min_df=2,
        ngram_range=(1, 2),
    ), "subject"),
    ("numeric", numeric_pipe, ["subject", "email"]),
])

spam_model = Pipeline([
    ("features", email_preprocess),
    ("logistic", LogisticRegression(
        max_iter=10_000,
        solver="saga",
    )),
])
```

这样可保证：

- 正文和主题分别学习词表；
- 数值特征只用训练折计算缩放参数；
- 相同转换自动用于验证和测试；
- 新邮件不会因列顺序不同而出错。

### 7.5 交叉验证选择模型，不靠排行榜试探测试集

```python
spam_search = GridSearchCV(
    spam_model,
    param_grid={
        "features__body__min_df": [2, 5, 10],
        "features__body__ngram_range": [
            (1, 1),
            (1, 2),
        ],
        "logistic__C": [0.1, 1.0, 10.0],
    },
    scoring="precision",
    cv=5,
    n_jobs=-1,
)

spam_search.fit(
    train_df[["subject", "email"]],
    train_df["spam"],
)
```

若作业平台每天允许多次提交测试预测，也不能把每次返回的测试分数当成调参反馈。提交次数足够多时，模型会间接过拟合隐藏测试集。

正确流程：

```text
训练数据
  -> 再分训练/验证或做 CV
  -> 在内部做 EDA、调参和错误分析
  -> 方案冻结
  -> 最后生成隐藏测试预测
```

### 7.6 错误分析要回到原始邮件

训练集 OOF 预测后，分别检查：

- 高置信度 FP：为什么正常邮件看起来像 spam？
- 高置信度 FN：模型缺少了什么词、格式或链接特征？
- 低置信度样本：是否本身就模糊？
- 特定邮件来源或格式：是否形成系统性错误？

不要看到一个误判样本就加一个专门词特征。先判断该模式是否会重复出现，再用交叉验证确认。

### 7.7 图像分类项目是同一流程的另一种特征空间

`grad-proj` 使用颜色、边缘和纹理等图像特征预测灾害类型或损伤等级。虽然原始数据从文本换成图像，流程没有改变：

```text
原始图像
  -> 固定、可复现的特征提取
  -> 训练/验证隔离
  -> 分类器与阈值
  -> 分类别性能和混淆矩阵
```

若同一灾害事件包含许多相似照片，随机按图片拆分会泄漏事件信息。应考虑按事件、地点或来源分组划分。

## 8. 文件夹扩展一：PCA 与降维

> PCA 和聚类不属于 Ch19-Ch21 的分类主线，但它们出现在 `lec25-26`、PCA 笔记和 `lab11.ipynb` 中。二者是无监督学习：只研究 $X$，不使用目标标签 $y$。

### 8.1 为什么需要降维

一个 $n\times p$ 数据矩阵可以同时理解为：

- $n$ 个位于 $p$ 维空间中的观测；
- $p$ 个位于 $n$ 维空间中的特征向量。

列数多不等于真正信息维度高。例如公斤和磅是两列，却只包含一个方向的信息。

PCA 希望找到少数正交方向，使投影后的数据保留尽可能多的变异：

```text
高维 X
  -> 少数主成分方向
  -> 低维得分 Z
  -> 可视化、压缩或后续建模
```

![PCA 用新的正交坐标方向表示原始数据](./代码数据/lab11/images/PCA.png)

### 8.2 第一步永远是中心化，并判断是否标准化

中心化：

$$
X_c=X-\mathbf1\bar{\mathbf x}^{\top}
$$

使每列均值为 0。PCA 寻找的是围绕数据中心的变化方向。

若特征单位不同或量级差异不具备业务含义，还应标准化：

$$
X_s=\frac{X-\bar X}{SD(X)}
$$

判断规则：

- 身高用厘米、收入用元：通常标准化；
- 所有像素都在同一灰度尺度：通常只中心化；
- 同单位下方差大小本身有意义：不要机械标准化。

sklearn 的 `PCA` 会自动中心化，但不会自动标准化。

### 8.3 SVD 与 PCA 的关系

对中心化矩阵：

$$
X_c=USV^\top
$$

- $U$：观测方向；
- $S$：从大到小排列的奇异值；
- $V$：特征空间中的正交方向。

前 $k$ 个主成分方向是 $V$ 的前 $k$ 列。低维得分：

$$
Z_k=X_cV_k=U_kS_k
$$

其中：

- $V_k$ 形状为 $p\times k$；
- $Z_k$ 形状为 $n\times k$；
- $Z_k$ 的每一行是一个观测的新坐标。

手工实现：

```python
X_centered = X - X.mean(axis=0)

U, s, Vt = np.linalg.svd(
    X_centered,
    full_matrices=False,
)

k = 2
components = Vt[:k]          # (k, p)
scores = X_centered @ components.T
```

sklearn 中 `components_` 的每一行是一条主成分方向，这与数学中把方向写成 $V$ 的列只是存储约定不同。

### 8.4 最大方差与最小重构误差是同一目标

第一主成分选择单位向量 $v_1$，使投影方差最大：

$$
v_1
=\arg\max_{\|v\|=1}
\operatorname{Var}(X_cv)
$$

后续主成分在与前面方向正交的约束下，继续捕获剩余最大方差。

保留前 $k$ 个方向的重构：

$$
\hat X_c=Z_kV_k^\top
$$

在所有 rank-$k$ 线性近似中，截断 SVD 使平方重构误差最小。因此：

```text
最大化保留的投影方差
等价于
最小化丢弃后的平方重构误差
```

```python
X_reconstructed = (
    scores @ components
    + X.mean(axis=0)
)

reconstruction_mse = np.mean(
    (X - X_reconstructed) ** 2
)
```

### 8.5 奇异值与解释方差

若使用分母 $n$ 的方差约定，第 $j$ 个主成分捕获：

$$
\frac{s_j^2}{n}
$$

解释方差比例为：

$$
\operatorname{EVR}_j
=\frac{s_j^2}{\sum_r s_r^2}
$$

累计解释方差：

$$
\sum_{j=1}^{k}\operatorname{EVR}_j
$$

```python
variance_ratio = s**2 / np.sum(s**2)
cumulative_ratio = np.cumsum(variance_ratio)
```

sklearn 使用样本方差约定计算 `explained_variance_`，但分母在比例中抵消，`explained_variance_ratio_` 的解释不变。

### 8.6 sklearn 实现与数据泄漏

```python
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

pca = Pipeline([
    ("scale", StandardScaler()),
    ("pca", PCA(n_components=2)),
])

Z_train = pca.fit_transform(X_train)
Z_test = pca.transform(X_test)
```

测试集不能参与均值、标准差或主成分方向的拟合。

若 PCA 用于监督分类：

```python
pca_classifier = Pipeline([
    ("scale", StandardScaler()),
    ("pca", PCA()),
    ("logistic", LogisticRegression(
        max_iter=10_000
    )),
])

pca_search = GridSearchCV(
    pca_classifier,
    param_grid={
        "pca__n_components": [5, 10, 20, 50],
        "logistic__C": [0.1, 1.0, 10.0],
    },
    scoring="f1",
    cv=5,
)
```

整个 Pipeline 必须放进 CV，确保每折只用自己的训练部分学习 PCA 方向。

### 8.7 怎样读 PCA 图、scree plot 和 biplot

PCA 散点图：

- 点接近：在前两个主成分表示下较相似；
- 点分组：数据可能存在潜在结构；
- 但前两维若只解释很少方差，二维图会遗漏大量信息。

scree plot：

- 横轴为主成分序号；
- 纵轴为单个或累计解释方差；
- 肘部可给出候选 $k$，不是自动真理。

biplot 同时画观测得分与原特征方向。方向接近的箭头表示这些特征在所展示主成分上变化相似；反向表示相反；箭头很短表示前两维未很好表达该特征。

### 8.8 PCA 最容易误解的地方

1. **主成分不是原始变量**：它是多个原特征的线性组合。
2. **符号不唯一**：某个主成分和它乘以 -1 完全等价。
3. **高方差不等于高预测价值**：低方差方向也可能与标签高度相关。
4. **PCA 对尺度敏感**：未标准化时大单位特征可能支配结果。
5. **PCA 对异常值敏感**：平方距离会放大极端观测。
6. **PCA 只能捕获线性低维结构**：弯曲流形未必能被少数线性方向表示。
7. **二维可视化不是完整数据**：必须同时报告前两维解释方差。

PCA 的价值在于压缩、可视化和去除线性冗余，不是自动提高任何模型的测试性能。

## 9. 文件夹扩展二：聚类

### 9.1 聚类与分类不是一回事

分类使用已知标签学习：

$$
X\longrightarrow Y
$$

聚类没有目标标签，只根据 $X$ 把相似观测分组：

$$
X\longrightarrow \text{cluster assignments}
$$

聚类编号 0、1、2 没有天然语义，也不是被发现的“真实类别”。数据科学家必须结合原始变量和领域背景解释每个群组。

K-Means 也不是 K-Nearest Neighbors：

| 方法 | 是否监督 | $K$ 表示什么 |
| --- | --- | --- |
| K-Means | 否 | 聚类数量 |
| KNN | 是 | 预测时参考的近邻数量 |

### 9.2 距离定义决定“相似”

K-Means 和许多层次聚类默认使用欧氏距离：

$$
d(\mathbf x_i,\mathbf x_j)
=\sqrt{\sum_r(x_{ir}-x_{jr})^2}
$$

如果收入范围是几十万、年龄范围是几十，未缩放时收入会支配距离。通常先标准化：

```python
from sklearn.preprocessing import StandardScaler

X_scaled = StandardScaler().fit_transform(X)
```

但缩放并非无脑操作。它相当于宣布“每个特征一个标准差的变化同等重要”。变量选择、变换、类别编码和距离度量都在定义聚类问题。

### 9.3 K-Means 算法

给定聚类数 $K$：

1. 初始化 $K$ 个中心 $\mu_1,\ldots,\mu_K$；
2. 把每个点分给最近中心；
3. 把每个中心移动到所属点的均值；
4. 重复 2-3，直到分配或中心几乎不再变化。

![K-Means 交替更新点的分组与每组中心](./笔记/clustering/images/cluster_iter5.png)

它最小化 inertia：

$$
\operatorname{Inertia}
=\sum_{k=1}^{K}
\sum_{i:c_i=k}
\|\mathbf x_i-\mu_k\|_2^2
$$

为什么中心更新为均值？固定某组成员后，使组内平方距离和最小的常数向量就是该组各维均值。

为什么分配给最近中心？固定中心后，每个点选择最近中心能最小化它自己的平方距离。

所以 K-Means 是交替优化：

```text
固定中心，优化分组
  -> 固定分组，优化中心
  -> 反复直到局部稳定
```

每一步都不会增加 inertia，但不保证找到全局最优。

### 9.4 初始化与局部最优

不同初始中心可能产生不同结果。可靠实现会运行多次初始化，保留 inertia 最低的一次：

```python
from sklearn.cluster import KMeans
from sklearn.pipeline import Pipeline

kmeans_model = Pipeline([
    ("scale", StandardScaler()),
    ("cluster", KMeans(
        n_clusters=3,
        init="k-means++",
        n_init=20,
        random_state=42,
    )),
])

labels = kmeans_model.fit_predict(X)
```

- `k-means++` 尽量让初始中心分散；
- `n_init=20` 独立尝试多次；
- `random_state` 让结果可复现。

即使固定随机种子，也应检查结果对种子和样本扰动是否稳定。

### 9.5 K-Means 偏好什么形状

K-Means 隐含偏好：

- 近似球形或凸形群组；
- 各组尺度相近；
- 欧氏距离有意义；
- 均值能代表中心；
- 极端值不太多。

它可能在以下情况失败：

- 月牙、环形等非凸结构；
- 不同密度或大小差异很大的群组；
- 大量离群点；
- 高维距离集中；
- 类别变量被不恰当地编码成数字。

inertia 低只表示组内平方距离小，不表示聚类符合人的“团块”直觉。

### 9.6 为什么不能按 inertia 最小选择 K

随着 $K$ 增加，inertia 必然不增：

- $K=1$：所有点共用一个中心；
- $K=n$：每点一个中心，inertia 为 0。

所以不能直接选择 inertia 最小的 $K$。常见方法：

1. **Elbow**：找下降开始明显变缓的位置；
2. **Silhouette**：同时考虑组内紧密与组间分离；
3. **稳定性**：重采样后聚类是否相似；
4. **领域代价**：例如产品真正能支持几种客户方案。

肘部经常不明显，最终 $K$ 可能本来就没有唯一正确答案。

### 9.7 Silhouette score

对样本 $i$：

- $a(i)$：到同组其他点的平均距离；
- $b(i)$：到最近其他组所有点的平均距离。

$$
s(i)=\frac{b(i)-a(i)}
{\max\{a(i),b(i)\}}
$$

范围约为 $[-1,1]$：

- 接近 1：组内近、邻组远；
- 接近 0：位于边界；
- 小于 0：可能更接近另一组。

```python
from sklearn.metrics import silhouette_score

results = []

for k in range(2, 9):
    km = KMeans(
        n_clusters=k,
        n_init=20,
        random_state=42,
    )
    labels = km.fit_predict(X_scaled)
    results.append({
        "k": k,
        "inertia": km.inertia_,
        "silhouette": silhouette_score(
            X_scaled, labels
        ),
    })

cluster_scores = pd.DataFrame(results)
```

silhouette 仍依赖选定距离，也偏好凸且分离的群组。它是证据之一，不是客观发现真实 $K$ 的机器。

### 9.8 Hierarchical Agglomerative Clustering

凝聚式层次聚类从“每个点单独一组”开始，不断合并最接近的两个群组，直到达到所需组数或合并为一组。

群组间距离由 linkage 定义：

| Linkage | 两组距离 | 典型行为 |
| --- | --- | --- |
| single | 最近点距离 | 能发现链状结构，也易 chaining |
| complete | 最远点距离 | 倾向紧凑群组 |
| average | 所有跨组点对平均距离 | 两者折中 |
| Ward | 合并后组内平方误差增量 | 类似 K-Means 的紧凑群组 |

![不同 linkage 用不同方式定义两个群组之间的距离](./笔记/clustering/images/linkage.png)

```python
from sklearn.cluster import AgglomerativeClustering

agg = AgglomerativeClustering(
    n_clusters=3,
    linkage="complete",
)
labels = agg.fit_predict(X_scaled)
```

层次聚类的合并过程可用 dendrogram 展示。不同高度切割树会得到不同 $K$，适合探索嵌套结构；但大数据上通常比 K-Means 更昂贵。

### 9.9 怎样解释与验证聚类

聚类完成后，不要只画彩色散点图。至少检查：

- 各组样本数是否极端不平衡；
- 各原始特征在组间怎样不同；
- 聚类是否主要由一个大尺度变量驱动；
- 改变随机种子、抽样或少量参数后是否稳定；
- 是否存在异常点单独形成小组；
- 分组是否对应实际可行动差异。

```python
clustered = original_df.assign(cluster=labels)
profile = clustered.groupby("cluster").agg({
    "feature_a": ["mean", "median"],
    "feature_b": ["mean", "median"],
})
```

如果事后拿已有标签评价聚类，应明确这些标签没有参与拟合。高一致性说明聚类与标签结构相近，不说明算法“重新发现了自然真理”。

## 10. 把本部分统一成“表示、目标、优化、评价”

看似不同的方法，其实都可以放进同一张表：

| 方法 | 输入表示 | 优化目标 | 输出 | 主要评价 |
| --- | --- | --- | --- | --- |
| 逻辑回归 | 设计矩阵/TF-IDF | 交叉熵 + 正则 | 概率、类别 | log loss、PR、ROC、成本 |
| PCA | 中心化/标准化矩阵 | 最大方差或最小重构误差 | 低维得分 | 解释方差、重构与用途 |
| K-Means | 距离空间中的点 | inertia | 聚类编号、中心 | silhouette、稳定性、业务意义 |
| 层次聚类 | 距离矩阵 | 按 linkage 逐步合并 | 聚类树 | dendrogram、稳定性、解释 |

共同逻辑：

```text
数据怎样表示
  -> 什么结果算好
  -> 用什么算法寻找
  -> 用什么证据验证
```

不能混淆的地方：

- 梯度下降是优化算法，不是分类模型；
- 交叉熵是拟合概率的损失，不等于最终业务成本；
- 阈值选择是决策问题，不等于重新训练概率模型；
- PCA 保留 $X$ 的方差，不保证保留与 $y$ 相关的信号；
- K-Means 的低 inertia 不等于真实世界分类正确。

## 12. 最容易犯的错误

1. **不先定义正类**：precision、recall 和 FP/FN 会失去语义。
2. **只看 accuracy**：极端不平衡时多数类模型也能很高。
3. **把概率和类别混为一谈**：0.51 与 0.99 可能得到同一类别，却不是同样预测。
4. **默认 0.5 阈值永远正确**：阈值应服从错误代价。
5. **用测试集选择阈值**：测试集就参与了模型开发。
6. **把 precision 的分母写成真实正类**：那是 recall 的分母。
7. **把 specificity 分母写成预测负类**：正确分母是全部真实负类 $TN+FP$。
8. **把 ROC-AUC 当成部署性能**：它不指定阈值和成本。
9. **类别不平衡时只看 ROC**：PR 往往更直接反映正类质量。
10. **把 F1 当万能指标**：它忽略 TN 和真实代价。
11. **用 `predict()` 后再调概率阈值**：类别输出已丢失概率信息。
12. **假设 `predict_proba[:,1]` 永远是业务正类**：先看 `classes_`。
13. **直接计算 `log(sigmoid(z))`**：极端分数可能产生 `log(0)`。
14. **忽略 ConvergenceWarning**：可能是尺度、可分、正则或求解器问题。
15. **忘记 sklearn 逻辑回归默认正则化**：它不等于教科书中的裸 MLE。
16. **把 `C` 理解为正则强度**：`C` 越小才是正则越强。
17. **在线性可分数据上追求无限大系数**：未正则化最优解可能不有限。
18. **在完整数据上拟合 TF-IDF**：词表和 IDF 泄漏测试信息。
19. **用测试文章做词语 EDA**：人工观察同样会泄漏。
20. **把高权重 token 解释成真假原因**：它只是条件关联和数据代理。
21. **随机拆分未来预测任务**：同一时期词汇让结果过于乐观。
22. **梯度下降只看参数变化**：极小学习率会制造假收敛。
23. **手工求 Hessian 逆**：应使用线性求解器或成熟优化库。
24. **PCA 前不考虑尺度**：大单位特征可能支配主成分。
25. **把前两主成分图当完整数据**：先看解释方差比例。
26. **用 PCA 自动选择预测特征**：高方差不等于对 $y$ 有用。
27. **把聚类编号当有序标签**：编号可以任意置换。
28. **用最小 inertia 选择 $K$**：$K=n$ 时必然为 0。
29. **只运行一次 K-Means**：不同初始化可能落到不同局部解。
30. **聚类前不定义相似性**：缩放和距离实际上决定了结果。

## 13. 两套端到端工作模板

### 13.1 分类模型：超参数与阈值分层选择

下面的模板使用嵌套交叉验证生成训练集 OOF 概率：

```python
from sklearn.metrics import (
    classification_report,
    confusion_matrix,
    log_loss,
)
from sklearn.model_selection import (
    GridSearchCV,
    StratifiedKFold,
    cross_val_predict,
    train_test_split,
)

# 1. 隔离最终测试集
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.2,
    stratify=y,
    random_state=42,
)

# 2. pipeline 包含全部数据驱动转换
pipeline = Pipeline([
    ("preprocess", preprocess),
    ("logistic", LogisticRegression(
        max_iter=10_000
    )),
])

# 3. 内层 CV 选择模型超参数
search = GridSearchCV(
    pipeline,
    param_grid={
        "logistic__C": [0.01, 0.1, 1, 10],
    },
    scoring="neg_log_loss",
    cv=4,
)

# 4. 外层 CV 产生未见过该样本的概率
outer_cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42,
)
oof_prob = cross_val_predict(
    search,
    X_train,
    y_train,
    cv=outer_cv,
    method="predict_proba",
)[:, 1]

# 5. 只根据 OOF 概率和真实成本选择阈值
thresholds = np.linspace(0.05, 0.95, 181)
oof_costs = [
    classification_cost(
        y_train,
        oof_prob,
        threshold=t,
        fp_cost=1,
        fn_cost=5,
    )
    for t in thresholds
]
threshold = thresholds[np.argmin(oof_costs)]

# 6. 在全部训练集重新调参和拟合
search.fit(X_train, y_train)
final_model = search.best_estimator_

# 7. 最后一次测试
test_prob = final_model.predict_proba(X_test)[:, 1]
test_pred = classify(test_prob, threshold)

print("threshold:", threshold)
print("log loss:", log_loss(y_test, test_prob))
print(confusion_matrix(y_test, test_pred))
print(classification_report(
    y_test,
    test_pred,
    zero_division=0,
))
```

逻辑顺序是：

```text
内层 CV 选择概率模型
  -> 外层 OOF 概率选择决策阈值
  -> 全训练集拟合最终模型
  -> 测试集只做一次最终审计
```

数据量不大时，嵌套 CV 计算较慢，但它把模型选择与阈值选择的反馈边界讲得最清楚。

最终报告至少包含：

- 正类含义和类别比例；
- 数据划分方式；
- 概率指标，如 log loss；
- 指定阈值及选择依据；
- 混淆矩阵；
- precision、recall、specificity；
- PR/ROC 或与业务相关曲线；
- 子群、时间和来源上的误差；
- 适用范围与漂移监控。

### 13.2 PCA 与聚类探索

```python
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.metrics import silhouette_score
from sklearn.preprocessing import StandardScaler

# 1. 明确用于定义相似性的特征
features = [...]
X = data[features]

# 2. 缩放
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

# 3. PCA 只用于表示和观察
pca = PCA(n_components=2)
Z = pca.fit_transform(X_scaled)
print(pca.explained_variance_ratio_)

# 4. 在原标准化空间比较候选 K
scores = []
for k in range(2, 9):
    km = KMeans(
        n_clusters=k,
        n_init=20,
        random_state=42,
    )
    labels = km.fit_predict(X_scaled)
    scores.append(
        silhouette_score(X_scaled, labels)
    )

best_k = range(2, 9)[int(np.argmax(scores))]

# 5. 拟合候选聚类并回到原始特征解释
kmeans = KMeans(
    n_clusters=best_k,
    n_init=20,
    random_state=42,
)
labels = kmeans.fit_predict(X_scaled)

profile = data.assign(cluster=labels).groupby(
    "cluster"
)[features].mean()
```

这里在原标准化空间计算 silhouette，而不是只在二维 PCA 图上聚类。二维图主要用于可视化；除非前两维已保留绝大部分信息，否则直接在图上聚类会丢失结构。

还要重复不同种子、重采样或特征组合，检查聚类是否稳定，并让领域指标参与最终 $K$ 的选择。

### 14.2 参考答案

1. 先输出 $P(Y=1\mid X)$，再由阈值得到类别。
2. 直线可超出 $[0,1]$，也不能自然表达概率两端饱和。
3. 其他特征不变时，$x_j$ 增加 1，正类 odds 乘以 $e^{\theta_j}$。
4. 概率变化为 $\theta_jp(1-p)$，取决于当前概率位置。
5. 对真实类分配接近 0 的概率时，损失趋于无穷。
6. 训练集正类比例 $\bar y$。
7. Bernoulli 对数似然取负并平均，正好得到交叉熵。
8. 每个样本的概率误差由各特征加权汇总，形成参数方向的偏导。
9. 放大分离方向可让训练交叉熵不断接近 0，而无需停在有限系数。
10. 正则化变强，系数通常更小。
11. precision 分母是全部预测正类 $TP+FP$；recall 分母是全部真实正类 $TP+FN$。
12. $\operatorname{FPR}=1-\operatorname{Specificity}$。
13. 预测正类增多，recall 通常提高，FP 也常增加。
14. 阈值会根据测试标签改变决策，测试误差因此偏乐观。
15. 稀有正类和正类质量常看 PR；整体排序与 TPR/FPR 权衡常看 ROC。
16. 它不指定阈值、概率校准、实际成本或子群公平性。
17. 可能越过最低点、振荡或发散。
18. 可微提供梯度；凸性避免更差的局部最低点。
19. 每步分别使用全部数据、一个样本和一小批样本。
20. Hessian 所描述的二阶曲率。
21. Politifact 选中、特定时期政治文章的 fake/real 标签。
22. 词表和 IDF 必须只从每个训练折学习，否则发生泄漏。
23. 主成分应描述围绕数据中心的变化，而不是均值位置。
24. 方向是特征空间中的 $V_k$；得分是观测投影 $Z=X_cV_k$。
25. $s_j^2/\sum_rs_r^2$。
26. PCA 保留 $X$ 的高方差方向，不使用标签 $y$。
27. 固定中心分配最近组；固定分组把中心更新为均值。
28. inertia 随 $K$ 增加必然下降，$K=n$ 时为 0。
29. $a(i)$ 是同组平均距离，$b(i)$ 是最近其他组平均距离。
30. 编号可任意置换，且聚类只反映所选特征和距离下的结构。

### 14.3 最终掌握标准

你应能够：

- 明确定义标签、正类、数据粒度和错误代价；
- 从线性分数推导 sigmoid、logit 和决策边界；
- 正确解释逻辑回归 odds ratio；
- 推导并稳定实现交叉熵与梯度；
- 使用 `scipy.optimize.minimize` 和 sklearn 拟合逻辑回归；
- 解释线性可分、正则化、`C` 和收敛警告；
- 从混淆矩阵计算主要分类指标；
- 根据实际代价在训练数据内部选择阈值；
- 区分 PR、ROC、AUC、F1、log loss 和校准；
- 理解 batch GD、SGD、mini-batch 与 Newton 法；
- 使用 TF-IDF Pipeline 完成文本分类；
- 识别文本泄漏、时间漂移和模型捷径；
- 用 SVD 理解 PCA、解释方差和重构；
- 正确运行和解释 K-Means、silhouette 与层次聚类；
- 把所有方法放回数据生命周期，而不是只报告一个分数。

第六部分可以浓缩成一句话：

> 分类模型先学习分数和概率，真实决策再用阈值与代价把概率变成行动；优化算法负责寻找参数，验证设计负责判断这些参数能否推广。
